# textshader

Анимированный текст без модов: плагин красит текст особым цветом, а core-шейдер ресурспака (через Nexo) рисует по
этому цвету эффект - тряску, волну, радугу, огонь, глитч, печатную машинку и еще 49 штук. Работает везде, где текст
рисуется в интерфейсе игрока: чат, таб, заголовки, табло, боссбар, названия и описания предметов, меню. В мире
(text_display, ники над головой) шейдер не анимирует, а заменяет код на обычный читаемый цвет.

Автор: tearsmilk. Сервер: Leaf 1.21.11 (Paper API), Java 21, Nexo 1.30-dev. PlaceholderAPI - не обязателен.

Перенос системы textfx из magicruruka: протокол цвета и номера эффектов 0-45 совместимы с исходными шейдерами,
код переписан. Бюсты, аватары и социальные функции не перенесены.

## Протокол цвета

- Текст: `R = 214`, `G = эффект * 4 | биты 2-3 номера буквы`, `B = биты 4-5 номера << 6 | цвет * 4 | биты 0-1 номера`.
- Тень (ваниль: цвет * 0.25): `R = 53`, `G = эффект`, `B = цвет` - шейдер узнает и тень.
- Номер буквы (0-63) нужен эффектам с индексом: `type` (печатная машинка), `bounce`, `scramble`. Плагин нумерует
  буквы сам (`FxText`), после 63 номер не растет, `\n` начинает счет заново.
- Цвета палитры (16): white, red, orange, yellow, lime, green, aqua, cyan, blue, purple, magenta, pink, gold, gray,
  black, brown. У эффектов со своими цветами (радуга, флаги, золото, новые matrix/frost/...) цвет кроме white
  перекрашивает узор по яркости.
- Номера эффектов не менять: они хранятся у игроков и в чужих конфигах. Новые - только в конец (до 63).
- Номера 52-55 зарезервированы и никогда не используются: `G` 208-223 при `R = 214` - это светло-серые цвета
  (`#D6D6D6`, `#D6D0D0` ...), а их тени (`#353535` и рядом) совпали бы с тенью эффекта. Такие цвета шейдер не трогает.
- Какие обычные цвета все же перехватываются: `R = 214` и `G` 0-207 или 224-239 (то есть `#D600xx`-`#D6CFxx`,
  `#D6E0xx`-`#D6EFxx`), и тени цветов с `R` 212-215 и `G` 0-207/224-239. `#D6B4xx`-`#D6B7xx` (typecursor) текст
  прячет совсем - это было и в исходнике. Не используйте такие цвета в других плагинах для обычного текста.

## Эффекты

0-45 из исходника: shake, wave, jump, flip, skew, pulse, rainbow, gradient, shimmer, chroma, metal, fire, fade, blink,
glow, outline, thin, pride, lesbian, mlm, bi, trans, pan, ace, aro, enby, rainbowwave, neon, glitch, ice, holo, type,
heart, gold, galaxy, quake, swing, echo, jeb, toxic, vampire, ghost, lava, hue, wavyoutline, typecursor (служебный,
скрыт).

Новые (46-51 и 56-59, 52-55 пропущены):

Превью всех эффектов - `preview/` (`fx_<ключ>.gif`, `strip_<ключ>.png` - 6 кадров, `sheet.png` - все эффекты,
`sheet_new.png` - только новые, `world_plain.png` - текст в мире, `title_<ключ>.gif` и `sheet_title.png` - эффекты
в заголовке, масштаб 4x).

## Команды (`/textshader`, алиас `/ts`)

| команда | права | что делает |
|---------|-------|------------|
| `/ts` или `/ts menu [страница]` | use | меню-превью всех эффектов (см. ниже) |
| `/ts set <эффект> [цвет]`, `/ts set off` | use + effect | эффект текста своих сообщений в чате |
| `/ts nick <эффект> [цвет]`, `/ts nick off` | use + effect | эффект ника (имя в чате, таб, плейсхолдеры) |
| `/ts off [chat\|nick]` | use | выключить (без аргумента - оба; `msg` = `chat`) |
| `/ts preview <эффект> [текст]` | use | примеры в чат: белым и тремя цветами + тег для копирования |
| `/ts list` | use | все эффекты (нажать - превью) и цвета |
| `/ts code <эффект> [цвет]` | use | код цвета: `#D6....`, для MiniMessage и legacy |
| `/ts give-name <эффект> [цвет] [текст]` | admin | переименовать предмет в руке (без текста - текущее имя) |
| `/ts title <игрок\|*> <эффект[:цвет]> <текст> [\| подзаголовок]` | admin | заголовок с эффектом |
| `/ts broadcast <эффект[:цвет]> <текст>` | admin | сообщение всем (внутри можно теги) |
| `/ts player <игрок> <chat\|nick> <эффект\|off> [цвет]` | admin | выставить игроку |
| `/ts reload` | admin | перечитать config.yml |

Эффект можно писать как `wave red` или `wave:red`.

Права: `textshader.use` (по умолчанию всем), `textshader.admin` (оп), `textshader.effect.<ключ>` - каждый эффект,
`textshader.effect.*` - все. По умолчанию все эффекты доступны всем (`effects-default: true`), при `false` - только
опам, остальным выдавать через LuckPerms.

В чате игрок может писать теги: `<wave>текст</wave>`, `<wave:red>текст`, `<fx:rainbow>`, `<textshader:fire:gold>`,
`</>` закрывает последний. Неизвестные теги остаются текстом. Тег с недоступным эффектом убирается, текст внутри
идет с выбранным эффектом игрока. Плагин обходит дерево компонентов сообщения и меняет только текст: ховеры,
клики, [item], упоминания и цвета от других чат-плагинов сохраняются (свой эффект игрока не перекрашивает
уже окрашенные куски, явный тег - перекрашивает). Номера букв у type/bounce/scramble идут одним счетом через все
сообщение.

Выбор игрока хранится в PDC игрока (`textshader:chat`, `textshader:nick`, строка `эффект:цвет`), переживает
рестарт и не требует файлов.

## Меню `/ts`

Сундук на 6 рядов, 36 эффектов на страницу (сейчас 55 эффектов, 2 страницы, typecursor не показывается).

- Название каждого предмета - сам эффект (живое превью), в описании два превью: `Ник: <ник с эффектом>` и
  `Сообщение: <menu-sample с эффектом>`, каждое своим цветом (цвет ника и цвет сообщений хранятся отдельно).
- ЛКМ - эффект на ник: имя в чате и в табе меняется сразу и сохраняется.
- ПКМ - эффект на текст своих сообщений в чате.
- Shift+ЛКМ / Shift+ПКМ - палитра из 16 цветов для этого эффекта на ник / на сообщения.
- Выбранные эффекты светятся и подписаны "Сейчас на нике" / "Сейчас на сообщениях".
- Верхний ряд: ник (текущий, нажать - цвет), цвет ника, снять с ника, справка, снять с сообщений, цвет сообщений,
  сообщения (текущие). Нижний ряд: страницы и "Закрыть".
- Недоступные по правам эффекты - серое стекло, "Нет доступа".
- Любые клики и перетаскивания в меню отменяются, цифры, Q, двойной клик и т.п. игнорируются; смена страницы и
  палитры открывает меню заново на следующем тике; на каждое действие - звук.

Ник в чате: при `chat.nick: true` плагин на приоритете HIGHEST оборачивает renderer чата и красит имя
(`sourceDisplayName`) эффектом ника; уже окрашенные части имени (префиксы, цветные ники других плагинов) не трогаются.
Без чат-плагинов это работает с ванильным форматом `<ник> сообщение`. Совместимость: если чат-плагин ставит свой
renderer позже нас (тоже HIGHEST/MONITOR) или собирает формат без `sourceDisplayName`, ник в чате останется
обычным - тогда в его формате использовать `%textshader_nick%`. Пока у игрока есть эффект ника, сообщение уходит
с типом чата RAW (имя внутри текста) - так Paper делает при любом своем renderer.

## Для других плагинов

- MiniMessage: резолвер `TextShaderApi.tags()` дает теги `<fx:wave>`, `<fx:wave:red>`, `<textshader:type:aqua>`
  (у type/bounce/scramble буквы нумеруются сами, через вложенные теги тоже).
- Готовый текст: `TextShaderApi.render("Текст", "wave", "red")` - Component, `legacy(...)` - строка `&#D6....`,
  `miniMessage(...)` - строка с `<#D6....>`, `code("wave", "red")` - число RGB, `nick(player)`.
- Плагины без зависимости могут просто ставить цвет `#D60404` (это wave + red), коды - `/ts code`.
- PlaceholderAPI (если стоит): `%textshader_nick%` (ник с эффектом, legacy `&#`), `%textshader_nick_mm%`
  (MiniMessage), `%textshader_nick_color%`, `%textshader_nick_effect%`, `%textshader_chat_effect%`,
  `%textshader_chat_color%`, `%textshader_fx_<эффект>[_<цвет>]%` (ник с указанным эффектом), `%textshader_fxmm_...%`,
  `%textshader_code_<эффект>[_<цвет>]%` (`&#D6....`), `%textshader_hex_...%` (`#D6....`).
  `nick*` и `chat_*` учитывают права (`textshader.use` и право эффекта), как таб и чат; для оффлайн-игрока - без эффекта.
- Таб: плагин сбрасывает имя в табе только если сам его ставил, чужие имена (из других плагинов) не трогает.

## config.yml

`chat.enabled`, `chat.tags` - эффект и теги в чате, `chat.nick` - ник в чате с эффектом ника. `chat.sanitize` (по умолчанию да) - из сообщения убираются
коды эффектов, на которые у игрока нет прав (и всегда typecursor, который делает текст невидимым): так нельзя обойти
`textshader.effect.<ключ>` через hex-цвета других плагинов (`&#D6B400`). Работает только для того, что попало в
сообщение до приоритета HIGH; формат чата, который другой плагин рисует позже (renderer), не проверяется. `nick.tab` - ставить ник с эффектом в таб (playerListName),
`nick.display-name` - еще и displayName (по умолчанию нет, чтобы не мешать чат-плагинам). `effects-default`.
`menu-sample` (фраза для превью сообщений в меню), `preview-text`. `messages` - все сообщения (MiniMessage,
русские, только короткие дефисы). `config-version: 2`: при старте со старым конфигом (версия 1) плагин сам
заменяет все `menu-*`, `usage-set`, `usage-nick`, `help`, `effect-*` на новые и дописывает `chat.nick`;
старый файл перед этим копируется в `config.v1.yml`, свои правки можно перенести оттуда.

## Ресурспак

- `pack/assets/minecraft/shaders/core/rendertype_text.{vsh,fsh}` (и `gui.*`, `position_tex_color.*`) - общие
  канонические файлы схемы хуков (см. ниже), эффекты подключаются через `textshader:ts_hook_text_vertex.glsl` /
  `ts_hook_text_fragment.glsl` (вызывают `ts_vertex` / `ts_fragment`), `rendertype_text_see_through.vsh` - то же для ников сквозь стены (только цвет в мире),
  `rendertype_text_intensity.vsh` и `rendertype_text_intensity_see_through.vsh` - TrueType-шрифты: код заменяется
  на цвет палитры (без анимации) и в GUI, и в мире. Фрагментные `*_see_through.fsh`, `rendertype_text_intensity.fsh`
  и `rendertype_text_background*` не трогаются.
- `pack/assets/textshader/shaders/include/`: `ts_common.glsl` (палитра, таблицы, декодирование, отступ квада),
  `ts_plain.glsl` (код -> обычный цвет палитры), `ts_vertex.glsl` (GUI: квад буквы расширяется на запас
  `ts_margin`, рассчитанный на заголовок 4x: обычно 4 GUI px, у bounce 40 по вертикали, у echo/extrude/sparkle/
  swing/vampire/sweep 8-16; углы 0 и 2 передаются во фрагмент; мир: цвет вершины = цвет палитры), `ts_fragment.glsl` (восстановление координат внутри буквы, сборка цвета),
  `ts_effects.glsl` (все эффекты, `ts_apply` по номеру).
- `rendertype_text.vsh/.fsh` общие с tabshader, nameshader и chatshader, но чужих include в паке textshader больше
  нет: только свои файлы, свои хуки и заглушки остальных (`pack/stubs`). Коды не мешают друг другу: маркер
  tabshader - цвет `R = 231` плюс проверка текселя глифа `tabshader:hud`, коды textshader - `R = 214` / тени `R = 53`.
- MythicHUD: его пак `hl-resourcepack.zip` кладет свои `rendertype_text.*` в оверлей `mythichud-1_21_6`, а оверлей
  важнее базовых ассетов - без правки эффектов textshader не будет. `pack/overlays/mythichud-1_21_6/...` - наш
  `rendertype_text` плюс `applyCustomHud()` MythicHUD (генерирует `tools/shaderhooks`, тот же файл в tabshader). Вставить в zip:
  `python3 -I tabshader/tools/mythichud_patch.py IN.zip OUT.zip` (подробно в README tabshader, раздел MythicHUD).
- `rendertype_item_entity_translucent_cull.*` (coreshaders) не пересекается с нами.
- Ограничения: курсив у буквы с эффектом не наклоняется (плагин ставит italic false), шрифты TrueType
  не анимируются (только цвет). Запас квада рассчитан на масштаб до 4x (заголовки); у текста крупнее
  часть эффекта за пределами буквы может обрезаться.

## Общие core-шейдеры: схема хуков (shaderhooks)

textshader, tabshader, nameshader, chatshader и aurahud меняют одни и те же core-шейдеры. Чтобы каждый плагин
работал один и в любом сочетании, а порядок установки не играл роли, используется одна схема во всех проектах:

- `gui.vsh/.fsh`, `position_tex_color.vsh/.fsh`, `rendertype_text.vsh/.fsh` - канонические файлы, побайтно
  одинаковые во всех плагинах (строки `#define SHADERHOOKS_VERSION 2` и `#define SHADERHOOKS_HASH h<16 hex>` -
  хэш содержимого без этой строки). Они вызывают фиксированный список хуков, по
  одному include на плагин и стадию: `<плагин>:<префикс>_hook_<программа>_<стадия>.glsl`. Префиксы: `ts` -
  textshader, `th` - tabshader, `ns` - nameshader, `cs` - chatshader, `ah` - aurahud. Программы: `gui`, `sprite`
  (`position_tex_color`), `text` (`rendertype_text`). Вершинная стадия: сначала `<p>_hook_<prog>_position(inout vec3
  pos)` у всех плагинов (сдвиг вершины до `gl_Position`; у `text` - `(inout vec3 pos, inout vec4 color)`, цвет
  вершины можно поправить до остальных хуков, так chatshader возвращает textshader-коду сообщений чата обычный вид), потом `<p>_hook_<prog>_vertex(...)` (исходная `Position`,
  цвет, UV, `gl_VertexID`, для текста свет, `inout vertexColor`). Фрагментная: `color = <p>_hook_<prog>_fragment(color,
  ...)` перед ванильным `discard`. Порядок вызова всегда ts, th, ns, cs, ah. С версии 2 `position_tex_color.vsh` объявляет
  `uniform sampler2D Sampler0`, так что вершинный хук `sprite` может читать текстуру (`textureLod`, `texelFetch`);
  сигнатуры хуков с версии 1 не менялись, хуки старых jar компилируются и с новыми общими файлами.
- Настоящие хуки плагина лежат в `pack/assets/<плагин>/shaders/include/<p>_hook_*.glsl` (тонкие адаптеры, вызывают
  функции плагина), заглушки всех пяти плагинов (пустые функции, `return color`) - в `pack/stubs/`. Путь у
  настоящего хука и у заглушки один и тот же, поэтому руками это не копируется: плагин при старте сам пишет файлы в
  `plugins/Nexo/pack/assets` (класс `ShaderHooks`, файлы берет из своего jar, `shaderpack/`):
  1. канонические файлы тех программ, где у него есть настоящий (не равный заглушке) хук - парой vsh+fsh. Чужой
     файл (без `#moj_import` наших плагинов) не заменяется, в логе красная строка, программа пропускается целиком.
     Файл с более новым `SHADERHOOKS_VERSION` тоже не заменяется (старый jar не откатывает новый). Файл той же версии
     с целым, но другим `SHADERHOOKS_HASH` (другая сборка той же версии) тоже не заменяется: красная строка
     "КОНФЛИКТ", пара пропускается, поэтому два разных jar не перезаписывают друг друга по кругу. Файл, правленный
     руками (хэш не сходится с содержимым), или старый без хэша заменяется, но сначала копируется в бэкап;
  2. все остальные свои файлы: include, свои хуки, текстуры, шрифты, свои отдельные core-файлы (если они не чужие);
  3. если в паке есть хоть один канонический файл - заглушки всех остальных плагинов, которых нет на сервере, или
     чьи хук-файлы неполные. Хуки удаленного плагина при следующем старте любого из оставшихся заменяются
     заглушками, его эффект в общих шейдерах пропадает.
  Файл пишется, только если содержимое другое (временный файл `*.shaderhooks.tmp` лежит в папке плагина, вне
  пака, потом переименование). Перед заменой общего core-файла или чужого хука (кроме заглушки) старое содержимое
  копируется в `plugins/<плагин>/pack-backup/<дата-время>/<путь>`, путь пишется в лог. Установка идет под одной
  общей для всех наших плагинов блокировкой JVM, так что два плагина не пишут пак одновременно. При старте сервера
  установка синхронная (до первого тика, когда Nexo собирает пак), при `reload` плагина - в фоновом потоке, итог и
  `nexo reload pack` - снова в основном. Nexo собирает пак на первом
  тике после включения всех плагинов, поэтому при старте сервера ничего перезагружать не надо. Если файлы
  изменились позже (`reload` плагина, загрузка на ходу) и Nexo включен - плагин сам вызывает `nexo reload pack`.
- Итог не зависит от порядка: общие файлы у всех одинаковые, свои файлы пишет только владелец, а заглушки - только
  за отсутствующие плагины. Проверки: `python3 -I tools/shaderhooks/shaderhooks.py combos` (каждый плагин отдельно,
  все пары и тройки, все вместе, все порядки установки: одинаковые файлы, повторная установка ничего не пишет, все
  программы компилируются glslangValidator 330 и 410, после удаления плагина его хуки - заглушки, чужой `gui.vsh` не
  тронут, более новая версия осталась; запускается и из `glsl_check.py`), JUnit `ShaderHooksTest` (то же для
  Java-кода на всех 31 наборе из 5 плагинов и всех порядках, совпадение общих файлов и `ShaderHooks.java` с
  соседними проектами), живой клиент `tabshader/tools/realclient.sh --server-pack` (пак пишут сами плагины на
  тестовом сервере, результат сверяется с эмуляцией `shaderhooks.py install`).
- `tools/shaderhooks/` (скрипт и шаблоны `ShaderHooks.java.in`, `ShaderHooksTest.java.in`) одинаковый во всех
  проектах. Правка - в любом проекте, потом `python3 -I tools/shaderhooks/shaderhooks.py --write` из него: папка
  копируется в остальные проекты, перегенерируются канонические файлы, заглушки, оверлей MythicHUD,
  `ShaderHooks.java` и `ShaderHooksTest.java` (отличаются только пакетом). Без `--write` - проверка, что все
  совпадает (ее запускает и `glsl_check.py`).
- config.yml каждого плагина: `pack.install` (по умолчанию `true`), `pack.dir` (пусто - `plugins/Nexo/pack/assets`;
  другой путь - для тестов), `pack.reload-nexo` (по умолчанию `true`). Без Nexo (нет `plugins/Nexo/pack`) плагин
  ничего не пишет и предупреждает в логе. Ручная установка при `pack.install: false`:
  `python3 -I tools/shaderhooks/shaderhooks.py install --dest plugins/Nexo/pack/assets --plugins textshader,tabshader,nameshader,chatshader,aurahud`
  (перечислить все наши плагины, что стоят на сервере). Копировать `pack/assets` руками нельзя: канонические файлы
  импортируют хуки всех плагинов, без заглушек пак не скомпилируется у игроков.
- chatshader (префикс `cs`): настоящие хуки `cs_hook_gui_*` (панель чата, поле ввода, подсказки команд) и
  `cs_hook_text_vertex` (сдвиг текста чата при `chat.position` не bottom-left); `cs_hook_sprite_*` и
  `cs_hook_text_fragment` равны заглушкам. chatshader пишет еще свой `chatshader:cs_config.glsl` из config.yml.
  aurahud (префикс `ah`) - раскладка HUD игрока, хуки во всех трех программах. Новые jar ставить все пять
  сразу: старый jar (версия 1) оставляет файлы версии 2 и пишет в лог предупреждение "обновите".
  nameshader с фиксом присевших ников пишет `rendertype_text.*` (настоящий `ns_hook_text_fragment`). Новая программа
  или другая сигнатура - только с новым `SHADERHOOKS_VERSION` во всех плагинах сразу. Хэши общих файлов каждой
  версии закреплены в `PINNED` в `shaderhooks.py`: проверка падает, если общий файл изменился без новой версии.
- Отдельные (не общие) core-файлы остаются у своих владельцев: textshader - `rendertype_text_see_through.vsh`,
  `rendertype_text_intensity*.vsh`; nameshader - `rendertype_text_see_through.fsh`, `rendertype_text_background*`.
  При удалении плагина их надо убрать из пака вручную (общие хуки плагин-сосед сам заменит заглушками).

## Сборка и проверки

```
cd textshader
./gradlew --offline build                      # тесты + build/libs/textshader-1.0.0.jar
python3 -I tools/glsl_check.py                 # glslangValidator: компиляция и линковка GLSL 330 и 410, дифф с ванилью, shaderhooks
python3 -I tools/shaderhooks/shaderhooks.py    # общие файлы схемы хуков совпадают во всех проектах (--write - обновить)
python3 -I tools/shaderhooks/shaderhooks.py combos   # все сочетания плагинов и порядки установки компилируются
python3 -I tools/preview.py                    # превью настоящими шейдерами (moderngl, EGL) в preview/
python3 -I tools/preview.py --only ocean,sweep # отдельные эффекты
python3 -I tools/preview.py --world            # текст в мире
python3 -I tools/preview.py --title            # заголовок 4x: bounce, extrude, sweep, sparkle ...
```

Тесты: коды цвета (все эффекты x цвета x номера, тень), разбор тегов чата и MiniMessage, нумерация печатной машинки,
сверка таблиц шейдера с Java (число эффектов, резерв 52-55, свои цвета, палитра, ветки `ts_apply`), светло-серые
цвета и их тени не являются эффектами, раскладка меню (каждый эффект ровно в одном слоте, страницы, кнопки не
пересекаются с эффектами, палитра, ЛКМ/ПКМ/Shift и игнор цифр), хранение выбора ника и сообщений по отдельности
(запись, рестарт, сброс, битые значения), ник в чате получает эффект и сохраняет чужие цвета, чат сохраняет чужие компоненты и события, сквозная нумерация, очистка чужих
кодов, все ключи сообщений из кода есть в config.yml, запрет комментариев в Java и шейдерах и длинных тире во всем
проекте.

## Деплой

1. Положить `build/libs/textshader-1.0.0.jar` в `plugins/`. Файлы пака руками не копировать: при старте плагин сам
   пишет в `plugins/Nexo/pack/assets` свои файлы, общие core-шейдеры и заглушки отсутствующих плагинов (см. "Общие
   core-шейдеры"). В логе: `Шейдеры в .../plugins/Nexo/pack/assets: записано файлов N` (или "все файлы на месте").
   Красная строка "Чужой шейдер ... не заменен" - в паке лежит чей-то `rendertype_text.*` (например, Nexo с
   gif-глифами): его надо объединить вручную или убрать, иначе эффектов не будет.
   Важно про Nexo: Nexo 1.30 при сборке пака сам кладет свои `rendertype_text*` шейдеры, если настроен хоть один
   анимированный (gif) глиф, и другие core-шейдеры при `hide_tablist_background` / `hide_scoreboard_*` в
   settings.yml. Сейчас это выключено и gif-глифов нет. Не включать это вместе с textshader (или объединять шейдеры
   вручную), иначе эффекты молча пропадут или сломаются.
2. Рестарт сервера (Nexo соберет пак на первом тике, Hermes раздаст). Без пака игроки увидят обычный цвет `#D6....`
   вместо анимации - плагин работает, но эффектов не видно.
3. Проверить в игре: `/ts preview sparkle`, `/ts list`, `/ts`. Обфускация SIMPLE шейдеры и include не трогает; в zip,
   который раздает Hermes, `assets/minecraft/shaders/core/rendertype_text.vsh` содержит `SHADERHOOKS_VERSION` и
   `ts_hook_text_vertex`, есть `assets/textshader/shaders/include/*.glsl` и заглушки
   `assets/{tabshader,nameshader,chatshader,aurahud}/shaders/include/*_hook_*.glsl` для тех, кого нет на сервере. Порядок
   установки плагинов (textshader, tabshader, nameshader) не важен.
4. Для таба через TAB-плагин (если он есть): в формате имени `%textshader_nick%`; без TAB плагин ставит ник в таб сам.
5. Откат: удалить jar и из пака отдельные файлы textshader - `rendertype_text_see_through.vsh`,
   `rendertype_text_intensity.vsh`, `rendertype_text_intensity_see_through.vsh`. Хуки `ts_hook_*` в общих файлах
   любой из оставшихся наших плагинов при старте заменит заглушками (папку `textshader/shaders/include` тогда не
   удалять - в ней эти заглушки). Если наших плагинов больше нет - удалить и общие файлы (`gui.*`,
   `position_tex_color.*`, `rendertype_text.*`) и папки `textshader/`, `tabshader/`, `nameshader/`, `chatshader/`, `aurahud/`.
