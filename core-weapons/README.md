# core-weapons

Система Amazake (Paper 1.21.11, форк; Java 21). Эффекты кастомного оружия Nexo. Оружие узнаётся по id предмета
Nexo (PDC `nexo:id`) или по своей метке `coreweapons:id`. Каждому оружию в `config.yml` назначаются поведения:
`orbit`, `swing`, `crit-tremor`. Новое оружие получает их, если добавить в конфиг секцию с его id. Первое оружие —
**Багровая коса** (`azerus_crimson_scythe`, модель и пак — `nexo-items/`).

| Поведение | Что видно | Как сделано |
|---|---|---|
| `orbit` | пока оружие в основной руке, вокруг лезвия по наклонённому кольцу кружат 3 точки: красно-оранжевая пыль (`DUST_COLOR_TRANSITION`), у каждой второй ещё `SMALL_FLAME`, который светится в темноте; у ладони иногда вспыхивает искра | задача игрока раз в 2 тика ставит частицы в мир, их видят все в радиусе 32 блоков |
| `swing` | при взмахе (`PlayerArmSwingEvent`, основная рука) коса делает замах: назад (1 тик), удар вперёд-вниз (2 тика), проводка у земли (3 тика), потом возвращается в обычное положение. По дуге перед игроком идёт огненный след (пыль и `FLAME`), звучит взмах | на предмет в слоте удара ставится строка `custom_model_data` `cw_swing_N`. Определение предмета в паке (`assets/azerus/items/crimson_scythe.json`, `select` по `custom_model_data`) выбирает по этой строке модель кадра, то есть ту же модель с другим `display` в руках. `hand_animation_on_swap: false` убирает перехват предмета в руке. После замаха строка снимается. Другие игроки видят кадры через пакет экипировки |
| `crit-tremor` | при крите (`EntityDamageByEntityEvent#isCritical`, удар в падении) от цели по земле расходится кольцо до 6 блоков за 12 тиков: частицы `BLOCK` и `DUST_PILLAR` верхнего блока каждого столбца, верхние блоки подпрыгивают на ~4 px и опускаются, глухой гул (шаг вардена, взрыв, deepslate). Игроков на кольце слегка подбрасывает (0.12) | копии блоков — `BlockDisplay` (`setPersistent(false)`, свет блока над поверхностью, интерполяция: вверх за 2 тика, вниз за 3, удаление на 6-м). **Мир не меняется.** Откат 30 тиков на игрока, не больше 90 копий за одну дрожь, урон по кольцу по умолчанию 0 |

Все числа лежат в `config.yml`: радиус, длительность, откат, высота подскока, толчок, урон, цвета, кадры, звуки.

## Почему без core-шейдера

Замах и дрожь сделаны без общего шейдера `rendertype_item_entity_translucent_cull`. Его копии лежат в rezusmenu,
core-portals и core-skyrift и уже заняты метками. Неточная метка однажды сломала текстуры всех предметов на сервере.
Пак и сервер дают нужное и без шейдера. Кадр замаха — это обычный `select` в определении предмета (1.21.4+): он
плавный, его видят все, и это работает с любым шейдерпаком (Iris/OptiFine). Дрожь — это настоящие копии блоков, и
её видят даже игроки без пакета ресурсов. Шейдер дал бы только интерполяцию между кадрами, а риск у него выше.

## Установка

1. Сборка: `./gradlew azs test` → `build/libs/core-weapons.azs` (копия лежит в `dist/core-weapons.azs`).
2. Файл кладётся в `systems/` сервера: сначала во временный файл, потом `mv` (класс дрожи загружается при включении,
   но заменять работающий файл на месте всё равно не надо). Затем `amazake system enable core-weapons`, для
   обновления — `amazake system restart core-weapons`.
3. Пак и предмет — в `nexo-items/` (см. `nexo-items/README.md`). Без пакета частицы и дрожь работают, а кадров не
   видно: предмет остаётся ванильным незеритовым мечом.

## Команды

| Команда | Что делает |
|---|---|
| `/cweapons give <оружие> [игрок]` | Выдаёт предмет для проверки без Nexo из `test-item`: материал, `item_model`, имя, метка `nexo:id` |
| `/cweapons list` | Оружия из конфига, сколько игроков отслеживается и сколько копий блоков стоит сейчас |
| `/cweapons reload` | Перечитывает `config.yml` |

Право — `coreweapons.admin` (у OP оно есть), алиас — `/coreweapons`.

## Как работает

- **Игрок**: у каждого онлайн-игрока есть `Holder`, задача `runForPlayer` каждый тик в его потоке. Она читает id
  предмета в основной руке (только PDC, без копии `ItemMeta`), ставит частицы кольца, ведёт кадры замаха и след.
- **Замах**: взмах раньше `min-interval` (6 тиков) после прошлого пропускается. Взмахи при копании блока тоже
  пропускаются (`BlockDamageEvent` … `BlockDamageAbortEvent`/`BlockBreakEvent`). Если сменить слот, переложить
  предмет или перечитать конфиг посреди замаха, кадры снимаются со всего инвентаря и курсора. Чужие строки, числа,
  флаги и цвета `custom_model_data` сохраняются. Если других данных нет, компонент возвращается к прототипу. Шкала
  атаки не сбрасывается, потому что тип предмета тот же.
- **Хвосты**: кадры снимаются при входе (на случай сбоя посреди замаха), выходе, смерти (с выпадающих вещей),
  выбрасывании и выключении системы.
- **Дрожь**: событие удара приходит в поток региона цели, туда же ставится задача регионального планировщика (раз в
  тик). Столбцы из чужого региона или незагруженного чанка пропускаются. Поверхность — верхний твёрдый непрозрачный
  блок от y+1 до y−4 от ног цели, над которым нет непрозрачного. Толчок игроку — `runOnceForPlayer`.
- **Потоки**: игрок (инвентарь, скорость) — только его поток. Мир (частицы у игрока, копии блоков) — поток региона.
  Общие карты — `ConcurrentHashMap`, настройки — неизменяемый снимок в `AtomicReference`. Планировщик сущностей
  не используется.
- **Выключение**: задачи отменяет ядро. Каждому игроку в его потоке снимаются кадры со всего инвентаря. Копии блоков
  удаляются: в своём регионе сразу, в чужом — задачей региона. Они и так не сохраняются в чанк.

## Проверено (mc-test, боты mineflayer, без Nexo: предмет из `/cweapons give`)

- Кольцо: наблюдатель в 4 блоках за 3 с получил 90 `dust_color_transition` и 60 `small_flame`. С пустой рукой
  частиц 0.
- Замах: свой слот `cw_swing_1` → `_2` (через 50 мс) → `_3` (через 100 мс) → без кадра (через 150 мс). Наблюдатель
  через экипировку видит ту же последовательность. Повторный взмах через 100 мс пропущен. После замаха кадра на
  предмете нет.
- Крит: каждый удар в падении поставил 90 `block_display`, и все 90 удалены. Частицы `block`, `dust_pillar`,
  `explosion` пришли. На сервере после этого 0 `block_display`.
- Выключение посреди дрожи: 0 `block_display` на сервере. Выключение посреди замаха: кадр снят. Смена слота посреди
  замаха: кадр снят. Частиц после выключения нет.
- Юнит-тесты: кадры, строки `custom_model_data`, геометрия (базис по yaw, кольцо, дуга, полосы волны), разбор
  конфига.
