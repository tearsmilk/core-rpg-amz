# guns (сервер) — огнестрел из TACZ: АКМ, AWP с прицелом 8x, Glock 17, M4A1, M16A1, Desert Eagle, M1897; своя плазменная винтовка ПВ-7

Пара клиентскому модулю `guns` (`client-modules/modules/guns`). Стреляет **сервер**: клиент присылает «выстрел» и
направление взгляда (раз в тик пачкой), сервер проверяет темп, патроны, перезарядку, «достаёт ли», порядок пачек и
угол к своему взгляду игрока ([FireValidator](src/main/java/ink/hoka/odyssey/guns/FireValidator.java)), сам
разбрасывает пулю ([Spread](src/main/java/ink/hoka/odyssey/guns/Spread.java): стоя / в движении / присев / в прицеле /
в вакууме), ведёт её по тикам с тяжестью и трением ([Ballistics](src/main/java/ink/hoka/odyssey/guns/Ballistics.java):
блоки по их формам, сущности по рамкам, попадание в голову — ±0,25 блока от глаз), наносит урон по расстоянию и шлёт
эффекты. У стрелка всё своё (вспышка, трассер, отдача, звук, счётчик) клиент показывает сразу, без ожидания сервера.

## Установка на сервер (точные пути)

Пути — от папки сервера (где `server.jar` и папка `module/`).

1. Собрать: `cd hoka-odyssey && ./gradlew :guns:build :gravity:jar` и
   `cd hoka-odyssey/client-modules && ./gradlew build -Phoka.core.jar=<ядро-мод 0.55+>` (команды с JAVA_HOME — в
   корневом README; клиентский модуль собирается и с ядром 0.68.0, и с ядром 0.69.0 с крючком onModelParts).
2. Серверный модуль: `hoka-odyssey/guns/build/libs/guns.jar` → **`module/guns.jar`**.
3. Клиентские модули: `client-modules/build/clientmods/guns.jar` и `spaceflight.jar` (в нём R не «ложится» с оружием
   в руке и отдача в невесомости) → **`module/clientmods/jars/`**.
4. Перезапустить сервер (или `homodule load guns` / `homodule reload guns`), затем в консоли или оператором:
   ```
   hogun install
   hoclient reload
   ```
   `hogun install` копирует ассеты из jar и дописывает записи (с копией `config.yml.bak-guns`, комментарии файла
   не трогаются; существующие записи не меняются):
   - **`module/guns/config.yml`** — оружие из config.yml в jar, которого там ещё нет (сервер, где config.yml создан
     прошлой версией с одним АКМ, получает `guns.ai_awp`, `guns.glock_17`, `guns.m4a1`, `guns.m16a1`, `guns.deagle`,
     `guns.m1897`, `guns.plasma_rifle`); у уже стоящей `guns.plasma_rifle` без слота `extended_mag` (прошлая версия)
     блок `attachments` заменяется новым из jar (удлинённая ячейка; остальная запись не трогается); после этого
     модуль сам перечитывает config.yml и рассылает моду новые файлы и настройки (без `homodule reload guns`);
   - **`module/hoitems/assets/tacz/`** — `ak47_lod.bbmodel`, `ak47_slot.png`, `762x39.png`, `ai_awp_lod.bbmodel`,
     `338.png`, `glock_17_lod.bbmodel`, `glock_17_slot.png`, `9mm.png`, `m4a1_lod.bbmodel`, `m4a1_slot.png`,
     `556x45.png`, `m16a1_lod.bbmodel`, `m16a1_slot.png`, `deagle_lod.bbmodel`, `deagle_slot.png`, `50ae.png`,
     `m1897_item.bbmodel`, `m1897_slot.png`, `12g.png`, `NOTICE.md`; в **`module/hoitems/config.yml`**
     → `items.ak47`, `items.ammo_762x39`, `items.ai_awp` (без `icon` — в инвентаре модель с прицелом),
     `items.ammo_338`, `items.glock_17`, `items.ammo_9mm`, `items.m4a1`, `items.ammo_556x45`, `items.m16a1`,
     `items.deagle`, `items.ammo_50ae`, `items.m1897`, `items.ammo_12g`, `items.plasma_rifle`,
     `items.ammo_plasma_cell`; своё оружие (не TACZ) — в **`module/hoitems/assets/hoka/`**: `plasma_rifle_lod.bbmodel`,
     `plasma_rifle_slot.png`, `plasma_cell.png`, `plasma_cell_extended.png` (иконка обвеса
     `items.att_plasma_cell_extended`; без NOTICE TACZ);
   - **`module/hosounds/assets/tacz/`** — 127 файлов `.ogg` и `NOTICE.md`; в **`module/hosounds/config.yml`** → 127
     звуков (`ak47_*`, `awp_*` — выстрел, выстрел с глушителем, доставание, затвор, перезарядка; `glock17_*`,
     `m4a1_*`, `m16a1_*`, `deagle_*`, `m1897_*` (помпа, патрон по одному), `gun_dry_fire`,
     `gun_fire_select`, `gun_flesh_hit`, `gun_head_hit`, `gun_kill`); звуки ПВ-7 (7 файлов `plasma_rifle_*.ogg`) — в
     **`module/hosounds/assets/hoka/`**, записи `plasma_rifle_*` с `files: [hoka/…]`;
   - затем сам выполняет `hoitem reload` и `hosound reload`. Не вышло дописать (YAML в одну строку и т.п.) — печатает
     YAML для ручной вставки (и пишет его в лог).
5. Модели от первого лица (`guns/ak47.bbmodel`, `guns/ai_awp.bbmodel`, `guns/glock_17.bbmodel`, `guns/m4a1.bbmodel`,
   `guns/m16a1.bbmodel`, `guns/deagle.bbmodel`, `guns/m1897.bbmodel`, `guns/plasma_rifle.bbmodel`), силуэты HUD,
   анимации тела (`rifle_default`, `pistol_default`) и вспышку модуль раздаёт моду сам через clientmods
   (`putFile`), из jar. Своя замена без пересборки — положить файл в **`module/guns/files/guns/<имя>`**.
6. Выдать: `hogun give ak47|ai_awp|glock_17|m4a1|m16a1|deagle|m1897|plasma_rifle [игрок]`, патроны: `hogun ammo [кол-во] [игрок] [оружие]` (без оружия
   — к оружию в руке, а если его нет — ко всему оружию).

Проверка: `hogun list` — оружие (у AWP — «затвор 0.9 с», «прицел 8.0x»); `hogun info [игрок]` — оружие, патроны, режим,
есть ли у игрока клиентский модуль и связь с clientmods/hoitems/hosounds. В логе при включении:
`guns: включён (оружие: ak47, ai_awp, glock_17, m4a1, m16a1, deagle, m1897; clientmods есть, hoitems есть, …)`.

## Команды (`/hogun`, только операторы)

| Команда | Что делает |
|---|---|
| `hogun give <оружие> [игрок]` | выдать оружие (полный магазин) |
| `hogun ammo [кол-во] [игрок] [оружие]` | выдать патроны (по умолчанию 90): к указанному оружию, иначе к оружию в руке, иначе ко всему (по разу на калибр) |
| `hogun reload [игрок]` | начать перезарядку |
| `hogun info [игрок]` | состояние стрелка |
| `hogun list` | оружие из config.yml |
| `hogun install` | дописать новое оружие в свой config.yml, поставить ассеты в hoitems/hosounds (см. выше; и обвесы: иконки, предметы `att_<id>`, звуки установки) |
| `hogun attach list [оружие]` | обвесы (все или подходящие оружию; `*` — встроенный) |
| `hogun attach give <обвес> [игрок]` | выдать предмет-обвес |
| `hogun attach set <обвес>` | поставить обвес на оружие в руке без предмета (совместимость проверяется) |
| `hogun attach remove <слот>`, `hogun detach <слот>` | снять обвес слота (предмет — в инвентарь) |
| `hogun attach clear` | снять весь обвес |

## Настройки — `module/guns/config.yml`

Создаётся при первом запуске, комментарии внутри. Главное: `pvp`, `damage-mobs`, `max-aim-deviation` (25°),
`rate-burst`, `vacuum.{impulse, target-impulse, sound, bullet-life}`, `particles`, `log-hits` (каждое попадание —
строкой в лог: кто, в кого, урон, расстояние, голова, здоровье до/после), `sound-range` и разделы `guns.<id>`
(магазин, темп, режимы, урон по расстоянию, пуля, разброс, отдача камеры, перезарядка, время доставания и
прицеливания, приближение (до 10), замедление в прицеле, файлы для клиента, id звуков). Новое у оружия:
`type` (rifle / sniper — за спиной, pistol — в кобуре и поза тела пистолета), `bolt-time` (ручной затвор, с),
`bolt-sounds-3p` (звуки затвора для остальных), `scope: true` (оптика: чёрный экран и круг прицела), `flash-scale`
(вспышка у ствола), `item-icon` / `item-model` / `ammo-icon` (что `hogun install` пишет в hoitems; `item-icon: ""` —
в инвентаре модель). Перечитать — `homodule reload guns` (клиенты получат новые настройки сразу).

## Как устроено

- Ручной затвор (AWP): сервер пропускает не больше одного выстрела за цикл «60/rpm + bolt-time» (запас на задержки
  сети ×1,25, «ведро» на один выстрел — паузой очередь не накопить); клиент после выстрела играет анимацию TACZ
  `bolt` (со звуками в такт) и не стреляет, пока затвор не закрыт. Убрал оружие до конца цикла — затвор не
  передёрнут: при доставании (по серийному номеру предмета) сначала `draw`, потом `bolt`, и сервер считает «достаёт»
  на время затвора дольше (сменой слота туда-обратно затвор не пропустить). После последнего патрона затвора нет —
  его передёргивает перезарядка с пустым магазином.
- Прицел у игрока с модулем — ПКМ забирает клиентский модуль и шлёт `ADS`; сервер считает «в прицеле» через
  `aim-time` (разброс 0,15°) и вешает замедление `hoka:gun_aim` (×`aim-speed`). Без модуля — ванильное
  «использование» предмета (CONSUMABLE без анимации), приближение через `setFieldViewModifier`.
- Патроны лежат в памяти по серийному номеру оружия (`hoka_gun_sn`) и пишутся в предмет (`hoka_gun_ammo`) при
  смене слота, раз в полсекунды после стрельбы, после перезарядки, при выходе и выключении модуля.
- Предмет из `/hoitem give ak47` (без меток) при взятии в руку сам становится оружием; предмет старой версии модуля
  получает компоненты заново.
- Модуль перезагрузили — игроки, у которых клиентский модуль уже загружен, подхватываются сами (clientmods
  `isReady`), без повторного входа.
- В `onDisable` — записать патроны, снять замедление/приближение, отписаться от clientmods и убрать свои файлы.

Протокол (канал `guns`, big-endian) — [Proto.java](src/main/java/ink/hoka/odyssey/guns/Proto.java): клиент → сервер
`HELLO`, `FIRE` (seq, до 16 выстрелов: мс от прошлого и направление), `RELOAD`, `FIREMODE`, `ADS`; сервер → клиент
`CONFIG`, `STATE` (патроны, запас, режим, флаги перезарядка/достаёт/вакуум, последний принятый seq), `TRACER` (другим
игрокам), `IMPACT` (точка, нормаль, вид; хвост — флаг плазмы и цвет трассера: по нему клиент рисует след пули на блоке), `RELOAD_START`, `REJECT`, `HIT`, `POSE` (тем, кто видит стрелка: оружие в руке, прицел,
перезарядка с её началом — при смене и раз в 2 с; по ней клиенты ставят позу тела от третьего лица), `BACK` (id
игрока и id оружия «за спиной» — первое длинное оружие быстрой панели не в выбранном слоте и через запятую первый
пистолет (он — в кобуре), «» — нет; тем, кто его видит, с модулем и ему самому — при смене и раз в 2 с; выключается
`back-gun: false` — тогда и второй хвост `CONFIG` пуст, и свой клиент его не рисует). В хвостах `CONFIG` — файл анимаций тела
(`player-animation`, по умолчанию `guns/rifle_default.player_animation.json`) и id предмета hoitems каждого оружия
(по нему клиент рисует оружие за спиной); третий хвост — вид оружия, время ручного затвора, флаг оптики и размер
вспышки; четвёртый — отдача в вакууме; пятый — дробь, свой прицел, перезарядка по одному; шестой — вид трассера
(0 — пуля, 1 — плазма) и длина сгустка. У `TRACER` флаг 4 — плазма, за флагами тогда f32 длина сгустка (старые
клиенты лишнее не читают). Без мода оружие за спиной не видно.

## Обвес (как в TACZ)

- Каталог — [`attachments.yml`](src/main/resources/attachments.yml) (в jar; свой — `module/guns/attachments.yml`):
  весь стандартный пак TACZ — 119 обвесов (110 предметов и встроенные части нашего оружия), 6 повышающих планок,
  метки. Сделан скриптом [`tools/tacz2bb/attachments2yml.py`](../tools/tacz2bb/README.md) из файлов пака (числа как
  есть, функции Lua FMJ/HE — нашими операциями `op`). Что подходит оружию — `guns.<id>.attachments` в config.yml
  (`slots`, `allow` со списком TACZ, `builtin`, `default`, `locked` — у AWP прицел, `extended-mag`, `reload-xmag`);
  `guns.<id>.explosion` — взрыв с фугасными патронами.
- Обвес хранится на предмете оружия (метки `hoka_att_scope|muzzle|stock|grip|laser|mag`, `hoka_att_virtual`,
  `hoka_att_adapter_scope`, `hoka_att_zoom`, `hoka_laser_<слот>`, `hoka_att_init`), в описании — «Обвес: …».
  Предмет-обвес — hoitems `att_<id>` (метка `hoka_att`), без hoitems — бумага с названием.
- Характеристики с обвесом ([`AttachmentMath`](src/main/java/ink/hoka/odyssey/guns/AttachmentMath.java), как TACZ:
  (база + add) × (1 + percent) × mul, потом op): время прицеливания, разброс (от бедра, присев, в прицеле), отдача,
  урон и дальности полос, скорость пули, темп, в голову, пронзание, отбрасывание, магазин (`extended-mag` по уровню),
  перезарядка с удлинённым магазином, кратность прицела (до 10), вспышка, глушитель (свой звук, тише на
  `distance` блоков, у других нет вспышки — флаг `TRACER`), фугасные (взрыв без разрушения блоков), зажигательные
  (поджог), пуля вместо дроби. Пробитие брони и вес — только считаются и показываются; штык/приклад (ближний бой) —
  пока нет.
- Ставит и снимает сервер (экран обвеса клиентского модуля, клавиша Y): всё проверяется — оружие в руке, не
  перезарядка, слот есть и не заперт, обвес подходит (allow, встроенный, планка), предмет правда в инвентаре; не
  чаще 10 действий в секунду. Старый обвес — в тот же слот инвентаря, снятый — в свободный (нет места — не снимается);
  магазин стал меньше — лишние патроны в инвентарь. Пока экран открыт, стрелять и целиться нельзя.
- Протокол обвеса — в [Proto.java](src/main/java/ink/hoka/odyssey/guns/Proto.java): клиент → сервер `REFIT` (6),
  `ATTACH` (7), `DETACH` (8), `BUILTIN` (9), `ADAPTER` (10), `LASER` (11), `ZOOM` (12); сервер → клиент `LOADOUT` (10,
  обвес своего оружия и его характеристики), `GEAR` (11, обвес оружия в руке — тем, кто видит), `REFIT_RESULT` (12).
  Каталог и обвес каждого оружия — файлом `guns/attachments.json` (clientmods), модели обвесов — `guns/att/<id>.bbmodel`
  (упрощённые — `<id>_lod.bbmodel`), иконки — `guns/att/<иконка>.png`.

## Своё оружие: плазменная винтовка ПВ-7 (`plasma_rifle`)

Не из TACZ и ничего из TACZ не повторяет: модель, текстура, анимации, иконки и звуки сделаны нашими скриптами
[`tools/plasma/`](../tools/plasma/) и лежат отдельно — в [`assets-hoka/`](assets-hoka/) (в jar — папка `hoka/`, в
hoitems/hosounds — `assets/hoka/`), под NOTICE TACZ не попадают. Перегенерировать:
`python3 tools/plasma/gen_plasma_rifle.py [превью.png]` и `python3 tools/plasma/gen_plasma_sounds.py` (numpy, Pillow,
ffmpeg с libvorbis).

- `gen_plasma_rifle.py` — модель кубами (корпус как у «калаша» с изогнутой энергоячейкой, пистолетной рукоятью и
  каркасным прикладом; вместо ствола — воротник-радиатор и вращающийся блок из четырёх коротких стволов с голубыми
  кончиками; тёмно-синий металл, тёмно-красные вставки, светящиеся индикаторы), процедурная текстура, анимации
  `static_idle`, `static_auto/semi`, `switch_auto/semi`, `draw`, `put_away`, `shoot` (толчок и поворот блока стволов
  на 90°), `reload_tactical` / `reload_empty` (ячейка вниз, новая снизу, с пустой — рукоять заряжания), те же
  `reload_tactical_xmag` / `reload_empty_xmag` медленнее в 1,12 раза (с удлинённой ячейкой), `inspect`;
  упрощённая модель для hoitems, силуэт HUD, иконки винтовки, ячейки, удлинённой ячейки и приклада, голубая вспышка. Координаты — как у
  `ak47.bbmodel`, поэтому в руках лежит так же. Кости: `sight` (механический прицел — прячется под оптикой),
  `scope_pos`, `laser_pos` (левая планка цевья), `grip_pos`, `stock_pos`, `refit_*_view`, `magazine` (внутри —
  `mag_standard` и удлинённая `mag_extended_1`, ×1,75, видна только с удлинённой ячейкой) / `additional_magazine`,
  `*_illuminated` (светятся), `plasma_wire_stock` (встроенный приклад), `ar_stock_adapter` (трубка для прикладов AR),
  `laser_adapter` (прижимные планки — только с ЛЦУ, у которых `display.adapter: laser_adapter`, например
  `laser_compact`).
- `gen_plasma_sounds.py` — звуки синтезом (numpy) → `.ogg` через ffmpeg (libvorbis): выстрел (стерео у стрелка и
  моно из точки), доставание, убирание, ячейка вынута / вставлена, заряд. Звуки в анимации — `hoka:<id>`.
- Обвес: слоты `scope`, `stock`, `laser`, `grip`, `extended_mag` — прицелы, рукояти, приклады AR и ЛЦУ (`#ar_laser` и
  пистолетные `#pistol_laser`, например «Компактный ЛЦУ Militech» `laser_compact`) те же, что у M4A1; встроенный
  приклад `plasma_wire_stock`; в слот магазина — только своя «Удлинённая плазменная ячейка» `plasma_cell_extended`
  (72 выстрела вместо 36, `extended-mag: [72, 72, 72]`, перезарядка `reload-xmag` 2,13 / 2,63 с; выдать —
  `hogun attach give plasma_cell_extended`). Обе записи — в `attachments.yml` в конце файла (свои, не TACZ).

## Ограничения

- Попадания — по положению целей на сервере, без компенсации задержки; корпуса кораблей (модуль ships) пули не
  видят. Броню Minestom не считает.
- Поза тела от третьего лица (винтовка двумя руками у плеча, прицел, перезарядка, отдача корпуса — анимации TACZ
  `rifle_default`, у Glock — `pistol_default`) — только у клиентов с модом, где есть крючок ядра `onModelParts`
  (0.65+ с нашей добавкой; сейчас — 0.69.0 из `model-parts-0.68.patch`;
  [docs/mod-additions](../docs/mod-additions/README.md)). Со старым ядром — поза игры: оружие вдоль опущенной руки, в
  прицеле — поза лука (обе руки вперёд, ствол вперёд): у оружия анимация использования BOW, игроку с модулем сервер в
  прицеле (не в перезарядке) ставит «использование» предмета (`refreshActiveHand`), замедление тогда — USE_EFFECTS
  предмета, как без модуля (атрибут — только в прицеле без позы, вместе не бывают). Для пистолета это тоже лучшая
  ванильная поза: у TACZ пистолет держат двумя руками, правая вперёд, левая под углом к ней (`pistol_default`
  `aim_upper`: −90° и −82°/+38°), у лука — обе руки вперёд, левая повёрнута внутрь на ~29°; другие анимации
  использования (SPYGLASS, TOOT_HORN — рука к лицу, BLOCK — поперёк груди, SPEAR — над головой, CROSSBOW — только у
  заряженного арбалета) дальше от неё. Поза лука держится только в прицеле: «использование» без зажатой ПКМ игра
  сразу отпускает (сервер получил бы конец прицела каждый тик), поэтому от бедра на 0.68 пистолет висит в опущенной
  руке. Клиенты без клиентского модуля видят только модель hoitems в руке.
- Оптика: прицел TACZ «Scout 4-10x» переключает 5x/10x — у нас одно приближение `zoom` (8). Сетка — с прицела TACZ
  (кости `division`), но без подсветки и без коллиматора сбоку (у TACZ он второй окуляр со своей сеткой). Круг
  оптики у нас всегда в центре экрана (у TACZ — где окуляр после анимации), чувствительность мыши в прицеле — делённая
  на приближение (в невесомости — как без прицела: взгляд держит spaceflight).
- AWP в TACZ стреляет патроном `.338` (Lapua Magnum), не 7,62×51 — так и у нас (`ammo_338`).
- Звук выстрела стрелка — стерео-файл TACZ: слышит только он сам (не из точки).
