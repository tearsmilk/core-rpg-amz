# starmap — карта-радар (клиентский модуль)

**M** — открыть/закрыть карту. Это «технический радар»: зелёный люминофор на почти чёрном, круглый экран с кольцами
дальности (подписи в блоках), рисками курса через 10° и буквами С/В/Ю/З, вращающейся развёрткой с послесвечением
(контакты вспыхивают, когда луч проходит по ним), сеткой, строками развёртки и лёгким мерцанием. Открывается с
«включением»: окно чуть пружинит (как `appear` у окон houi), полоса развёртки проходит экран сверху вниз.

На карте:

- **блоки вокруг** — вид сверху на то, что прогружено у клиента (в пределах прорисовки): самый верхний блок
  каждого столбца, цвет — цвет блока на карте, переведённый в палитру радара: ниже тебя — зелёный и темнее, выше —
  голубой и ярче, через каждые 4 блока высоты — полоса-горизонталь. В космосе (пустые карты) при большом обзоре
  астероиды и станции дополнительно видны **засветками** — точка на каждый чанк с блоками;
- **ты** — белая стрелка по курсу взгляда в центре (с расходящимся кольцом); увёл вид — стрелка на ободе показывает,
  где ты;
- **корабли** (с сервера): твой — голубой, чужие — янтарные, нос — по курсу корабля; за краем обзора — точка на ободе;
- **игроки** — зелёные стрелки. С сервера (модуль `starmap`), а без него — те, кого видит сам клиент;
- **твои точки** — розовые ромбики с именем.

У каждого контакта — **ножка высоты** (значок поднят над своим местом, если выше тебя, опущен — если ниже) и подпись
разницы высот (`+12`, `−30`). Наведи мышь — подсказка: имя, что это, владелец, дальность и высота.

## Управление

| | |
|---|---|
| **M** | открыть / закрыть (не срабатывает, пока открыт чат или другое окно; клавиша — `open_key`) |
| колёсико, **+** / **−**, кнопки «+» «−» | масштаб: радиус обзора 32…1024 блока (в свободном виде колёсико приближает к курсору) |
| тянуть левой кнопкой | сдвинуть вид (вид перестаёт следовать за тобой) |
| **R**, кнопка «К СЕБЕ» | вернуть вид к себе (`recenter_key`) |
| щелчок левой по пустому месту | поставить точку («Точка N», высота — верхний блок там или твоя) и выбрать её |
| щелчок левой по точке | выбрать (в боковой панели — имя, его можно исправить в поле; Enter — готово) / снять выбор |
| правая по точке, **Delete**, кнопка «УДАЛИТЬ ТОЧКУ» | удалить точку |
| **Esc** | закрыть |

Боковая панель: позиция (X/Y/Z), курс (градусы и сторона света), радиус обзора и шаг сетки, режим вида, координаты
и высота блока под курсором с дальностью до него, число кораблей / игроков / точек, ход сканирования блоков, связь с
сервером («НЕТ» мигает, если серверного модуля нет или он молчит), условные знаки.

Точки хранятся отдельно для каждого сервера и карты: `.minecraft/hoka_odyssey/data/starmap/waypoints/<сервер>__<карта>.json`
(`{"waypoints": [{"name", "x", "y", "z"}]}`, не больше 256). Имя карты присылает сервер; без серверного модуля —
измерение игры (`minecraft_overworld` и т.п.).

По желанию — **метки точек на экране без карты** (`hud_waypoints = true`, по умолчанию выкл.): ромбик с именем и
расстоянием вверху экрана, когда точка впереди (±60° от взгляда).

## Почему своё окно, а не houi

Окна houi (JSON-раскладка, `/houi reload`) хороши для меню с кнопками и списками, но радар — это рисование каждый
кадр по данным клиента: развёртка, масштаб колёсиком, перетаскивание, щелчок в произвольную точку карты, слой блоков
из прогруженных чанков (своя текстура). Узлов для этого в houi нет, а гонять данные через сервер ради каждого кадра
нельзя. Поэтому окно — свой `Screen` клиентского модуля (`RadarScreen`), нарисованный `GuiGraphics`. Классы
окон ядра (`ink.hoka.odyssey.client.ui.*`) — не API модулей, поэтому не используются; внешний вид повторяет их сами:
затемнение мира `#88000000` без размытия, рамки как у `box` (заливка, рамка 1 px, пиксельные скругления), пиксельный
шрифт игры, появление с упругостью «back». Цифры — моноширинным шрифтом игры (`minecraft:uniform`, `mono_digits`).

## Как устроен слой блоков

`Terrain`: текстура 1024×1024 (1 пиксель = 1 блок, ±512 блоков вокруг места, где её начали; ушёл дальше 256 блоков —
собирается заново вокруг тебя). Чанки читаются по кругу от центра **понемногу за кадр** (`scan_budget_ms`, 3 мс) —
в потоке отрисовки, потому что мир клиента из другого потока читать нельзя; так кадр не стоит дольше бюджета. Пустые
секции («только воздух») пропускаются целиком, поэтому космос почти ничего не стоит. Пока карта открыта, чанки
перечитываются по кругу (новые блоки, твоя высота), текстура отправляется на видеокарту не чаще раза в 150 мс.
Закрыл карту — сканирование стоит; текстура остаётся до выхода с сервера (следующее открытие — сразу с картинкой).

## Настройки

`.minecraft/hoka_odyssey/data/starmap/config.properties` (создаётся сам, с комментариями):
`open_key` (`key.keyboard.m`), `recenter_key` (`key.keyboard.r`), `default_range` (256), `terrain` (true),
`scan_budget_ms` (3), `sweep_seconds` (4), `flicker` (true), `mono_digits` (true), `client_players` (true — без
серверного модуля показывать игроков, которых видит клиент), `hud_waypoints` (false), `hud_waypoints_distance` (5000).

## Протокол (канал модуля `starmap`, big-endian, как `DataOutputStream`)

Клиент → сервер:

| op | Содержимое |
|---|---|
| 1 — карта открыта/закрыта | `u8 op, u8 open` (1 — открыта, 0 — закрыта). Пока открыта — повтор раз в 5 с; сервер без повтора 15 с (`open-timeout-seconds`) считает её закрытой |
| 2 — «на какой я карте» | `u8 op` — при входе и смене мира (сервер отвечает не чаще раза в секунду) |

Сервер → клиент:

| op | Содержимое |
|---|---|
| 1 — контакты | `u8 op, u8 version (1), UTF map, i32 shipCount`, на корабль `UTF id, UTF name, UTF owner, u8 flags, f64 x, f64 y, f64 z, f32 yaw`; затем `i32 playerCount`, на игрока `i64 uuidMost, i64 uuidLeast, UTF name, f64 x, f64 y, f64 z, f32 yaw, u8 flags` |
| 2 — имя карты | `u8 op, UTF map` |

Флаги корабля: бит 0 — мой, 1 — летит, 2 — я пилот, 3 — спрятан. Флаги игрока: бит 0 — пилотирует корабль.
`yaw` — градусы Minecraft (0 — на юг, +Z; 90 — на запад). Сервер шлёт op 1 сразу после «открыта» и дальше раз в
`period-ticks` (10 — 2 раза в секунду), только пока карта открыта.

Клиент проверяет ввод: не больше 4096 кораблей/игроков и не больше, чем помещается в длину сообщения; строки
обрезаются до 64 символов, управляющие символы и `§` выкидываются; нечисловые и огромные (>1e8) координаты
отбрасываются; незнакомые op — пропускаются (новая версия сервера). Данные старше 3 с считаются устаревшими.

## Сборка

Нужны только обычные крючки ядра (`onTick`, `onHud`, `onMessage`, `send`) — собирается и против jar мода 0.17, и
против исходников ядра:

```bash
cd hoka-odyssey/client-modules
JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./gradlew build --max-workers=1 \
  -Porg.gradle.java.installations.paths=/usr/lib/jvm/java-25-openjdk-amd64 \
  -Phoka.core.jar=/путь/к/hoka-odyssey-0.17.0.jar
```

Результат — `build/clientmods/starmap.jar` → на сервер в `module/clientmods/jars/`, затем `/hoclient reload`.
Серверная пара — `hoka-odyssey/starmap` (`starmap/build/libs/starmap.jar` → `module/`).

## Ограничения

- Блоки — только то, что прогружено у клиента (прорисовка); дальше — пусто (засветок там тоже нет).
- Курс стоящего (не летящего) корабля сервер вычисляет по «носу» чертежа (`forward`) — если в чертеже нос не задан,
  курс 0 (на юг).
- Корабли — только с серверным модулем `starmap` и модулем `ships`; без них — ты, игроки рядом (что видит клиент) и
  точки.
- Точки — только у себя (на сервер не уходят и другим игрокам не видны).
