# spaceflight — живая невесомость в вакууме (клиентский модуль, мод 0.48+)

Пока сервер говорит «ты в вакууме», игрок летает как в настоящем космосе:

- **инерция** — ни сопротивления воздуха, ни «ванильного» падения: толкнулся — летишь, пока что-то не остановит;
- **тяготение** — от тел, которые прислал сервер, по закону 1/r² (общая библиотека `spacephys`, та же, что у
  сервера): рядом с планетой тянет к ней, можно выйти на орбиту;
- **тяга ранца** — W/S вперёд/назад, A/D вбок, пробел/shift вверх/вниз — по осям **взгляда** (а не по горизонту),
  `thrust` б/с² (0,8; сервер может ограничить своей); стоя на блоке — обычный шаг и прыжок от поверхности (прыжок —
  только по новому нажатию пробела, зажатый пробел не толкает снова);
- **стабилизатор** — без клавиш движения скорость сама плавно гаснет (`stabilizer`, 1,5 б/с²; 0 — чистый реализм:
  летишь, пока не врежешься, орбиты держатся); **X** — тормоз (`brake`, 3 б/с², клавиша `brake_key`). Предел скорости
  `max_speed` — 20 б/с (и не больше серверного `physics.thrust.max-speed`);
- **свободная камера** — мышь вращает взгляд в своих осях, крен на 360° — Z/C (настраивается); можно сделать петлю
  через верх. Поворот камеры уходит в ядро целым кватернионом (`CameraState.rotation`) — без особых точек у
  «прямо вверх/вниз»; углы yaw/pitch/roll тоже заполняются (звук и прочее). Прицел и ломание блоков следуют за взглядом;
- **магнитные ботинки** — зажми **Shift** у любого блока (пол, стена, потолок): прижимает к нему, вакуум больше не
  уносит, W/A/S/D — шаг вдоль поверхности (по взгляду, спроецированному на неё), пробел — оттолкнуться. Из
  касаний выбирается то, чья нормаль ближе к верху камеры («на чём стоишь»). Камера плавно выравнивает крен по
  поверхности, так что стена или потолок становятся «полом» (мышь работает как обычно, относительно экрана).
  Отпустил Shift — снова обычная невесомость (инерция, отскок и трение при ударе как раньше). Обычная ходьба по
  земле планет — без изменений;
- **поворот тела** (крючок ядра `onEntityPose`; видно другим игрокам и себе в F5):
  - **стоишь на поверхности** (ботинки держат, или касаешься блока, чья нормаль ближе 60° к верху камеры — «под
    ногами»; пол, стена, потолок) — тело повёрнуто относительно ног: верх тела по нормали поверхности, ноги на ней,
    лицом — по взгляду вдоль поверхности, голова смотрит туда же, куда ты;
  - **свободно в пространстве** — тело всегда повёрнуто к прицелу: лицом туда, куда смотришь, верх тела — по верху
    камеры, поворот вокруг середины тела;
  - **R** — «лёжа»: тело вдоль взгляда (макушкой вперёд, «супермен»), на поверхности — лёжа на ней;
  - смена режима — плавно (~150 мс); касание пропало — ещё 4 тика считается, что стоишь (без дрожи на отскоках).

  Модуль шлёт серверу кватернион тела (без «лёжа») и флаги (лёжа, грань под ногами) ~10 раз в секунду и только
  когда они меняются, сервер раздаёт их остальным, а их модуль строит ту же позу.

### Поворот тела и мод

- **0.48.0** — поворот работает (`onEntityPose`), но ядро крутит модель только **вокруг ног**: свободно летящее тело
  поворачивается вокруг ступней, а стоящий на стене стоит ногами в середине своей (ровной) рамки, а не на стене;
- **с добавкой `EntityPose.offset`** (`docs/mod-additions/README.md`) — модуль сам находит её рефлексией и ставит
  модель точно: свободно — вокруг середины тела, на стене/потолке — ногами на поверхности. Пересобирать модуль не нужно;
- ядро без `onEntityPose` — модуль не рисует чужие тела, лёжа своё тело показывает анимацией плавания, а сервер
  показывает лежащих другим позой полёта на элитрах (как раньше). Модуль шлёт серверу op 5 («рисую сам») только
  когда крючок есть.

Вне вакуума камера плавно возвращается «в горизонт», дальше всё как обычно. При выключении модуля, смене мира
и возрождении всё восстанавливается.

## Настройки

`.minecraft/hoka_odyssey/data/spaceflight/config.properties` (создаётся сам, с комментариями): `thrust` (0,8),
`max_speed` (20), `stabilizer` (1,5), `brake` (3), `brake_key` (`key.keyboard.x`), `roll_speed` (60 °/с),
`roll_left`, `roll_right`, `ground_grip`, `walk_speed`, `jump_speed`, `upright_rate`,
и для магнитных ботинок: `grip_press` (сила прижима, б/с², 20), `grip_break_speed` (отлетаешь быстрее — не
удерживает, б/с, 4), `surface_align_rate` (выравнивание камеры по поверхности, доля за секунду, 2; 0 — выкл.).
`ground_grip`, `walk_speed`, `jump_speed` действуют и при ходьбе по стенам. Файл старой версии (без
`config_version`) модуль обновляет сам: значения, равные прежним умолчаниям (`thrust = 2.0`, `roll_speed = 90`,
`max_speed = 120`), заменяются новыми, свои значения сохраняются, старый файл — `config.properties.old`.

Тяга и предел скорости — не больше, чем прислал сервер (op 2), так что проверка скорости сервера с ними согласна.
Скорость модуль ведёт сам: от vanilla берёт только удар о блок (ось обнулилась) и толчки сервера, а ввод WASD
vanilla и обнуление скоростей меньше 0,003 блока/тик — нет (иначе ввод был бы «бесплатной» тягой, а слабая тяга
0,8 б/с² из покоя не разгоняла бы вовсе: прибавка 0,002 блока/тик за тик стиралась бы). Телепорт (сдвиг на блок
больше ожидаемого) — скорость как есть у vanilla.

На сервере (модуль `gravity`, `config.yml`) — `physics.surface-walk` (8 б/с): запас проверки скорости у блоков,
чтобы ходьба по стенам и прыжки от них не считались читом. Если поднимаете `walk_speed`/`jump_speed`, поднимите и его.
Клавиши крена — имена Minecraft (`key.keyboard.q`, `key.mouse.4` …). По умолчанию Z/C, потому что Q и E в игре
уже заняты (выбросить предмет, инвентарь).

## Протокол (канал модуля `spaceflight`, big-endian)

Сервер → клиент:

| op | Содержимое |
|---|---|
| 1 — тела | `u8 op, i32 count`, на тело `f64 x, y, z, mu, radius, softening` (блоки, μ — блоки³/с²). `softening > 0` — малое тело (Пламмер), иначе планета радиуса `radius` |
| 2 — физика | `u8 op, u8 on` (1 — включить невесомость, 0 — выключить); при `on = 1` дальше `f64 thrust, f64 maxSpeed` — пределы сервера (б/с², б/с; 0 — без предела скорости). Старый сервер их не шлёт — тогда свои настройки |
| 3 — поворот тела другого игрока | `u8 op, i32 entityId, f32 w, x, y, z, u8 flags` — кватернион тела без «лёжа» (соглашение FreeLook/spacephys: лицо +Z, верх +Y; свободно — это взгляд, на поверхности — верх по нормали, лицом по взгляду), флаги: бит 0 — лёжа, бит 1 — действует, биты 2–4 — грань под ногами + 1 (1 +X, 2 −X, 3 +Y, 4 −Y, 5 +Z, 6 −Z; 0 — свободно). Старый клиент лишние биты не читает |
| 4 — поворот больше не действует | `u8 op, i32 entityId` (вышел из вакуума, ушёл с сервера) |

Клиент → сервер:

| op | Содержимое |
|---|---|
| 3 — свой поворот | `u8 op, f32 w, x, y, z, u8 flags` (как S2C op 3, без entityId; флаги 0 — «больше не действует») |
| 5 — возможности | `u8 op, u8 caps`: бит 0 — умеем рисовать повёрнутые тела (шлётся в ответ на op 1, только если в ядре есть `onEntityPose`) |
| 6 — модуль загружен | `u8 op` — один раз на подключение (и после `/hoclient reload`): сервер заново шлёт тела и «физика вкл.» |

Сервер проверяет op 3 (конечные числа, нормирует кватернион, оставляет только известные биты флагов, грань 7 —
«свободно», не больше 30 сообщений в секунду), раздаёт повороты
только игрокам в вакууме с модулем и только тем зрителям, у кого модуль загружен (не чаще 10 раз в секунду, без
изменений — раз в секунду для новых зрителей).

Ввод проверяется: не больше 4096 тел, длина сообщения, конечные числа. Новые тела заменяют старые целиком.

## Как это устроено (соглашения)

- **Взгляд** — `FreeLook`: Q = Ry(−yaw)·Rx(pitch)·Rz(roll), взгляд +Z, верх +Y (как `spacephys.Quat`).
- **Камера** — игра строит поворот как `rotationYXZ(π − yaw, −pitch, roll)` и смотрит вдоль −Z, поэтому
  `CameraState.rotation` = Qlook·Ry(π) (roll камеры = −roll FreeLook); F5 «лицом к себе» — сам Qlook. Доказано
  тестом `CameraConventionTest` (случайные углы и разложение произвольных ориентаций против JOML `rotationYXZ`).
- **Модель** — `EntityPose(tilt = Qbody, bodyYaw = 0, headYaw, headPitch[, offset])`: vanilla после tilt делает
  Ry(180° − bodyRot), лицо модели в этих осях −Z, значит с bodyYaw = 0 модель смотрит вдоль Qbody·(+Z) и стоит вдоль
  Qbody·(+Y) (`BodyFrameTest.modelConventionMatchesVanillaChain`). Голова — взгляд сущности в системе тела:
  L = Qbody⁻¹·look, headYaw = atan2(−Lx, Lz), headPitch = asin(−Ly).
- **Сдвиг** (если ядро умеет `offset`): середина модели (0, h/2, 0) ставится в точку C, offset = C − Qbody·(0, h/2, 0);
  свободно C — середина рамки; стоя на грани n — точка касания (середина рамки − n·полразмера рамки вдоль n) + n·h/2,
  то есть ноги ровно в точке касания; лёжа на грани — середина тела на 0,15 блока над ней. Рамка сущности остаётся
  ровной (столкновения не меняются), поворот и сдвиг — только картинка.
- **Ввод** — крючок ядра `onInput`: в невесомости `keyPresses = Input.EMPTY` и вектор хода 0 (`setMove`), то есть игра
  не ходит, не прыгает, не приседает и не бежит; клавиши модуль читает сам по их привязкам (переназначение
  учитывается).

## Сборка

Модулю нужен мод **0.48+** (`CameraState.rotation`, `onInput`, `onEntityPose`) — рядом файл `requires-camera-api`.
Сборка идёт против jar мода (в репозиторий jar **не** кладётся — только путь):

```bash
cd hoka-odyssey/client-modules
JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./gradlew build --max-workers=1 \
  -Porg.gradle.java.installations.paths=/usr/lib/jvm/java-25-openjdk-amd64 \
  -Phoka.core.jar=/путь/к/hoka-odyssey-0.48.0.jar        # или переменная окружения HOKA_CORE_JAR
```

Перед jar прогоняются тесты математики (`BodyFrameTest`, `CameraConventionTest`, JUnit 5). Результат —
`build/clientmods/spaceflight.jar` (классы `spacephys` вшиты). Положить на сервер в `module/clientmods/jars/`, затем
`/hoclient reload`.
