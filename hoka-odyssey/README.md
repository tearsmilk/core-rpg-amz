# Модули Hoka Odyssey (Minestom 1.21.11)

Модули для сервера **Hoka Odyssey** — ядро на Minestom из репозитория
[SakuraMesd/HokaOdyssey](https://github.com/SakuraMesd/HokaOdyssey). Здесь только модули; ядро и его API мы **читаем**,
но не меняем (правила — `DEVELOPER.md` в репозитории ядра).

| Модуль | jar | Что делает |
|---|---|---|
| `coreshaders` | `coreshaders.jar` | Порт плагина `coreshaders` (Paper) — «окна в другой мир»: куб или плоскость с панорамой 360° на шейдере. Эффекты — `ItemDisplay`, команды `/hocs…`. `depends: [respack]` |
| `spacesky` | `spacesky.jar` | Небо шейдером: профили неба по мирам — галактики (звёзды, туманности, Млечный путь, чёрные дыры из gravity) и планеты (атмосфера, сутки, солнце, облака, луна); у каждого профиля свой тип мира `hoka:<профиль>` (модуль регистрирует), карта выбирает его в `map.yml` (`/hosky world`). Во всех мирах (без профиля — космос `space`) или только в мирах профилей. На сервере ничего не крутится. `depends: [respack]`, `softdepends: [gravity]` |
| `gravity` | `gravity.jar` | Вакуум/невесомость на выбранных картах: игрок висит, пробел/Shift — плавно вверх/вниз, WASD — с инерцией; без клавиш вакуум сносит игрока к чёрной дыре (или по `drift`). Предметы (ItemEntity) — без гравитации, плывут по инерции и поглощаются чёрными дырами. Гравитация игрока = 0 (атрибут), тяга и дрейф — добавочными импульсами скорости. Карты и дыры — `module/gravity/config.yml`, команда `/hograv [on\|off <карта>\|reload\|hole list\|add\|remove]` (OP). Подробнее — раздел gravity ниже |
| `oxygen` | `oxygen.jar` | В космосе нет воздуха: на картах из `maps` (`module/oxygen/config.yml`, по умолчанию `galaxy1`) без скафандра убывает ванильная шкала пузырьков, потом урон как от утопления. Скафандр — стекло на голове (`/hosuit [ник]`, OP). Креатив и наблюдатель урона не получают. Без `depends` |
| `items` | `items.jar` | Выбрасывание и подбор предметов как в ванили (в Minestom из коробки нет): Q / Ctrl+Q, курсором за окно, из креативного меню; подбор с задержкой 2 с, частичный при неполном месте, наблюдатель не подбирает; слияние и исчезновение (`despawn-seconds`). Лежащие предметы — обычные `ItemEntity` (физику в вакууме даёт `gravity`); при выключении/перезагрузке модуля выброшенные им предметы убираются. Живая проверка — `tools/e2e/items.js` |
| `gravzones` | `gravzones.jar` | Зоны гравитации, выделяемые топориком (`/hozone axe`): 0.1…10 — множитель гравитации (прыжок выше/ниже), 11…13 — вакуумный выброс вверх и невесомость модуля gravity. Команда `/hozone` (OP), зоны — `module/gravzones/zones.json`. `depends: [gravity]`. Живая проверка — `tools/e2e/gravzones.js` |

Ресурспак собирает и раздаёт модуль **`respack`** (автор — Takuyamo, уже стоит на сервере, от него зависит и `ships`).
Его исходников здесь нет: `respack-api/` — только интерфейс `ResourcePackApi`, снятый с `module/respack.jar`, чтобы
`coreshaders` компилировался; в выкладку он не идёт (класс берётся из настоящего `respack.jar`). Если в respack
поменяют интерфейс — обновить `respack-api/src/main/java/ink/hoka/odyssey/respack/ResourcePackApi.java`.

## Сборка

Нужны JDK 25 и git (Gradle — через `./gradlew`).

```bash
./gradlew build
```

→ `coreshaders/build/libs/coreshaders.jar` (+ тесты).

Ядро подключается как *included build*: при первой сборке `settings.gradle.kts` сам клонирует
`SakuraMesd/HokaOdyssey` (ветка `main`) в `.hoka-core/` (в git не идёт), и модули компилируются против его `:api`.

- обновить ядро до свежего `main`: `./gradlew build -Phoka.core.update=true` (или удалить `.hoka-core/`);
- свой клон ядра: `-Phoka.core.dir=/путь/к/HokaOdyssey` или переменная `HOKA_CORE_DIR`;
- другая ветка/тег: `-Phoka.core.ref=<ref>`.

Локальный сервер с модулями: `./gradlew runServer` (папка `run/`, порт 25565, HTTP пака — 25574).
После правок: `./gradlew deployModules`, в консоли сервера `homodule reload coreshaders`. Для `runServer` положите `respack.jar` (Takuyamo) в `run/module/`.

## Выкладка на сервер

1. На сервере должен стоять модуль `respack` (Takuyamo) — он раздаёт пак (порт `25574`, `module/respack/config.yml`).
2. Положить `coreshaders.jar` в `module/` и в консоли: `homodule load coreshaders.jar`
   (обновление — заменить jar и `homodule reload coreshaders`).
3. `coreshaders` при включении отдаёт respack шейдер, модели и панорамы (`put`) и просит пересобрать пак;
   respack рассылает его игрокам.

## coreshaders

Всё, что было в плагине, кроме Nexo и прав Bukkit:

| Команда (только OP) | |
|---|---|
| `/hocs give [игрок] [cube\|plane] [картинка] [цвет]` | шейдерный жезл |
| `/hocs color\|image\|shape\|remove\|info` | эффект под прицелом |
| `/hocs list`, `/hocs removeall <радиус\|all>` | список / убрать |
| `/hocs cmd add <player\|console> <команда> [group]`, `cmd list\|remove\|clear\|perm <op\|off>\|msg` | команды на эффекте (порталы) |
| `/hocs trigger <enter\|click\|both\|off> [group]`, `/hocs cooldown <с> [group]`, `/hocs rim <on\|off> [group]` | |
| `/hocs upload <имя> <https-ссылка>`, `/hocs import <имя>`, `/hocs delete-image <имя>` | свои картинки и GIF → пак пересобирается и рассылается |
| `/hocs reload` | перечитать `config.yml` |

Жезл: ПКМ по блоку — поставить, ЛКМ — убрать, Shift+ПКМ — картинка, Shift+ЛКМ — форма.

Что изменилось при переносе:

- **Эффекты хранятся в `module/coreshaders/effects/<карта>.json`** — Minestom не сохраняет сущности вместе с миром.
  `ItemDisplay` и `Interaction` (хитбокс для кликов) создаются при загрузке чанка и убираются при выгрузке/выключении
  модуля. Эффекты ставятся только на картах из `maps/` (у карты есть имя — есть куда сохранить).
- Право на портал: вместо прав Bukkit — `/hocs cmd perm op` (только операторы) или `off` (все).
- Сообщения — в `config.yml`, цвета через `&` (MiniMessage в сервере нет).
- Встроенный пак (шейдер, модели, 12 панорам) лежит в jar (`src/main/resources/pack/`); при включении и после
  `/hocs import|upload|delete-image` модуль читает его и свои картинки (`module/coreshaders/pack/`) в async и отдаёт
  в respack через `put`, затем `rebuild`. Исходники для `/hocs import` — `module/coreshaders/images/`.
- Шейдер и номера картинок не менялись — старые свои картинки (`kinds`) совместимы.

Инструменты (`coreshaders/tools/`): `panoramas.py` (генерация панорам и файлов пака), `glsl_check.py`, `preview.py` —
те же, что в плагине, пути поправлены на `src/main/resources/pack/`.

## spacesky

- Небо — шейдер неба (`sky.vsh`/`sky.fsh`): в 1.21.11 у неба обычного мира нет текстуры, это цвет из шейдера `sky`,
  поэтому всё небо рисуется в нём. Край диска неба опущен почти до надира — в пустоте снизу тоже небо.
- **Профили неба** (`profiles` в `config.yml`, до 16): у каждого профиля свой тип мира `hoka:<профиль>` и свой вид неба.
  Профиль по умолчанию — `space` (тип мира `hoka:space`, космос как раньше). Вид профиля:
  - `galaxy` — космос: фон, звёзды (плотность, яркость, оттенок), Млечный путь вкл/выкл, цвет туманностей, свои
    области (`zones.<имя>.profile`), свои чёрные дыры (дыры gravity по карте → профиль карты);
  - `planet` — атмосфера: цвета зенита и горизонта днём и ночью, закат (свечение у солнца), своё солнце (цвет,
    угловой размер; ванильное прячется), облака вкл/выкл и их цвет, туман днём/ночью и дымка (`haze`), ночью — звёзды
    профиля (вращаются вместе с солнцем, у горизонта гаснут), соседняя планета/луна (`moon`: размер, цвет, направление;
    фаза — от положения солнца). Сутки — 24000 тиков, как в ванили (свет неба днём/ночью — как у ванильных суток).
  Примеры в `config.yml`: `galaxy1` (фиолетовый фон, звёзды гуще, своя туманность `galaxy1_glow`), `andromeda` (тёплые звёзды гуще, без
  Млечного пути, голубая туманность), `mars` (рыжая атмосфера, голубоватый закат, маленькое солнце, без облаков),
  `ocean` (бирюзовое небо, большое тёплое солнце, облака, вторая планета на небе).
  - **Добавить галактику/планету**: раздел `profiles` в `config.yml` (`<имя>: {type: galaxy|planet, …}`, поля — в
    комментариях там же), **перезапуск сервера** (тип мира регистрируется только до старта; до перезапуска
    `/hosky profiles` и `/hosky reload` пишут «появится после перезапуска»), затем `/hosky world <карта> <профиль>`
    (карта перегрузится — небо её мира станет профилем). Цвета существующих профилей меняет `/hosky reload`, кроме
    облаков: `clouds`, `cloud-color` и вид (`type`) — в самом типе мира, только после перезапуска (`/hosky reload`
    об этом пишет). Цвет `nebula` профиля берут только его области-туманности без своего `color`.
  - `/hosky profiles` — профили (вид, номер, метка, карты); `/hosky world` — карты и их тип мира;
    `/hosky world <карта> <профиль|off>` — записать `dimension: "hoka:<профиль>"` в `maps/<карта>/map.yml` или убрать его
    (`on` = `space`; `off` убирает только тип мира профиля, чужой не трогает; файл пишется в async, остальные ключи
    сохраняются; подсказки карт — из кэша, он обновляется в async раз в 10 с). Применится при следующей загрузке
    карты; читает ключ ядро — нужен патч `docs/core-dimension.md`. Основная карта `world` грузится до модулей — для неё
    пока не сработает.
- **Как шейдер узнаёт профиль — МЕТКА.** Небо и туман мира профиля №i — служебный цвет `(0, 24, i)`, туман под водой —
  `(0, 24, 16 + i)` (тип мира и его Timeline: таймлайн клиент применяет поверх биома). Красного в метке нет: у всех
  ванильных цветов тумана и неба красный ≥ 12% зелёного (проверено по данным `client.jar` 1.21.11 — биомы, сутки,
  закат, дождь/гроза, смешение тумана с небом, вода, лава, снег, Незер, Энд, ~1,5 млн сочетаний —
  `spacesky/tools/marks_check.py`), так что метку с
  ванильным цветом не спутать. Номер — отношение синего к зелёному: его не меняют ни затемнение у дна мира и ночное
  зрение (умножение на число), ни затемнение экрана (зелёный и синий умножаются одинаково). Прежняя метка `#020205`
  совпадала с ванильным туманом под водой на границе болота и океана — заменена. Метка — служебный цвет:
  `fog.glsl` в мирах профилей подставляет настоящий цвет тумана профиля (у планеты — по времени суток, со своей
  дымкой; под водой — `water-fog`), затемнённый во столько же раз, во сколько клиент затемнил метку (слепота, тьма,
  у дна мира, босс; при слепоте/тьме начало тумана подменено — у планеты ночной цвет и дальности эффекта).
  `terrain.fsh` (ванильный + одна строка) проявляет новые чанки из того же цвета, а не из метки. **Без ресурспака**
  небо и туман мира профиля тёмно-зелёные.
- **Время суток планеты**: таймлайн планеты ведёт `fog_start_distance` от 30000 до 31000 за сутки (туман окружения
  с такого расстояния не виден), под водой — `water_fog_start_distance` от −8 до −9; клиент передаёт их числами с
  плавающей точкой без округления — шейдер получает точную фазу (направление солнца, день/ночь).
- `sky.vsh` по метке тумана (`FogColor`, во всех проходах неба; под водой — метка воды) или неба (`ColorModulator`
  верхнего диска) находит номер профиля, берёт его параметры из `spacesky:profiles.glsl` (константные массивы — индекс
  один на кадр, на 18 вершинах) и отдаёт во фрагментный шейдер `flat`: там нет ни разбора метки, ни массивов, ветка
  «галактика/планета» одна на кадр (без планет в профилях её нет вовсе; при звёздах галактик по умолчанию они
  считаются константами, как раньше).
- **Общий план галактики всегда** (фон, редкие звёзды) — почти бесплатно. **Млечный путь, туманности, звёздные
  скопления — только в областях** (`zones`, команда `/hosky`): `sky.vsh` по позиции камеры (`CameraBlockPos`) считает,
  насколько игрок внутри области, и плавно проявляет картинку у края. Области модуль пишет в шейдер файлом
  `spacesky:zones.glsl` (до 32); область с `profile` видна только в этом профиле, без него — во всех галактиках;
  туманность без `color` — цвета `nebula` профиля; при `milky-way: false` области Млечного пути профиля не видны.
- Скорость (кадр 1280×720, программный рендер llvmpipe, стенд `sky.fsh` на весь кадр): ваниль 0,5 мс, первая версия
  18,3 мс; сейчас вне областей без дыр — 2,0–2,3 мс, как до профилей (в пределах шума, и в режиме `false`); внутри
  всех трёх видов областей ~6 мс; небо планеты 2,5–3,5 мс (ночь со звёздами и закат дороже полудня); 16 дыр чужих
  профилей отсекаются одним сравнением (+0,3 мс). `fog.glsl` добавляет в туман всех шейдеров мира проверку метки
  (несколько операций, у ванильных цветов — выход после первого сравнения).
- `/hosky` — список областей и дыр (и где ты); `/hosky add <имя> <milky_way|nebula|stars> <радиус> [#цвет] [профиль]` —
  область с центром там, где стоишь; `/hosky remove <имя>`; `/hosky reload`. Изменение пересобирает пак (у игроков
  пара секунд перезагрузки). `add|remove` пишут в async только раздел `zones` (остальной `config.yml` и его
  комментарии целы).
- **Регистрация типов миров** (`SpaceDimension`): как overworld (y −64…320, небесный свет, без потолка, skybox
  OVERWORLD, infiniburn, звуки), небо и туман — метка, закатный веер — альфа 0, ванильные звёзды — яркость 0; у
  галактики облаков нет и таймлайн без периода (свет неба всегда дневной), у планеты — таймлайн суток. Регистрируется
  в `onLoad` — только до старта сервера (потом реестры Minestom заморожены: при горячей загрузке — WARN «нужен
  перезапуск»); при перезагрузке модуля уже зарегистрированные не трогаются — номер берётся из их метки (порядок
  профилей в `config.yml` можно менять), новый профиль получает свободный номер после перезапуска.
- **Режим** `everywhere` в `config.yml` (модуль пишет `spacesky:mode.glsl`):
  - `true` (по умолчанию, как было) — небо во всех мирах с обычным небом: миры без метки (в том числе все карты на
    ядре без патча) — профиль `space`, как раньше; миры профилей — свой профиль. В пак добавляется `everywhere/`:
    `stars.fsh` — ванильные звёзды выключены, `position_color.vsh` — убран закатный веер; туман дальности миров без
    метки уходит в фон `space` (вода, лава, слепота — как в ванили); солнце, луна, облака — прозрачные текстуры `hide/*`
    (`hide-sun|moon|clouds`, во всех мирах — и у планет: облака планет в этом режиме видны только при `hide-clouds: false`).
  - `false` — небо профилей только в мирах профилей; в остальных мирах — ванильное небо, туман, облака, солнце
    (проверено в клиенте). Облака, звёзды, веер миров профилей выключает сам тип мира; ванильные солнце и луну —
    `position_tex.vsh` (pipeline celestial, квад `(±1, 0, ±1)` при перспективной проекции, масштаб модель-вида 30 —
    солнце, 20 — луна; у галактик — по `hide-sun|moon`, у планет — всегда) при метке в `FogColor`.
  - Погоду в мирах профилей модуль держит ясной (раз в секунду): дождь перекрашивает небо и туман — метки бы не было.
    BossBar с затемнением экрана в мирах профилей не использовать.
- **Чёрные дыры** — из модуля gravity (`softdepends: [gravity]`, сервис `BlackHoles`: список дыр с картой и подписка
  на изменения; всё обращение к классам gravity — в `GravityHoles`, без gravity дыр просто нет). Модуль пишет
  `spacesky:holes.glsl` (`SS_HOLES`, `SS_HOLE_POS = (x, y, z, горизонт)`, `SS_HOLE_DISK = (нормаль диска, внешний
  радиус в горизонтах)`, `SS_HOLE_LOOK = (вращение, яркость, температура, зерно из хэша имени)`, `SS_HOLE_PROF` —
  номер профиля, `SS_HOLE_IPOS`/`SS_HOLE_FRAC` — центр целой и дробной частью: шейдер вычитает целые из
  `CameraBlockPos` в int, поэтому дыра не дрожит и за миллионы блоков от 0; запасной в jar — `SS_HOLES 0`). Дыра видна в небе профиля **своей карты** (`dimension` в её
  `map.yml`); карты без профиля — профиль `space` (при `everywhere: true` — значит во всех мирах без профиля, как
  раньше). `sky.fsh`: тень = горизонт (внутри горизонта всё чёрное), фотонное кольцо, аккреционный диск с
  доплеровской асимметрией и «изображением» дальней части над/под шаром, линза звёзд вокруг — без raymarch. Вид дыры
  — необязательные поля в gravity: `disk-tilt`, `disk-yaw`, `disk-size` (0 — без диска), `disk-spin`,
  `disk-brightness`, `disk-temp`. Дыра — картинка в небе (не сущность), живёт сколько угодно. После
  `/hograv hole add|remove|reload` и смены неба карты пак пересобирается сам (через 2 с, только если `holes.glsl`
  изменился; пока пак собирается, проверка ждёт конца сборки; config.yml при этом не перечитывается). До 16 дыр
  (отбор развёрнут макросами на константных индексах), на пикселе рисуются все отобранные.
- Проверка шейдеров: все сочетания режима, `hide-*`, профилей (только space / примеры / 16), областей и дыр —
  glslangValidator (`sky`, `position_tex`, `terrain`, `fog.glsl` во всех ванильных шейдерах, где он есть).
- У Энда и Незера своё небо — их модуль не трогает ни в каком режиме. Выключить: `homodule unload spacesky`
  (типы миров профилей останутся зарегистрированными до перезапуска сервера).

## oxygen

- Шкала воздуха — ванильные пузырьки: метаданные «air supply» игрока (`EntityMeta#setAirTicks`, 0…300). Minestom
  воздух сам не считает: модуль каждый тик убывает/восстанавливает запас и шлёт его клиенту (пока воздух тратится —
  каждый тик, с полным запасом — ничего). Темп по умолчанию ванильный: воздуха на 15 с, восстановление за 3,75 с,
  потом урон `drown` 4 (два сердца) раз в секунду — всё в `config.yml`.
- Скафандр — `GLASS` с компонентом `equippable` (слот головы) и меткой `hoka_oxygen_suit` в `custom_data`; обычное
  стекло на голове не считается. Надеть: ПКМ в воздух (обмен со шлемом делает сам Minestom), ПКМ по блоку (модуль
  не даёт поставить его блоком и надевает), положить в слот шлема или Shift-клик в инвентаре.
- `/hosuit [ник]` (OP) — выдать скафандр; в action bar без скафандра — предупреждение раз в секунду (только
  выживание/приключение). Креатив и наблюдатель урона не получают; пузырьки в креативе — `creative-bubbles`.
- Выключение модуля возвращает всем полный запас воздуха. Ядро ставит при входе креатив — урон виден только в
  выживании (команды смены режима в ядре пока нет).

## gravity

- **Игрок в вакууме** (карты из `maps`): атрибут гравитации ×0, прыжок с земли и урон от падения ×0. Тяга —
  «пустым» пакетом взрыва с отдачей (прибавляется к скорости клиента, не затирает её — плавно при любом пинге).
  Пробел/Shift — вверх/вниз до `vertical.max-speed`, WASD — добавочный разгон, отпустил — инерция.
- **Дрейф без клавиш**: если не нажато ничего (WASD, пробел, Shift, бег), игрока сносит к ближайшей чёрной дыре в
  пределах её `reach` — притяжение × `player-pull-scale`, не быстрее `player-max-drift-speed`; дыр рядом нет — по
  `drift.direction` со скоростью `drift.speed` (0 — выключить). Сервер ведёт модель скорости клиента (без клавиш
  клиент гасит горизонталь ×0,91 и вертикаль ×0,98 за тик) и толкает ровно на разницу — разгон плавный, предел
  соблюдается по настоящему сдвигу за тик. Нажал клавишу — дрейф сразу отключается. На земле (стоит на блоке) не сносит.
  У горизонта: `player-on-horizon: none` — тормозит заранее и держит у горизонта, внутрь не тянет; `spawn` — переносит
  на точку появления карты (из `maps/<карта>/map.yml`).
- **Чёрные дыры** — `black-holes: <карта>: <имя>: {x, y, z, horizon, reach, pull, max-speed}`. Притяжение
  `pull × (horizon / d) ^ falloff`, но на всём `reach` не меньше `hole-physics.min-pull` — в пределах радиуса всё
  медленно сносит к дыре. По умолчанию одна дыра `abyss` на galaxy1 в 600 блоках к северу от спавна (0.5 65 −600,
  горизонт 6, радиус 1500). Команды (OP): `/hograv hole list [карта]`, `/hograv hole add <имя> [горизонт] [радиус]` —
  дыра там, где стоишь (тяга и предел — из `hole-defaults`), `/hograv hole remove <имя> [карта]`. Команды переписывают
  только раздел `black-holes` в config.yml (имена — в кавычках), остальные комментарии целы; правки идут по очереди и
  применяются к содержимому файла в момент записи, так что две команды подряд и правки руками не теряются.
  Вид дыры в небе (рисует spacesky, на физику не влияет) — необязательные `disk-tilt` (наклон диска, °), `disk-yaw`
  (куда опущен край, °), `disk-size` (радиус диска в горизонтах, 0 — без диска), `disk-spin`, `disk-brightness`,
  `disk-temp`; команды их сохраняют (пишутся только отличные от умолчания), перенос дыры `hole add` оставляет прежний вид.
  Сервис `BlackHoles` (`services().get(BlackHoles.class)`) — дыры всех карт и подписка на перечитывание конфига.
- **Предметы** (обычные `ItemEntity`, их создаёт модуль items): на картах с вакуумом сразу при появлении — без
  гравитации (`setNoGravity`), сервер их скорость не гасит (аэродинамика: горизонтальное сопротивление 1), а модуль
  раз в `items.update-ticks` тиков сам применяет слабое затухание (`items.drag-half-life`) и притяжение дыр до её
  `max-speed`. Мелкие изменения копятся, чтобы не слать пакет скорости каждый тик, но позиция летящего предмета уходит
  игрокам каждые `update-ticks` тиков (обычно раз в секунду — клиент гасит скорость сам и предмет скакал бы рывками).
  Minestom не двигает сущность в незагруженный чанк: если предмет долетел до края загруженного мира, а его тянет
  дыра — он считается упавшим в неё и тихо исчезает; без дыры — скорость гасится, предмет висит у края. За горизонтом предмет исчезает
  (частицы reverse_portal и звук телепорта эндермена, `items.absorb-effect`). `hograv off`, `items.enabled: false` и
  выгрузка модуля возвращают предметам гравитацию и прежнюю аэродинамику.
- **Зоны для предметов** — другой модуль (gravzones) ставит через `VacuumService.zoneProvider(...)` источник зон;
  gravity раз на карту за проход берёт у него `ZoneLookup` и спрашивает режим точки каждого предмета (без аллокаций на
  предмет). `NORMAL` (зона 0.1…10) — предмет не захватывается, а захваченный (залетел из вакуума) отпускается: снова
  с гравитацией и прежним затуханием, дыры его **не тянут и не поглощают**; гравитацию зоны ставит владелец зон.
  `MAP`/`VACUUM` — как решает карта (вакуумная зона на обычной карте предметы не трогает). Источник снимается
  `removeZoneProvider` (gravzones — в onDisable) и сбрасывается при выключении gravity.

## items

- Выброс разбирает сам Minestom (Q, Ctrl+Q, клик за окном — слот −999, Q над слотом, креативное меню — слот −1, закрытие
  окна с предметом на курсоре): везде вызывается `Player.dropItem` → `ItemDropEvent`, и Minestom сам убирает предмет из
  инвентаря. Модуль на это событие создаёт `ItemEntity`: на 0,3 ниже глаз, скорость по взгляду как в ванили
  (`throw-speed` 0,3 блока/тик, +0,1 вверх, небольшой разброс).
- Подбор: `PickupItemEvent` (его зовёт сам Minestom у игрока рядом с предметом) — модуль кладёт предмет в инвентарь;
  если влезло не всё — событие отменяется, игрок получает сколько влезло, остаток лежит. Анимация и звук — штатный
  `CollectItemPacket`. Задержка подбора общая (`pickup-delay-seconds`, как в ванили). Наблюдатель не подбирает.
- Слияние — штатное у `ItemEntity` (`merge`, `merge-range`), исчезновение — `despawn-seconds` (0 — никогда).
- **При выключении/перезагрузке модуля выброшенные через него предметы исчезают** (модуль убирает свои сущности).
- Команд нет. Настройки — `module/items/config.yml`, перечитать — `homodule reload items`.

## gravzones

| Команда (только OP) | |
|---|---|
| `/hozone axe` | топорик выделения: ЛКМ по блоку — точка 1, ПКМ — точка 2 (блок не ломается/не ставится, в action bar — координаты и объём) |
| `/hozone pos1\|pos2` | точка там, где стоишь (для углов в воздухе, как `//pos1` в WorldEdit) |
| `/hozone create <имя> <сила>`, `set <имя> <сила>`, `remove <имя>`, `info <имя>` | зона из выделения на текущей карте |
| `/hozone list`, `/hozone reload` | зоны карты и в какой ты сейчас; перечитать `config.yml` |

- **Сила 0.1…10** — модификатор `hoka:gravzone` (ADD_MULTIPLIED_TOTAL) на `gravity` (0.08 × g), `jump_strength`
  (× g^0.1 при g &lt; 1, × g^0.3 при g &gt; 1 — прыжок плавный: g = 0.1 → 4.7 бл. и 3.5 с в воздухе, g = 10 → 0.9 бл. и 0.2 с),
  `safe_fall_distance` (растёт вместе с высотой прыжка), `fall_damage_multiplier` (config). Выброшенные предметы — гравитация
  `Aerodynamics` × g (сразу при появлении и раз в 5 тиков). На вакуумной карте такая зона главнее карты: gravzones
  просит gravity «здесь не вакуум» — игроку через `override`, предметам через `ZoneProvider` (режим `NORMAL`): предмет
  в зоне падает с гравитацией зоны, чёрная дыра его не тянет и не поглощает; вылетел из зоны в вакуум — снова
  невесомость и притяжение дыр. `items: false` — зоны предметы не трогают (как решает карта).
- **Сила 11…13** — gravity включает игроку вакуум (`VacuumService`), через 5 тиков gravzones толкает его вверх
  (12/18/24 бл/с, config), дальше обычная невесомость; держится ещё `linger-seconds` после выхода. Прыжок с земли в зоне — снова выброс.
- Пересекаются — действует **меньшая по объёму**, при равном — созданная позже.
- Рамки частицами — только у игрока с топориком, раз в 10 тиков, не больше 240 частиц, рёбра ближе 40 блоков.

## Проверка

- `./gradlew build` — юнит-тесты (хранение эффектов, файлы пака, геометрия, GIF, панорамы, скачивание, луч).
- `RESPACK_JAR=/путь/к/respack.jar tools/e2e/run.sh` — живая проверка ботом (mineflayer) на настоящем ядре с модулем
  respack с сервера: пак с файлами coreshaders, жезл, куб и плоскость, `/hocs info`, команда на эффекте и вход в него,
  сохранение, `homodule reload` coreshaders и respack без дублей, `/hocs import` → картинка в новом паке, ЛКМ-удаление,
  `/hocs` недоступна не-OP. Ядро для теста запускается с офлайн-входом (копия `OdysseyServer` с `Auth.Offline`,
  только в `tools/e2e/.harness/`).
- gravity: `tools/e2e/gravity.js` (тяга, инерция, on/off, reload) и `tools/e2e/blackholes.js` (дрейф к дыре и предел
  скорости, управление клавишами поверх дрейфа, остановка у горизонта, предметы: без гравитации, к дыре, поглощение,
  инерция без дыры, `hole add/remove/list`, off/reload/unload). `tools/e2e/zonefix.js` — предметы в зонах gravzones на
  вакуумной карте (бросок Q в зоне 1 — падает и лежит, вне зоны и в зоне 12 — летит в дыру, вылет из зоны в вакуум,
  reload gravzones/gravity). Предметы для проверки создаёт тестовый модуль
  `tools/e2e/itemspawner` (`/hoitemtest`, собирается отдельно `javac` + `jar`, на сервер не выкладывать). Как запускать —
  в шапке скриптов.
- `SRV=/путь/к/серверу PORT=… node tools/e2e/items.js` — модуль items двумя ботами (`ibot1`, `ibot2` в ops.json, в
  `module/items/config.yml` `despawn-seconds: 12`): Q/Ctrl+Q, курсор за окно, креатив, подбор, задержка, полный и
  неполный инвентарь, слияние, исчезновение, `homodule reload items`. Для проверки наблюдателя нужен тестовый модуль
  с командой `/hotgm <режим>` (без него шаг пропускается).
