# core-mechanics

Система Amazake (Paper 1.21.11, регионы как в Folia; собирается под Java 21). **Рэгдоллы игроков на физдвижке
[Jolt](https://github.com/jrouwe/JoltPhysics)** (через [jolt-jni](https://github.com/stephengold/jolt-jni) 6.1.1) и
**куклы-статуи** с позами, анимациями и экспортом в ванильный `/summon`. Перенесено из плагина MagicRuruka
(`/mrr rd …`, классы `RagdollManager`, `DollStudio`, `DollPoses`, `SkinCubes`) и физики PasToSmith (`physblock/jolt`)
— только то, что нужно куклам (без физблоков).

- **Смерть** — на месте смерти падает «тряпичная кукла» игрока, живёт 90 с (`ragdoll.death-lifetime-seconds`).
- **`/rd <ник>`** — кукла этого игрока перед админом (лицом к нему, с подбросом), живёт 5 мин. Игрок не в сети —
  скин ищется у Mojang (асинхронно), не нашёлся — Стив.
- **Руки**: Shift+ПКМ по любой части куклы — взять за неё и таскать (кукла волочится; держать могут несколько
  игроков сразу — за одну часть точки усредняются, за разные — куклу растягивают), ПКМ — отпустить, ЛКМ — бросить.
  Взятая кукла живёт не меньше 5 мин.
- **Скин**: голова — настоящая голова игрока; туловище, руки и ноги — 10 растянутых голов с его скином через
  [MineSkin](https://mineskin.org) (кусок 4×4×4 пикселя скина = своя «голова»), а пока они не готовы — блоки средних
  цветов скина. Подписи MineSkin кэшируются (`skins-cache.yml`), живые куклы переодеваются сами.
- **Статуи**: кукла со скином стоит в позе (22 позы), играет анимацию (12: танец, ходьба, отжимания, зомби…) или свой
  мультик из записанных кадров. «Кукловод» (палочка) крутит части по 15°. Удар (ЛКМ) или взрыв рядом — статуя
  обмякает настоящим рэгдоллом и через 10 с встаёт. Экспорт в `/summon` (командный блок / функция, работает без
  системы).

Право на всё — `coremechanics.admin` (таскать/бросать кукол может любой игрок — как в оригинале).

## Команды

`/rd` (псевдонимы `/ragdoll`, `/coremechanics`), полное автодополнение (ники, позы, анимации, подкоманды).

| Команда | Что делает |
|---|---|
| `/rd <ник>` | рэгдолл игрока перед тобой (5 мин) |
| `/rd clear` | убрать все рэгдоллы (статуи остаются) |
| `/rd info` | состояние: физика, кукол, статуй, дисплеев, MineSkin, позиции кукол, время шага (можно из консоли) |
| `/rd statue <ник> [поза\|анимация]` | поставить статую в 2,5 блока перед собой |
| `/rd pose <поза>` | поза статуи (снимает анимацию) |
| `/rd anim <анимация\|stop>` | анимация статуи |
| `/rd frame add\|play\|stop\|clear\|speed <тики>` | свой мультик: кадр = текущая поза; ≥ 2 кадров для play |
| `/rd tool` | выдать «Кукловода» |
| `/rd topple` / `/rd up` | уронить статую рэгдоллом / поднять сразу |
| `/rd turn` | развернуть статую лицом к себе |
| `/rd move` | перенести статую к себе |
| `/rd remove` / `/rd removeall` | убрать статую / все |
| `/rd list` / `/rd poses` | список статуй / поз и анимаций |
| `/rd summon` | статуя как `/summon`: командный блок в инвентарь, файл в `statue_summon/`, кнопка «скопировать» |
| `rd summon` (консоль) | команды `/summon` всех статуй в файлы `statue_summon/<ник>_<id>.mcfunction` и `<ник>_point.mcfunction` |

Статуя для команды — выбранная кукловодом, под прицелом (до 12 блоков) или ближайшая в 8 блоках.

**Кукловод** (палочка с подсветкой): ПКМ по части статуи — выбрать (часть светится; ПКМ мимо — снять выбор),
ЛКМ +15°, Shift+ЛКМ −15°, Shift+ПКМ — сменить ось (X вперёд/назад, Y кручение, Z в сторону, у тела ещё высота таза),
F — записать кадр, Shift+F — проиграть/остановить. Правка части во время анимации «замораживает» текущий кадр в позу.

Позы: `stand tpose wave victory zombie point dab sit sitground lie facedown dead kneel salute think facepalm crossarms
shrug bow pushup run fly`. Анимации: `wave dance walk zombie pushup jacks clap headbang floss fly bow sitwave`.

## Настройки (`systems/core-mechanics/config.yml`)

Комментарии — в самом файле. После правки — `amazake system reload core-mechanics`; раздел `physics` применяется
после `amazake system disable` + `enable`.

| Ключ | По умолчанию | |
|---|---|---|
| `ragdoll.on-death` | `true` | кукла при смерти |
| `ragdoll.death-lifetime-seconds` / `command-lifetime-seconds` | 90 / 300 | время жизни |
| `ragdoll.max-dolls` | 12 | больше кукол сразу нет: самые старые исчезают |
| `ragdoll.grab-reach` | 6.0 | досягаемость Shift+ПКМ, блоков |
| `ragdoll.throw-strength`, `hold-stiffness`, `hold-max-speed` | 14 / 10 / 25 | бросок и «пружина» удержания (как в оригинале) |
| `statues.topple-seconds`, `topple-on-hit`, `topple-on-explosion` | 10 / true / true | статуи |
| `physics.gravity`, `substeps`, `threads`, `max-bodies`, `section-requests-per-tick` | 17 / 3 / 0 (авто) / 4096 / 24 | Jolt |
| `skins.fetch-on-join`, `skins.mojang-lookup` | true / true | заранее качать скин при входе; искать скин офлайн-ника у Mojang |
| `mineskin.key` | `""` | **ключ API MineSkin — только в конфиг сервера, в репозиторий никогда**. Пусто — тело цветными блоками |
| `mineskin.api-url`, `timeout-seconds` | v2/generate, 60 | |
| `libraries.auto-download`, `repositories` | true, repo1 + зеркало Google | откуда качать jar-ы Jolt, если их нет в `.azs` |

Если MineSkin недоступен (нет сети, таймаут, DNS) — в лог одна строка INFO «MineSkin недоступен … следующая
попытка через 10 мин», куклы остаются в цветных блоках, ничего не падает. Неверный ключ — одно предупреждение.

Файлы системы на сервере: `config.yml`, `statues.yml` (статуи; пишет система, раз в 2 с при изменениях и при
выключении, атомарно), `skins-cache.yml` (подписи MineSkin), `statue_summon/` (экспорт), `lib/` (jar-ы Jolt),
`lib/natives/libjoltjni-<отпечаток>.so` (нативка, распаковывается из jar-а).

## Как загружается Jolt

```
core-mechanics.azs
 ├─ core/amazake/systems/coremechanics/**   код системы (Bukkit): команды, события, дисплеи, статуи, скины,
 │                                          мешер секций, поток физики. Про Jolt не знает — только интерфейсы
 │                                          physics.PhysicsHost / PhysicsWorld / RagdollBody
 ├─ host/**.class.bin                       код, который зовёт Jolt (JoltHost, JoltWorld, JoltRagdoll, самотест)
 ├─ libs.txt                                jar-ы jolt-jni: имя, размер, sha256, путь в Maven Central
 └─ bundled-lib/*.jar                       сами jar-ы (~2,7 МБ; сборка с -PbundleJolt=false — без них)

ClassLoader-ы:  сервер ─┬─ SystemClassLoader(core-mechanics.azs)        новый на каждое включение
                        │     └─ HostLoader (host/**.class.bin)           новый на каждое включение;
                        │           классы com.github.stephengold.* берёт ↓
                        └─ платформенный JDK ─ «core-mechanics/jolt» (lib/*.jar)   ОДИН на всю JVM
                                                 └─ libjoltjni.so привязана к нему
```

- **Почему так.** JVM разрешает привязать нативную библиотеку только к **одному** загрузчику классов. Если бы классы
  Jolt грузил загрузчик `.azs`, второе включение системы упало бы с «already loaded in another classloader» (так было
  в плагине: «перезапусти сервер»). Поэтому, как в core-python, jar-ы jolt-jni грузит один `URLClassLoader` на всю
  жизнь JVM: он лежит в `System.getProperties()` под ключом `core-mechanics.jolt.loader` (единственная общая карта
  JVM, видимая из любого загрузчика; значение — класс JDK, поэтому он не держит классы системы). `System.load`
  вызывает класс из этого же загрузчика — `com.github.stephengold.joltjni.NativeLibraryLoader.loadLibrary(путь)`,
  поэтому нативка привязывается именно к нему. Флаг `core-mechanics.jolt.native` — «нативка загружена»,
  `core-mechanics.jolt.factory` — «фабрика типов Jolt создана» (тоже раз на JVM).
- **Порядок при включении** (в асинхронном потоке, тик не ждёт): проверить `lib/*.jar` по sha256 из `libs.txt` →
  нет/битые — распаковать из `bundled-lib/` (или скачать из `libraries.repositories`), запись через `.part` и
  переименование после сверки → общий загрузчик → нативка в `lib/natives/` → `System.load` (раз на JVM) → новый
  `HostLoader` → `JoltHost.start()`: слои, аллокатор, пул потоков Jolt, **самотест** (куб на пол-бокс и на пол-меш
  секции: «box-floor y=0.494, mesh-floor y=1.494»). Самотест провален или нативки нет — физика выключена (в лог
  SEVERE с причиной), а статуи работают.
- **Выключение**: в потоке физики уничтожаются все тела, физ-системы миров, пул потоков и аллокатор Jolt;
  `HostLoader` и загрузчик `.azs` после этого никем не держатся. Общий загрузчик и нативка остаются до рестарта JVM
  (это и позволяет включать снова).
- **Решение: jar-ы вшиты в `.azs`** (2,7 МБ — `.azs` ≈ 2,8 МБ, меньше лимита чтения файлов панели ~5 МБ, так что
  sha256 после заливки сверяется обычным способом). Сеть на проде не нужна. `-PbundleJolt=false` собирает `.azs`
  ≈ 180 КБ — тогда jar-ы скачиваются из Maven Central (или их кладут в `lib/` руками: `build/jolt-lib/*.jar`).
- **Смена версии jolt-jni** (новый `libs.txt`) требует **рестарта сервера**: старая нативка уже привязана к старому
  загрузчику; система в этом случае не стартует физику и пишет «нужен рестарт сервера».
- Нативка есть только для **Linux x86-64** (прод и тестовый сервер). На другой ОС/архитектуре физика выключится с
  понятной ошибкой.

## Потоки

Amazake тикает мир регионами (как Folia): сущность или блок можно трогать только в потоке региона, которому они
принадлежат. Устройство:

```
поток игрока ── события (смерть, Shift+ПКМ, ЛКМ, F), команды ──┐ очередь команд
поток региона ── снимки секций мира, отрисовка дисплеев, статуи │   (ConcurrentLinkedQueue)
                      ▲ задачи регионов          │ снимок       ▼
                      │ (поза → дисплеи)         └──────► поток физики core-mechanics-physics (20 Гц)
                      └──────────────────────────────────  все вызовы Jolt — только здесь
```

- **Поток физики** — свой `ScheduledExecutorService` (1 поток, 50 мс). Все вызовы Jolt — только из него, поэтому
  Jolt ничем не синхронизируется (внутри шага Jolt сам раскидывает работу на свой пул `physics.threads`). Другие
  потоки дают ему задания очередью (создать/убрать куклу, бросок, «держат», блок изменился, пришёл снимок секции).
  Тики сервера его не ждут, он не ждёт их.
- **Мир для коллизий** читается **только в потоке региона**: физика просит секцию 16×16×16 (плюс слой сверху и
  снизу) — `getRegionScheduler().execute(мир, cx, cz, …)` снимает формы коллизии блоков (кэш на состояние блока) и
  отдаёт неизменяемый снимок обратно в поток физики; меш строится там. Соседние чанки по X/Z не читаются (могут быть
  в чужом регионе) — на границе чанка грани строятся всегда (лишние внутренние грани безвредны). Незагруженный
  чанк не грузится. Пока у секции нет меша, кукла рядом придерживается кинематикой. Изменения мира: события
  (ломание/постановка/взрыв/поршни) помечают секцию, плюс сверка по кругу (переснять, сравнить хэш геометрии) —
  ловит WorldEdit и `/setblock`. Не более `section-requests-per-tick` снимков за тик.
- **Взгляд держащего игрока** снимается в его потоке (`context.runForPlayer`, каждый тик) и кладётся в volatile-поле;
  физика тянет часть к точке перед глазами. Игрок вышел/умер/сменил мир — задача перестаёт обновлять взгляд, через
  2 с кукла выпадает из рук.
- **Отрисовка**: после шага поток физики публикует неизменяемую позу и ставит задачу региона якоря куклы (не больше
  одной в очереди на куклу). **Якорь**: все дисплеи куклы стоят в одной точке, поза — только трансформацией
  (смещение части от якоря входит в translation), поэтому каждый тик меняются лишь метаданные сущностей, без
  телепортов. Когда туловище ушло от якоря дальше 8 блоков (бросили, утащили), дисплеи переезжают
  `teleportAsync` в новую точку — **так кукла переходит границы регионов**: сущности сами переходят в регион нового
  якоря, следующие задачи отрисовки ставятся туда. Позиция (`teleportDuration 1`) и трансформация
  (`interpolationDuration 1`) интерполируются клиентом за один тик, рывка нет. Телепорт не удался — кукла убирается
  без хвостов.
- **Статуи**: глобальный таймер каждый тик ставит тик каждой статуи задачей региона её чанка (не больше одной в
  очереди); манекен рисуется там же. Команды и кукловод (поток игрока) меняют только volatile-описание статуи
  (массивы позы — копия при записи), а действия с сущностями (обмякнуть, встать, перенести, убрать) кладут в очередь
  статуи. Взрыв (поток региона взрыва) роняет статуи в их регионах через ту же очередь.
- **Файлы и сеть** — вне тиков: скин (PNG) и Mojang — асинхронный пул; MineSkin — свой поток
  `core-mechanics-mineskin`; `statues.yml` и экспорт `/summon` — асинхронно, атомарно (временный файл + rename).
- **Выключение** (глобальный поток): остановить таймеры статуй, сохранить `statues.yml`, остановить поток физики
  (тела, миры, пул — в нём же; ждём до 5 с), убрать дисплеи. Сегодня Amazake тикает мир в одном потоке, поэтому
  глобальный поток владеет всеми регионами и убирает всё сразу (проверено: 0 дисплеев после disable). Если регион
  чужой — дисплеи несохраняемые (`persistent=false`) и пропадут с выгрузкой чанка, а следующее включение уберёт хвосты
  по метке (`coremechanics_doll` + PDC `coremechanics:doll`) на `EntitiesLoadEvent` и рядом с игроками.

## Сборка и тесты

```bash
cd core-mechanics
cp ../core-mobs/libs/*.jar libs/      # если libs/ пустой (jar API систем)
./gradlew test azs                    # тесты + build/libs/core-mechanics.azs + build/jolt-lib/
```

jolt-jni качается из зеркала Maven Central от Google (repo1 часто отвечает 429 на большие jar-ы).

Юнит-тесты (`src/test`, 45): `libs.txt` и распаковка со сверкой sha256; мешер секций (нормали наружу, отсечение
граней, хэш, снимок секции и его границы, формы коллизии); менеджер секций (запросы, лимит, пересборка только при
изменении, соседи на границе, выгрузка); позы (стоя, статуя, T-поза, углы), выбор части лучом, трансформации
кусков; интерполяция кадров и сглаживание; каталог поз/анимаций; экспорт `/summon`; сохранение статуи туда-обратно;
средние цвета скина и палитра, коробки скина MineSkin; автодополнение `/rd`; настройки (пределы, конфиг = значения
по умолчанию); **настоящий Jolt** (нативка из jar-а на classpath): самотест, повторный `start` (фабрика — раз на
JVM), кукла падает на меш-пол и лежит, импульс подбрасывает, придержанная кукла не падает.

Живой тест — тестовый сервер `/home/user/mc-skilltest` (Amazake 1.21.11, офлайн, без интернета), боты
`/home/user/mc-bot/rd1_ragdoll.js`, `rd2_statue.js`, `rd3_reanchor.js` (выводы — `*.out.txt` рядом).

## Заливка на прод

Новая система (на проде её ещё нет). Только по явному «заливай» владельца (`docs/DEVELOPER_GUIDE.md`, раздел 5).

1. `./gradlew test azs` → `build/libs/core-mechanics.azs` (≈ 2,8 МБ, jar-ы Jolt внутри).
2. Загрузить в `/systems/core-mechanics.azs.new`, сверить sha256 (`files/contents`), переименовать в
   `core-mechanics.azs`.
3. (Необязательно, до включения) записать `/systems/core-mechanics/config.yml` с ключом MineSkin в `mineskin.key`.
   Без этого шага конфиг создастся сам при первом включении (без ключа — тело цветными блоками); ключ можно вписать
   потом и сделать `amazake system reload core-mechanics`.
4. `amazake system enable core-mechanics` (сам допишет её в `systems.yml`).
5. Проверить лог: «распакован из .azs: jolt-jni-…» ×2 (только первый раз), «физика готова — Jolt 6.1.1 … самотест:
   box-floor y=0.49…, mesh-floor y=1.49…», нет `SEVERE`/`Exception` от core-mechanics. В игре — `/rd info`.
6. jar-ы Jolt отдельно заливать **не нужно** (они в `.azs`). Если собран `-PbundleJolt=false`, а у прода нет выхода на
   Maven Central: залить `build/jolt-lib/*.jar` в `/systems/core-mechanics/lib/` до включения.

Обновление: `disable` → заменить `.azs` (через `.new`) → `enable`. Если в новой сборке сменилась версия jolt-jni —
нужен рестарт сервера (см. выше).

## Отличия от оригинала (MagicRuruka / PasToSmith)

- Команда `/rd …` вместо `/mrr rd …`; право `coremechanics.admin` вместо `pastosmith.admin`; новое: `/rd info`.
- Всё время жизни, лимит кукол, досягаемость, сила броска/удержания, время «обмякания» статуи — в `config.yml`
  (в оригинале — константы). Значения по умолчанию те же.
- Физика — в своём потоке, мир для коллизий — снимками в потоках регионов (в оригинале всё на главном потоке, чтение
  чанков напрямую). На границе чанков в меше коллизии могут быть лишние внутренние грани (соседний чанк не читается).
- Дисплеи куклы стоят в одной точке-якоре и двигаются трансформацией; переезд — `teleportAsync` (в оригинале каждый
  кусок телепортировался в центр своей части каждый тик).
- Игроки-кинематики (толкание физблоков телом) и сами физблоки не перенесены — рэгдоллы с ними не сталкивались
  (слой PLAYER сталкивался только с PUSHABLE).
- Танцы игроков из меню взаимодействий (`DollStudio.emote`, игрок невидим, кукла танцует) не перенесены — их нет в
  списке функций; код поз/анимаций готов, добавить можно.
- Статуи из несуществующего сейчас мира не теряются при сохранении (в оригинале выпадали из файла).
- Голова игрока без скина (офлайн, Стив) — обычная голова без профиля: иначе сервер на каждую отправку предмета
  ходит к Mojang за профилем (в офлайне — WARN в логе).
- Звуки анимаций — ключи (`entity.zombie.ambient`), не константы `Sound` (тесты без сервера).
- MineSkin недоступен — пауза 10 мин и одна строка в логе (в оригинале — предупреждение на каждую ошибку).

## Ограничения

- Нативка Jolt — только Linux x86-64.
- Смена версии jolt-jni — только с рестартом сервера.
- Кукла в выгруженном чанке пропадает (дисплеи несохраняемые; физика уберёт её через 10 с без отрисовки).
  Статуи — сохраняются в `statues.yml` и появляются снова при загрузке чанка.
- Скорость куклы ограничена 60 блоков/с, вокруг неё строится меш ±4 блока: очень быстрый бросок в плотную стену
  может на тик-другой пройти сквозь неё (как в оригинале).
- Внешний вид (кубики скина MineSkin, трансформации) проверен ботами только по данным сущностей; в настоящем
  клиенте на этом сервере не смотрели. MineSkin с настоящим ключом не проверялся (на тестовом сервере нет сети) —
  код загрузки перенесён из оригинала без изменений протокола.
