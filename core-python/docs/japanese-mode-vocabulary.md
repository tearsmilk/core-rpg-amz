# Японский режим (日本語モード) — словарь языка

Спецификация словаря для Python-систем, написанных целиком японскими знаками. Это **договор** между переводчиком
(хост, `core-python/src/host`), модулем `amazake` (`src/host/resources/python/amazake.py`) и авторами систем.
Всё, что здесь перечислено, должно работать; всё, чего здесь нет, остаётся английским (через запасной путь — см. §6.9).

Образец — `scripts/core_potions/` (полный `main.py` — в §8).

---

## 1. Включение и что делает режим

`manifest.yml` системы:
```yaml
name: core_potions
言語: 日本語          # или  language: ja   (значения: 日本語 | ja | japanese, регистр не важен)
```
Тогда **каждый** `.py` этой системы перед компиляцией проходит через переводчик. Без ключа — обычный Python,
ничего не переводится (но японские псевдонимы `amazake` из §4 доступны и там).

Что режим делает:

| Слой | Как | Где |
|---|---|---|
| ключевые слова (§2) | **замена токенов** NAME → английское слово | переводчик, до compile |
| методы встроенных типов (§3.3, «слова после точки») | замена токена NAME после `.` (и имени метода в теле `型定義`) | переводчик |
| dunder-имена (§2.3) | замена токенов `__初期化__` → `__init__` и т.п. | переводчик |
| встроенные функции и исключения (§3) | **не переводятся**: японские имена кладутся в `builtins` контекста системы | хост при создании контекста |
| API `amazake` (§4) | японские псевдонимы **в самом модуле** `amazake` (+ модуль `甘酒` = `amazake`) | `amazake.py`, всегда |
| Bukkit/Paper (§5) | прокси `包む(obj)` с японскими атрибутами; события/отправители в японских обработчиках приходят уже обёрнутыми | `amazake.py`, всегда |

Строки (включая литеральные части f-строк), комментарии, числа — **не трогаются**. Имена внутри `{…}` f-строк
переводятся (в Python 3.12 это обычные токены NAME между `FSTRING_START`/`FSTRING_END`).

### 1.1 Сохранение строк и столбцов (инвариант длины в байтах)

Переводчик меняет текст **на месте**: каждая заменяемая лексема занимает ту же строку, а английское слово
дополняется пробелами до **той же длины в байтах UTF-8**, что и японское:

```
もし データ である 無し:          (байты: もし=6, である=9, 無し=6)
if     データ is        None  :
```

- число строк и все переводы строк — те же → номера строк в трассах совпадают с исходным файлом;
- смещения столбцов в объекте кода (в Python 3.12 это **байты UTF-8**) совпадают с исходным файлом → «крышечки»
  `^^^^` в трассе стоят под нужным местом исходной (японской) строки;
- `co_filename` — путь исходного файла; трасса печатается по исходному файлу (linecache читает его с диска), так что
  в логе видна японская строка, а сообщение об ошибке — английское (`NameError: name '体力' is not defined`).

Отсюда **правило выбора слов**: японское ключевое слово из *k* знаков = 3·*k* байт, и это должно быть **не меньше**
длины английского слова. Все слова таблиц §2 и §3.3 ему удовлетворяют (проверка — в таблицах, столбец «байты»).
Все знаки — из BMP (3 байта в UTF-8); 4-байтовые знаки в словаре запрещены.

Известное следствие: самодокументирующие f-строки `f"{はい=}"` печатают **переведённый** текст выражения
(`True  =`) — так устроен Python (берёт текст из компилируемого исходника). Редкость, задокументировано.

`SyntaxError` из переведённого исходника: хост подставляет в `text` **исходную** строку (номер строки/столбец уже верны).

| `case` (мягкое) | **場合** | ばあい | 6 ≥ 4 | `場合 "reload":` | «случай» |

**Почему `於` для `in`.** Японский порядок слов «y の中に x» обратен питоновскому `x in y`, а `の中`/`内` между x и y
читались бы как «внутри x». `於` (おいて, «в/на», 於東京 = «в Токио») — классический предлог, который ставится **перед**
местом, ровно как `in`: `各 効果 於 一覧` — «каждый эффект в списке», `もし 識別子 於 設定` — «если id в настройках»,
`x 非 於 y` — «x не в y». Знак редкий, как имя переменной не встречается.

**Почему はい/いいえ/無し, а не 真/偽/無.** Однознаковые 真/偽/無 короче английских слов (3 байта < 4–5) — сломали бы
инвариант столбцов. 真実/虚偽 подходят по длине, но はい/いいえ читаются естественнее в аргументах
(`取消済み無視=はい`, `返す いいえ, 理由`). Регистр — один (разговорный): はい・いいえ・無し.

Мягкие ключевые слова `場合分け`/`場合` переводятся **всегда** (в японском режиме они зарезервированы); в английском
`match` остаётся мягким, поэтому `x.場合分け` → `x.match` по-прежнему корректно. Шаблон-«всё остальное» — `_`.
Мягкое `type` (оператор `type X = …`) не переводится.

## 3. Встроенные имена (кладутся в builtins контекста; НЕ зарезервированы)

Хост для японской системы добавляет в модуль `builtins` её контекста японские имена (ссылки на те же объекты).
Переводчик их не трогает: в трассах видны японские имена, а локальная переменная с таким именем просто **затеняет**
встроенное (как `list = …` в обычном Python). Английские встроенные имена остаются доступны.

### 3.3 Методы встроенных типов («слова после точки»; переводятся токенами, зарезервированы как имена методов)

Методы `dict`/`list`/`str`/`set` — английские атрибуты, их не заменить псевдонимами. Поэтому переводчик заменяет

## 4. Псевдонимы API `amazake` (в `amazake.py`, доступны всегда)

`甘酒` — тот же модуль (`sys.modules["甘酒"] is amazake`): `取り込む 甘酒`, `から 甘酒 取り込む 送る`.
Японские функции **разворачивают** обёртки §5 во всех аргументах; японские декораторы событий/команд передают
обработчику **обёрнутые** объекты (§5.1). Английские функции тоже разворачивают обёртки (чтобы `amazake.send(包み, …)`
работал), но ничего не оборачивают. Имена параметров японских функций — японские; английские имена параметров у
японских функций не принимаются (`ValueError`/`TypeError` с английским текстом).

## 5. Обёртки Bukkit/Paper (`包む`)

### 5.1 Как устроено

- `甘酒.包む(obj)` → `包み` (прокси с `__slots__ = ("_生",)`); `None`, объекты Python и уже обёрнутые — как есть.
  `甘酒.解く(x)` → Java-объект (для не-`包み` — как есть).
- **Автоматически оборачиваются**: аргумент обработчика `@イベント時`, `送り主` в `@コマンド`/`.補完`, результаты
  японских атрибутов/методов из таблиц ниже (Java-коллекции → список Python из обёрнутых элементов), задачи из японских
  `run_*`. Английские декораторы (`@on`, `@command`) **не** оборачивают — поведение старых систем не меняется.
- **Разворачиваются автоматически**: все аргументы функций `amazake` (английских и японских), аргументы японских
  методов обёрток, аргументы методов запасного пути (ниже).
- **Чтение** `x.体力` → геттер; **запись** `x.体力 = 20` → сеттер (`__setattr__`); свойство без сеттера → `属性エラー`
  с английским текстом (`AttributeError: '最大体力' is read-only on Player`).
- **Запасной путь**: имя не из таблиц (любое английское) → атрибут сырого Java-объекта. Если это метод — возвращается
  тонкая функция, которая разворачивает аргументы и возвращает **сырой** результат (английский мир остаётся английским):
  `プレイヤー.getHealth()`, `プレイヤー.showTitle(…)` работают.
- Сравнение и хэш — по Java-объекту (`包み == 生`, `hash(包み) == hash(生)`), `str()` — `toString()`, `bool` — `True`.
- **Скорость**: отражения на каждый вызов нет. Таблица каждого вида — dict `японское имя → (геттер, сеттер | функция)`;
  вид объекта определяется **один раз на Java-класс** (`obj.getClass().getName()` → кэш: какие таблицы применимы, по
  `java.instanceof` в порядке приоритета ниже), а для событий — ещё и какой из кандидатов-геттеров есть у класса
  (кэш `(класс, имя) → метод`). Обёртка создаётся лениво — вид ищется при первом обращении к атрибуту.

Приоритет видов (берётся первый подходящий, затем его «родители»): Player → HumanEntity → LivingEntity → Entity →
CommandSender; ItemStack; Event; World; Location; Block; PlayerInventory → Inventory; AttributeInstance; PotionEffect;
задача хоста.

Именование: **свойства** — существительные и предикаты на `か`/`中` без скобок (`体力`, `空か`, `スニーク中`),
**методы** — глаголы со скобками (`送る()`, `取り消す()`).

## 6. Правила коллизий и ограничения

1. **Ключевые слова §2 и dunder §2.3 зарезервированы** в японском режиме: токен переводится всегда и везде (имя
   переменной, параметра, атрибута после точки, именованного аргумента). Использовать их как имена нельзя — будет
   `SyntaxError` (так же, как с `if` в обычном Python). Отсюда выбор слов, которые не похожи на имена переменных:
   `抹消`, а не `削除`; `大域`, а не `全体`; `型定義`, а не `クラス`; `完了待ち`, а не `待つ`.
2. **Целиком токен.** Переводится только токен NAME, совпадающий со словом целиком: `もしも`, `無しの数`, `返す値` —
   обычные идентификаторы. Поэтому **после ключевого слова нужен пробел** (или знак препинания): `もしx > 0` — это
   идентификатор `もしx`. В японском тексте пробелов обычно нет — переводчик при ошибке компиляции в строке, где
   токен NAME **начинается** с ключевого слова, добавляет подсказку по-английски:
   `hint: 'もしx' is a single name; put a space after the keyword 'もし' (if)`.
3. **Слова после точки §3.3** зарезервированы как имена **методов** (после `.` и в `関数` прямо в теле `型定義`).
   Переменные и функции верхнего уровня с такими именами можно. Обёртки §5 и псевдонимы §4 эти слова не используют.
4. **Встроенные §3 не зарезервированы** — их можно затенить локальной переменной (не рекомендуется).
5. **Псевдонимы `amazake` §4** — атрибуты модуля, с переменными не конфликтуют (`データ = 甘酒.永続データ(…)` — можно).
   Но `から 甘酒 取り込む 送る` кладёт `送る` в глобальные имена — тогда своё `送る` его затенит.
6. Японские атрибуты обёрток никогда не перекрывают Java-имена (Java-имена — ASCII), английские всегда доступны.
7. **Полноширинные знаки** (`（）：，＝　` и т.п.) вне строк/комментариев не поддерживаются: переводчик выдаёт
   `SyntaxError` по-английски с позицией и подсказкой (`full-width '（' (U+FF08) at line 12; use ASCII '('`).
   Цифры — ASCII. Пунктуация Python (`( ) : , . = [ ] { }`) — ASCII.
8. **Имена файлов** `.py` и модулей — латиницей (как в README). Имена своих модулей импортируются как есть.
9. **Запасной путь к любому Java-API**: `甘酒.呼ぶ(obj, "methodName", *引数)`, `属性取得(Cls, "FIELD")`,
   `甘酒.ジャバ型("fq.Name")` — английское только внутри строк (строки — не код, их переводчик не трогает).
   Строки, которые остаются английскими по необходимости: полные имена классов Java, имена методов в `呼ぶ`, ключи yml,
   ключи PDC/NamespacedKey, английские имена событий без японского псевдонима.
10. **Ошибки**: тексты исключений и подсказок переводчика — английские; трасса указывает на исходный файл и строку
    (и столбец — инвариант §1.1). Новые сообщения в `amazake.py` для японских функций — по-английски.

関数 体力増加(プレイヤー, 体力, 期限):
    """期限（ミリ秒）まで最大体力を増やす。もう一度飲むと延長: 古いタイマーは新しい期限を見て何もしない。"""
    甘酒.一時修飾子追加(プレイヤー, "最大体力", 体力キー, 体力)
    残り = 最大値(1, 整数((期限 - 甘酒.現在ミリ秒()) / 50))

    関数 終了():
        データ = 甘酒.永続データ(プレイヤー)
        もし データ.読む(期限キー, 0) != 期限:
            返す   # 新しい薬で延長された — 新しいタイマーが外す
        甘酒.一時修飾子削除(プレイヤー, "最大体力", 体力キー)
        データ.消す(期限キー)
        データ.消す(量キー)
        上限 = プレイヤー.最大体力
        もし プレイヤー.体力 > 上限:
            プレイヤー.体力 = 上限

    甘酒.プレイヤーで一度(プレイヤー, 終了, 遅延=残り)

関数 参加(イベント):

            体力増加(プレイヤー, 小数(データ.読む(量キー, 0)), 期限)
        でなければもし 期限:
            データ.消す(期限キー)
            データ.消す(量キー)

    甘酒.プレイヤーで一度(プレイヤー, 復元, 遅延=2)
