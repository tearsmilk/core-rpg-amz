# AuraHud

Плагин Leaf/Paper 1.21.11 (автор tearsmilk, пакет `dev.tearsmilk.aurahud`): полная раскладка ванильного HUD игрока
через core-шейдеры ресурспака Nexo, без модов на клиенте. Хотбар, вторая рука, сердца, броня, еда, воздух, сердца
маунта, полоска опыта с уровнем и название предмета в руке ставятся куда угодно на экране: строкой, столбиком,
сеткой ("кубом"), с отступами, по любому из 9 якорей экрана, или скрываются.

Одна раскладка на сервер. Плагин пишет ее в пак как сгенерированный include `aurahud/shaders/include/ah_config.glsl`
и перезагружает пак Nexo. Ванильная раскладка (по умолчанию) дает `#define AH_ACTIVE 0`: хуки компилируются в пустые
функции, картинка пиксель в пиксель как без плагина (проверено в настоящем клиенте 1.21.11).

Плагин модульный: `HudModule` (`enable`, `reload`, `disable`, `packFiles`, `status`) регистрируется в
`ModuleRegistry`, раскладка - модуль `layout` (`dev.tearsmilk.aurahud.layout.LayoutModule`). Новые возможности
добавляются новыми модулями, которые отдают свои файлы пака.

## Что двигается вместе

| элемент | ключ | что входит |
|---|---|---|
| хотбар | `hotbar` | фон хотбара (режется на 9 ячеек), рамка выбора, предметы (и при анимации подбора), полоски прочности, перезарядка, числа стаков, индикатор атаки (режим "хотбар") |
| вторая рука | `offhand` | фон слота, предмет, прочность, перезарядка, число; слева или справа - как у игрока |
| сердца | `hearts` | все виды сердец (обычные, яд, иссушение, поглощение, заморозка, хардкор, мигающие), дрожание при малом здоровье и волна регенерации сохраняются |
| броня | `armor` | 10 иконок; поднимается вместе с лишними рядами сердец, как в ванили |
| еда | `food` | 10 иконок, дрожание при голоде сохраняется, вариант с эффектом голода |
| воздух | `air` | 10 пузырей, сдвигается вместе с лишними рядами сердец маунта |
| маунт | `mount` | сердца лошади и других живых маунтов (до 30) |
| опыт | `xp` | полоска опыта, полоска прыжка лошади, полоска локатора с точками и стрелками, число уровня |
| название | `item-name` | название предмета в руке и его подложка |

Ничего вне HUD не двигается: экраны инвентаря, чат и строка ввода, таб, табло, боссбары, титулы, actionbar.

## Команды (`/aurahud`, алиас `/ah`, право `aurahud.admin`)

- `/ah status` - состояние пака, режим каждого элемента (на ванильном месте, сдвинут, скрыт), метки текстур,
  замечания к config.yml.
- `/ah reload` - перечитать config.yml и обновить пак в фоне.
- `/ah preset` - список пресетов; `/ah preset <имя>` - применить (заменяет раздел `hud`);
  `/ah preset save <имя>` - сохранить текущую раскладку в `plugins/AuraHud/presets/<имя>.yml`.
- `/ah set <элемент> <ключ> <значение>` - поменять одну настройку, например `/ah set hotbar layout column`.
  Смена `anchor` сбрасывает `x` и `y` в 0; смена `layout` убирает `direction`, `wrap`, `per-line`, `reverse`.
  Слоты хотбара: `/ah set hotbar slot.3.y -6`, `/ah set hotbar slot.9.hidden true`.
- `/ah hide <элемент>`, `/ah show <элемент>` - скрыть или вернуть.
- `/ah reset <элемент>` или `/ah reset all` - вернуть на ванильное место.

Каждая правка сохраняет config.yml, перегенерирует `ah_config.glsl`, переписывает пак и вызывает
`nexo reload pack` (если `pack.reload-nexo: true`). Таб-дополнение знает элементы, ключи и значения.

## config.yml

```yaml
pack:
  install: true      # ставить файлы в пак
  dir: ""            # пусто - plugins/Nexo/pack/assets
  reload-nexo: true  # nexo reload pack после изменений
hud:
  hotbar: { ... }
  offhand: { ... }
  hearts: { ... }
  armor: { ... }
  food: { ... }
  air: { ... }
  mount: { ... }
  xp: { ... }
  item-name: { ... }
messages: { ... }    # тексты MiniMessage
```

Пустой элемент или отсутствующий ключ - ванильное значение. Ошибки в значениях не ломают пак: берется ванильное
значение, замечание пишется в консоль и в `/ah status`.

### Координаты и якоря

Координаты в пикселях GUI (как у ванили, без учета масштаба интерфейса), `x` вправо, `y` вниз. Якорь `anchor` - одна
из 9 точек экрана: `top-left`, `top-center`, `top-right`, `center-left`, `center`, `center-right`, `bottom-left`,
`bottom-center`, `bottom-right`. Одноименная точка рамки элемента ставится в точку экрана и сдвигается на `x`, `y`.
Например, `anchor: bottom-right, x: -2, y: -2` - правый нижний угол элемента в 2 пикселях от правого нижнего угла
экрана. Центр берется с округлением вниз, как в ванили.

Если `anchor` не задан, действует ванильный якорь `bottom-center` и ванильные `x`, `y` (таблица ниже); если задан
другой якорь, `x` и `y` по умолчанию 0.

| элемент | рамка (ширина x высота) | ванильные `x`, `y` от `bottom-center` |
|---|---|---|
| hotbar | 182 x 22 (строка) | 0, 0 |
| offhand | 29 x 24 | -106, 1 |
| hearts | 81 x 9 (первые 10 сердец) | -51, -30 |
| armor | 81 x 9 | -51, -40 |
| food | 81 x 9 | 50, -30 |
| air | 81 x 9 | 50, -40 |
| mount | 81 x 9 (первый ряд) | 50, -30 |
| xp | 182 x 5 (5 x 182 при повороте 90/270) | 0, -24 |
| item-name | точка: верх-центр текста | 0, -59 |

Рамка иконок считается по первой линии (у сердец, брони, еды, воздуха - 10 иконок, у хотбара - 9 слотов). Лишние
ряды сердец и сердец маунта уходят в сторону `wrap` за рамку, как второй ряд сердец в ванили.

### Ключи

Все элементы:

| ключ | значение | по умолчанию |
|---|---|---|
| `enabled` | `true` / `false` (скрыть) | `true` |
| `anchor` | якорь экрана | `bottom-center` |
| `x`, `y` | сдвиг, -4096..4096 | ванильный |

Иконки (`hotbar`, `hearts`, `armor`, `food`, `air`, `mount`):

| ключ | значение | по умолчанию |
|---|---|---|
| `layout` | `row` (строка), `column` (столбик), `grid` (сетка) | `row` |
| `per-line` (или `columns`) | иконок в линии, 1..40 | строка/столбик: 9 у хотбара, 10 у остальных; сетка: 3 у хотбара, 5 у остальных |
| `gap` | добавка к шагу иконок, -256..256 | 0 (шаг 20 у хотбара, 8 у иконок) |
| `line-gap` | добавка к шагу линий | 0 (шаг 20 у хотбара, 10 у иконок) |
| `direction` | куда идут иконки: `right`, `left`, `up`, `down` | строка/сетка: `right` (еда, воздух, маунт - `left`), столбик: хотбар `down`, остальные `up` |
| `wrap` | куда идут следующие линии, поперек `direction` | хотбар `down`, остальные `up`; у столбика `right` (еда, воздух, маунт - `left`) |
| `reverse` | `true` - обратный порядок в линии | `false` |

Хотбар дополнительно:

| ключ | значение |
|---|---|
| `slots.<1-9>.x`, `slots.<1-9>.y` | личный сдвиг слота (номер как клавиша), рамка выбора, предмет, прочность, перезарядка и число идут вместе со слотом |
| `slots.<1-9>.hidden` | `true` - спрятать слот целиком |
| `attack-indicator` | `false` - спрятать индикатор атаки в режиме "хотбар" |
| `attack-x`, `attack-y` | сдвиг индикатора атаки от его ванильного места рядом с 9-м слотом (1-м, если вторая рука справа) |

Шаг ячеек хотбара 20 при размере 22: соседние ячейки делят рамку, как в ванили. `gap: 4` - отдельные "кубики".

Вторая рука: `follow: hotbar` (по умолчанию) - слот держится рядом с 1-м слотом хотбара (справа от 9-го, если
ведущая рука левая) и ездит вместе с ним; `follow: none` - стоит по своим `anchor`, `x`, `y` (если задан `anchor`,
`x` или `y`, то `none` по умолчанию).

Опыт: `rotate: 0|90|180|270` (по часовой; 270 - вертикально, заполнение снизу вверх), `level: false` - скрыть число
уровня, `level-x`, `level-y` - сдвиг числа от его ванильного места относительно центра полоски.

### Примеры

Вертикальный хотбар у левого края по центру, вторая рука под ним:

```yaml
hud:
  hotbar:
    anchor: center-left
    x: 2
    layout: column
  offhand:
    anchor: center-left
    x: 2
    y: 105
```

Хотбар кубом 3x3 в правом нижнем углу, слоты отдельными кубиками:

```yaml
hud:
  hotbar:
    anchor: bottom-right
    x: -2
    y: -2
    layout: grid
    per-line: 3
    gap: 2
    line-gap: 2
```

Сердца в левом нижнем углу, броня над ними, еда столбиком у правого края:

```yaml
hud:
  hearts:
    anchor: bottom-left
    x: 2
    y: -2
  armor:
    anchor: bottom-left
    x: 2
    y: -12
  food:
    anchor: bottom-right
    x: -2
    y: -2
    layout: column
```

Скрыть опыт и броню, поднять 1-й слот, спрятать 9-й:

```yaml
hud:
  xp:
    enabled: false
  armor:
    enabled: false
  hotbar:
    slots:
      '1':
        y: -6
      '9':
        hidden: true
```

Вертикальная полоска опыта у правого края с числом слева:

```yaml
hud:
  xp:
    anchor: center-right
    x: -2
    rotate: 270
    level-x: -10
```

## Пресеты

`/ah preset <имя>`:

- `vanilla` - ванильная раскладка;
- `left-column` / `right-column` - хотбар столбиком у левого/правого края, вторая рука под ним, полоски внизу по центру;
- `grid-corner` - хотбар кубом 3x3 в правом нижнем углу, вторая рука над ним, вертикальный опыт слева от куба,
  сердца, броня, еда и воздух в левом нижнем углу;
- `compact` - хотбар на месте, опыт прямо над слотами, сердца и броня блоками 5x2 слева от хотбара, еда и воздух
  справа (нужна ширина GUI от 364);
- `sides` - сердца и броня столбиками у левого края, еда и воздух у правого, опыт вертикально у левого края;
- `minimal` - скрыты опыт, броня и название предмета.

Свои пресеты: `/ah preset save <имя>` или файл `plugins/AuraHud/presets/<имя>.yml` с разделом `hud:`.

## Как шейдер узнает и сдвигает элементы

Все элементы HUD в 1.21.11 рисуются общими core-шейдерами (`position_tex_color` - спрайты и предметы, `gui` -
заливки, `rendertype_text` - текст), отдельного шейдера HUD нет. Вершинные хуки `ah` по одной вершине (позиция,
цвет, UV, угол квада `gl_VertexID % 4`, размер экрана из `ProjMat`) решают, к какому элементу и слоту относится
квад, и добавляют сдвиг в clip-пространстве поверх того, что записали хуки других плагинов. Все четыре вершины
квада получают один и тот же сдвиг, поэтому квады не рвутся.

- Фон хотбара, рамка выбора, фон второй руки, индикатор атаки: точное положение угла квада по известному размеру.
  Фон хотбара 182x22 при нестандартной раскладке растягивается на рамку новой раскладки, а фрагментный хук
  вырезает из спрайта 9 ячеек по 22x22 и рисует каждую на новом месте (работает и с перерисованными хотбарами).
- Предметы: блит из атласа предметов UI (квадратная текстура, степень двойки, UV кратны ячейке `16 * guiScale`,
  V перевернута) плюс окно слота, которое выдерживает анимацию подбора.
- Прочность, перезарядка: заливки `gui` по точной высоте, цвету и окну слота.
- Числа стаков: чисто белый текст (тень 0x3F3F3F) на строке слота; строка ввода чата (0xE0E0E0) не трогается.
- Сердца, броня, еда, воздух, сердца маунта: метки в прозрачных угловых текселях спрайтов (R=167, G=семейство,
  B=90, альфа 0 - на экране не видны) плюс точная колонка; ряд сердец считается по высоте, дрожание остается.
- Полоска опыта, прыжка и локатора: белые квады на высотах h-29/h-24 в пределах полоски, точки и стрелки локатора по
  своим высотам; все двигаются жестко (с поворотом). Число уровня - зеленый и черный текст в своей полосе.
- Название предмета: текст в его строке (h-59, в креативе h-45) и его подложка.

### Метки текстур

Когда раскладка не ванильная, плагин кладет в пак 59 спрайтов `minecraft:hud/...` (сердца всех видов, сердца
маунта, броня, еда, воздух) с метками в 4 углах каждого кадра и `.png.mcmeta` с `"mipmap_strategy": "mean"` (иначе
клиент перекрашивает прозрачные тексели и метка теряется). Источник текстуры, по порядку: файл, который уже лежит в
`pack.dir` (свой скин сервера; перед изменением копируется в `plugins/AuraHud/pack-backup/<дата>-sprites/`), такой
же файл во внешних паках Nexo (`plugins/Nexo/pack/external_packs/*.zip` и папки), ванильный спрайт из jar. Анимация
и другие поля `.mcmeta` сохраняются. Спрайт с непрозрачным углом пометить нельзя - он остается как есть, его иконки
не сдвигаются, это видно в `/ah status` и в консоли. Метки невидимы, поэтому ванильная раскладка с уже помеченными
текстурами тоже совпадает с ванилью пиксель в пиксель.

## Ограничения

- Больше 3 рядов сердец (больше 60 единиц здоровья с поглощением): ваниль сжимает ряды, шаг ряда шейдеру не
  известен, при сдвинутых сердцах 4-й и следующие ряды могут лечь на соседние. Таблица раскладки сердец - 40 сердец.
- Сердца маунта - до 3 рядов (30 сердец, как в ванили).
- Предметы с моделью больше 16x16 в GUI (рисуются отдельной текстурой) не двигаются вместе со слотом.
- Шрифт "только юникод" (forceUnicodeFont) и TTF-шрифты: числа стаков, уровень и название предмета не двигаются
  (определяются по ванильной высоте глифа 8).
- Подчеркивание и зачеркивание в названии предмета остаются на месте.
- Хотбар наблюдателя (меню наблюдателя) не двигается.
- Броня и воздух при сдвиге следуют за лишними рядами сердец и сердец маунта по шагу `wrap` этих элементов.
- Перекрытия при узком экране не проверяются: раскладка в пикселях GUI, при маленькой ширине элементы с разных якорей
  могут наложиться (пресет `compact` рассчитан на ширину GUI от 364).
- Если внешний пак Nexo перекрывает помеченные спрайты после сборки, меток в итоговом паке не будет и иконки этих
  элементов останутся на месте.

## Общие core-шейдеры: схема хуков (shaderhooks)

textshader, tabshader, nameshader, chatshader и aurahud меняют одни и те же core-шейдеры (`gui`,
`position_tex_color`, `rendertype_text`). Канонические файлы побайтно одинаковые во всех плагинах
(`#define SHADERHOOKS_VERSION 2` и `#define SHADERHOOKS_HASH h<16 hex>`) и вызывают хуки всех плагинов в порядке
ts, th, ns, cs, ah. У aurahud префикс `ah`, хуки лежат в `pack/assets/aurahud/shaders/include/ah_hook_*.glsl`,
заглушки всех пяти плагинов - в `pack/stubs/`. Хук `ah` вызывается последним, поэтому его запись `gl_Position`
окончательная.

Сигнатуры хуков `ah`:

- `gui` (`gui.vsh/.fsh`, все `fill()`):
  - `void ah_hook_gui_position(inout vec3 pos)`
  - `void ah_hook_gui_vertex(vec3 pos, vec4 color, int vertexId, inout vec4 outColor)`
  - `vec4 ah_hook_gui_fragment(vec4 color, vec4 vertexColor)`
- `sprite` (`position_tex_color.vsh/.fsh`, спрайты HUD и предметы из атласа UI): с версии 2 вершинный шейдер
  объявляет `uniform sampler2D Sampler0`, так что вершинный хук может читать текстуру (`textureLod`, `texelFetch`).
  - `void ah_hook_sprite_position(inout vec3 pos)`
  - `void ah_hook_sprite_vertex(vec3 pos, vec2 uv, vec4 color, int vertexId, inout vec4 outColor)`
  - `vec4 ah_hook_sprite_fragment(vec4 color, vec4 tex, vec2 uv, vec4 vertexColor)`
- `text` (`rendertype_text.vsh/.fsh`, весь текст, `Sampler0` и `Sampler2` объявлены):
  - `void ah_hook_text_position(inout vec3 pos, inout vec4 color)`
  - `void ah_hook_text_vertex(vec3 pos, vec4 color, vec2 uv, int vertexId, vec4 light, inout vec4 outColor)`
  - `vec4 ah_hook_text_fragment(vec4 color, vec4 vertexColor, vec2 uv)`

`pos` в вершинном хуке - исходная `Position`, `vertexId` - `gl_VertexID`. Хук-файлы не объявляют `in`/`out` и не
объявляют сэмплеры заново; все глобальные имена с префиксом `ah_`/`AH_`.

Плагин при старте синхронно (при `/ah reload` в фоне) пишет в пак канонические файлы, свои include и заглушки
отсутствующих плагинов (класс `ShaderHooks`, генерируется из `tools/shaderhooks/ShaderHooks.java.in`). Замененные
файлы копируются в `plugins/AuraHud/pack-backup/<дата-время>/`. Ставить вместе с textshader, tabshader, nameshader и
chatshader той же сборки схемы (версия 2): старый jar (версия 1) файлы версии 2 оставляет и пишет предупреждение,
та же версия с другим хэшем - красная строка "КОНФЛИКТ".

## Сборка и проверки

```
./gradlew --offline build                          # jar в build/libs/aurahud-1.0.0.jar, тесты
./gradlew --offline test -Daurahud.golden=write    # обновить ah_config.glsl и tools/configs/*.glsl после правок генератора
python3 -I tools/glsl_check.py client-1.21.11.jar  # glslangValidator 330 и 410, все раскладки, MythicHUD, combos
python3 -I tools/shaderhooks/shaderhooks.py        # общие файлы схемы хуков совпадают во всех проектах (--write - обновить)
```

Тесты: `HudMirrorTest` - зеркало логики шейдеров на Java: для всех пресетов, нескольких раскладок и размеров экрана
строит ванильные квады HUD (дрожание сердец и еды, ряды поглощения, маунт, воздух, анимация подбора, вторая рука
справа, креатив) и проверяет, что все части элемента едут вместе и встают на свое место, а ванильная раскладка и
квады экранов (инвентарь, чат, таб, боссбар) не двигаются. `SettingsTest` - разбор config.yml, `GeneratorTest` -
вывод генератора (ванильный include в паке и эталоны `tools/configs/`), `PresetsTest` - пресеты в пределах экрана и
без перекрытий, `SpriteMarkerTest` - метки, идемпотентность, свои и внешние скины, анимации, серые PNG.

`tools/glsl_check.py` компилирует все шейдеры с aurahud одним и со всеми плагинами, каждую раскладку из
`tools/configs/` с каждым набором остальных плагинов (16 наборов), MythicHUD-оверлей `rendertype_text` с каждой
раскладкой, сравнивает с ванилью и прогоняет все комбинации и порядки установки (shaderhooks combos).

## Деплой

1. Собрать и положить вместе `aurahud-1.0.0.jar`, `textshader`, `tabshader`, `nameshader`, `chatshader` той же
   сборки схемы хуков (версия 2).
2. Перезапустить сервер. В логе: `Шейдеры в .../Nexo/pack/assets: записано файлов N`.
3. `/ah preset <имя>` или правки `hud:` + `/ah reload`, проверить `/ah status`.
4. Откат: `/ah preset vanilla` (или `/ah reset all`) - шейдеры снова ничего не делают; помеченные спрайты можно
   оставить, они выглядят как исходные.
