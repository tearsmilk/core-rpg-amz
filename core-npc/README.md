# core-npc

Система Amazake (Paper 1.21.11, форк; Java 21): свои NPC вместо Citizens.

- **NPC** — манекен (`mannequin`, сущность 1.21.9+: модель игрока со скином) или любой живой моб (`villager`,
  `zombie`…). Бессмертные, без ИИ, бесшумные, не толкаются, не горят днём, **не сохраняются в мир**
  (`setPersistent(false)`): система ставит их сама из `npcs.yml` при включении и при загрузке чанка и убирает при
  выключении — после падения сервера или `restart` дублей не бывает. Если сущность NPC убрал другой плагин или
  система (чистка мобов, `/kill`), NPC встаёт заново: сразу (не чаще раза в 10 с) и проверкой раз в 5 с.
- **Скин** манекена — по нику (профиль ищется у Mojang вне потоков тика, текстура запоминается в `npcs.yml`) или
  готовой текстурой `value` + `signature`.
- **Модель ModelEngine** (по желанию): `/npc model <id> <модель> [масштаб]`, анимация по умолчанию и при клике.
  Нет ModelEngine — NPC работают без моделей.
- **Диалоги как в LuxDialogues**: окно над хотбаром из пакета ресурсов (рамка, имя говорящего, текст печатается
  по буквам со звуком, `<wait:N>` — пауза), ответы выбираются колёсиком и подтверждаются F / ЛКМ / кликом по NPC,
  Shift — уйти; ветвление страниц, условия (права, PlaceholderAPI), действия (команды игрока и консоли, сообщения,
  звуки, переходы в другие диалоги). Запасной режим — обычное окно диалога клиента 1.21.6+ (`mode: native`).
- **Команды по клику** (ПКМ, по желанию и ЛКМ): от игрока или из консоли, с кулдауном и правом.

## Установка

1. Сборка: `./gradlew azs test` → `build/libs/core-npc.azs` (копия — `dist/core-npc.azs` в корне репозитория).
2. Файл в `systems/` сервера (через временный файл и `mv`), затем `amazake system enable core-npc`
   (обновление — `amazake system restart core-npc`). Появится `systems/core-npc/` с `config.yml`,
   `dialogs/example.yml`, а после первого NPC — `npcs.yml`.
3. Пакет ресурсов: `pack/assets/corenpc/` скопировать в `plugins/Nexo/pack/assets/corenpc/` как есть, затем
   `nexo reload pack` (игрокам пак переотправится). При обновлении папку `corenpc` в паке заменить целиком
(старые `glyphs.png`, `box.png`, `highlight.png` больше не используются). **Общие core-шейдеры не меняются** — только глифы шрифтов в
   своём пространстве имён `corenpc` (обычный `rendertype_text`). Без пакета окно диалога будет «квадратиками» —
   тогда поставьте `dialog.mode: native`.
4. **Citizens**: команда `/npc` занята Citizens, пока он стоит (плагины регистрируют команды раньше систем) — тогда
   пользуйтесь `/cnpc` или `/corenpc` (те же подкоманды). Удалите Citizens — заработает и `/npc`. В `system.yml`
   Citizens указан в `conflicts` (предупреждение при включении).
5. ModelEngine (по желанию) — обычный плагин в `plugins/`. Если он включится позже системы, NPC с моделями
   переставятся сами.

## Команды

Право `corenpc.admin` (у OP есть). `/npc`, `/cnpc`, `/corenpc`. Автодополнение — по всем аргументам.
Добавить NPC **консольную** команду (`/npc command add <id> console …`) можно только с отдельным правом
`corenpc.admin.console` (у OP есть): это доступ к консоли сервера.

| Команда | Что делает |
|---|---|
| `/npc create <id> [тип]` | NPC здесь (тип по умолчанию `mannequin`; `villager`, `zombie`, `skeleton`… — любой живой моб). Id: латиница, цифры, `_ - .` |
| `/npc remove <id>` | Удалить |
| `/npc list` | Список (зелёные стоят в мире, серые — их чанк не загружен) |
| `/npc info <id>` | Всё про NPC |
| `/npc tp <id>` | Телепорт к NPC |
| `/npc tphere <id>` (`move`) | Перенести NPC к себе (с вашим поворотом) |
| `/npc rename <id> <имя…>` | Имя в MiniMessage (`<gold>Староста Ведан`); `-` — без имени |
| `/npc skin <id> <ник>` | Скин игрока (ищется у Mojang, сохраняется в `npcs.yml`) |
| `/npc skin <id> value <value> [signature]` | Скин текстурой (например, с mineskin.org) — удобно из консоли |
| `/npc skin <id> clear` | Стандартный скин |
| `/npc type <id> <тип>` | Сменить тип сущности |
| `/npc model <id> <модель> [масштаб]` | Модель ModelEngine (базовая сущность становится невидимой) |
| `/npc model <id> anim idle\|interact <анимация\|->` | Анимация по умолчанию / при клике |
| `/npc model <id> remove` | Снять модель |
| `/npc dialog <id> <диалог\|none>` | Привязать диалог (`dialogs/<диалог>.yml`) |
| `/npc command add <id> <player\|console\|message\|sound> <текст…>` | Действие по клику (`{player}`, `{npc}`, `%papi%`); `console` — с правом `corenpc.admin.console` |
| `/npc command list <id>` / `remove <id> <номер>` | Список / удалить |
| `/npc look <id> [on\|off\|me]` | Следить за игроком (`on`) или стоять статично (`off` — как поставили, `me` — лицом к вам); без аргумента — переключить |
| `/npc set <id> <ключ> <значение>` | `look-at true/false`, `look-radius 8`, `gravity`, `collidable`, `permission <право\|->`, `cooldown 3s\|default`, `left-click true`, `hologram name\|display\|none`, `lines <строка \| строка>` (для `display`), `scale 1.2` |
| `/npc talk <id> [игрок]` | Открыть диалог NPC игроку (без команд и кулдауна) |
| `/npc open <диалог> <игрок> [npc]` | Открыть любой диалог — для других плагинов и систем (из консоли) |
| `/npc close [игрок]` | Закрыть диалог |
| `/npc reload` | Перечитать `config.yml`, `dialogs/`, `npcs.yml`, поставить NPC заново. Файлы читаются вне потоков тика; если что-то не прочиталось (битый YAML), не меняется ничего — NPC остаются стоять, причина — в ответе и в консоли |

Клик по NPC (поток игрока): если с ним уже идёт разговор — «дальше/ответить»; иначе проверяется право NPC
(`permission`), кулдаун, выполняются команды NPC по порядку, проигрывается анимация модели `interact`, открывается
диалог. ЛКМ всегда отменяет удар; как клик срабатывает только при `left-click: true`.

## npcs.yml

Пишется командами (атомарно: временный файл и переименование). Правка руками — затем `/npc reload`.

```yaml
npcs:
  elder:
    type: mannequin
    location: {world: world, x: 12.5, y: 64.0, z: -3.5, yaw: 180.0, pitch: 0.0}
    name: "<gold>Староста Ведан"
    hologram: name            # name — имя над головой; display — TextDisplay (name + hologram-lines); none
    hologram-lines: ["<gray>староста деревни", "<yellow>[ПКМ]"]
    skin: {name: Notch, value: "ewog…", signature: "…"}
    model: {id: elder, scale: 1.0, idle: idle, interact: wave}   # ModelEngine; без раздела — без модели
    dialog: example
    commands:
      - "console: say {player} говорит со старостой"
      - "sound: minecraft:entity.villager.ambient 1 1"
    permission: ""            # право, без которого NPC не отвечает
    cooldown: -1.0            # секунд между кликами игрока (-1 — npc.cooldown-seconds из config.yml)
    left-click: false
    look-at: true             # поворачивать голову к ближайшему игроку
    look-radius: -1.0         # блоков (-1 — npc.look-radius)
    gravity: false
    collidable: false
    scale: 1.0                # атрибут scale (0.0625..16)
```

## Диалоги: dialogs/<id>.yml

Id диалога — путь файла без `.yml` (подпапки можно: `dialogs/quests/wolf.yml` → `quests/wolf`). Ошибки и
предупреждения (битые переходы, недостижимые страницы, строки шире окна, лишние строки) пишутся в консоль при
включении и `/npc reload`; битый переход в игре закрывает диалог с сообщением.

```yaml
start: greet                  # стартовая страница (иначе первая)
speaker: "Староста Ведан"     # имя по умолчанию для страниц (MiniMessage)
speed: 1.0                    # символов за тик по умолчанию (иначе dialog.chars-per-tick)
sound: ""                     # звук при показе страницы по умолчанию
mode: hud                     # hud | native — иначе как dialog.mode
on-end: ["sound: minecraft:entity.villager.celebrate"]   # дошёл до конца (не Shift, не ушёл)
pages:
  greet:
    speaker: "<gold>Ведан"
    lines:                    # до 3 строк; {player} {npc} {npc_name} {world} {dialog}, %papi%, <wait:20> — пауза 1 с
      - "Здравствуй, <white>{player}</white>.<wait:10> Давно не было путников."
      - "Ты по делу или так, <gray>поглазеть</gray>?"
    speed: 1.5
    sound: "minecraft:entity.villager.ambient 0.8 1"
    actions: ["message: <gray>Ведан смотрит на вас.</gray>"]   # при показе страницы
    answers:
      - text: "Кто ты такой?"
        goto: who             # страница | другой_диалог:страница | другой_диалог: | end
      - text: "Мне нужен хлеб."
        requires: ["!permission: volya.example.bread"]           # все условия; «a || b» — любое из
        actions:
          - "console: give {player} bread 3"
          - "message: <gray>Ведан протягивает вам три буханки.</gray>"
        goto: bread
      - "Ничего, я пойду."    # просто строка — ответ, закрывающий диалог
  who:
    lines: ["Я староста этой деревни."]
    next: greet               # страница без ответов: F / ЛКМ / клик по NPC — дальше (без next — конец)
```

**Действия** (страницы, ответа, `on-end`, команды NPC): `player: <команда>` — от имени игрока; `console:
<команда>` — из консоли (глобальный поток, см. ниже); `message: <MiniMessage>`; `actionbar: <MiniMessage>`; `sound: <звук>
[громкость] [высота]`; `goto: <страница>`; `close`. Строка без префикса — команда игрока. Выдавать вещи и права —
только консольными командами (`give`, `lp user {player} permission set …`).

**Подстановки и безопасность.**
- В **консольную** команду подставляются только `{player}`, `{player_uuid}`, `{npc}`, `{dialog}`, `{world}`
  (`{player_display}`, `{npc_name}` остаются как есть: ник из плагинов ников задаёт игрок). Каждое подставленное
  значение — переменная или `%плейсхолдер%` — должно быть одним словом: без пробелов, управляющих символов и `§`,
  не селектор `@…`. Иначе команда не выполняется (в консоль — предупреждение один раз на шаблон).
- В тексте (MiniMessage: строки, ответы, имя говорящего, `message`, `actionbar`) значения переменных **и результаты
  `%плейсхолдеров%`** экранируются — плейсхолдер, отдающий текст игрока, не вставит теги (цвет, клик).
  Плейсхолдер, который должен вернуть разметку MiniMessage, поэтому как разметка не сработает.

**Условия**: `permission: узел`, `!permission: узел`, `papi: %placeholder% >= 10` (`== != >= <= > < contains`;
числа сравниваются как числа, иначе строки без регистра). Ответ с невыполненным условием не показывается.

Полный рабочий пример — `src/main/resources/dialogs/example.yml` (кладётся в `systems/core-npc/dialogs/` при первом
включении): ветвление, условие, выдача хлеба, переход обратно, `on-end`.

## Окно диалога (hud) и ввод

- Окно рисуется в **actionbar**: рамка 320×78 шрифта `corenpc:dialog` и 7 строк — шрифты `corenpc:row0` (имя),
  `row1..row3` (текст), `row4..row6` (ответы).
  - Клиент 1.21.11 собирает глифы в атлас 256×256 (`FontTexture.SIZE`): глиф шире или выше 256 не рисуется. Поэтому
    рамка — две половины 160×78 (`U+E000`, `U+E001`, между ними сдвиг −1), подсветка выбранного ответа — две
    половины 154×16 (`U+E010`, `U+E012`, только в `row4..row6`), «▼ дальше» (`U+E011`) — только в `row6`.
  - У bitmap-шрифта `ascent` не может быть больше `height` — иначе клиент отбрасывает **весь файл шрифта**
    («Unable to load font»). Строки поднимаются над actionbar ascent'ом, поэтому у глифов снизу прозрачный запас:
    клетка 8×h, где h = max(8, ascent) у каждой строки своя (`glyphs_h59.png` … `glyphs_h8.png`; буквы с
    надстрочными знаками Й, Ё… — `tall_h*.png` из ванильного `accented.png`). Чем ниже строка, тем меньше пустоты:
    атлас всех 7 шрифтов — около 36 страниц 256×256 (было 70 при общей клетке 8×64).
  - Символа нет в наборе (ascii, латиница с диакритикой, греческий, кириллица, пунктуация, стрелки, рамки) — в окне
    вместо него `?`: у шрифтов строк нет запасного шрифта, клиент нарисовал бы «нет глифа».
  - `tools/gen_pack.py` проверяет оба правила клиента при генерации, `PackTest` — в `./gradlew test`.
  - Сдвиги по горизонтали — пробелы `U+F801..` (−1…−512) и `U+F821..` (+1…+512) шрифта `corenpc:dialog`. Итоговая ширина строки = ширине окна, поэтому
  клиент центрирует её ровно. Окно — от H−128 до H−51 (над сердцами и бронёй), на 1080p с масштабом GUI 4 —
  чуть ниже прицела. Превью раскладки (симуляция, не снимок клиента) — `tools/preview/hud.png`.
- Текстуры и шрифты генерирует `tools/gen_pack.py` (Python 3 + Pillow + numpy; ванильные текстуры шрифта берёт из
  клиентского jar 1.21.11 — путь аргументом или скачает с серверов Mojang), он же пишет `font-widths.txt` (ширины
  глифов для раскладки в Java). Числа раскладки — в `hud/HudLayout.java` и в начале скрипта.
- Строка текста — до 304 пикселей GUI (≈ 50 символов кириллицы). Шире — конец вылезет за рамку (в консоль —
  предупреждение при загрузке). Строк — до 3, ответов видно 3 (список прокручивается за выбором).
- **Ввод**: колёсико или цифры 1–9 двигают выбор (смена слота отменяется), **F** или **ЛКМ** — допечатать / ответить
  / дальше, **клик по NPC** — то же, **Shift** — уйти. Дальше `max-distance` (6) от NPC — диалог закрывается. Во
  время диалога нельзя ходить (`freeze`), по желанию и крутить головой (`camera-lock`); при открытии игрок
  поворачивается к NPC (`face-npc`). Диалог закрывается при смерти, смене мира и телепорте далеко (от NPC — дальше
  `max-distance`; без NPC — дальше 16 блоков). Ответы можно дублировать в чат кликабельными строками
  (`chat-answers`, по умолчанию выключено; клик — custom-событие `corenpc:c<сессия>_<номер>`). Чат на время разговора
  чистый: при открытии он «прокручивается» пустыми строками (`clear-chat-lines`), а сообщения других игроков этому
  игроку не приходят (`hide-chat`). Сообщения плагинов и системы сервер скрыть не может — спрятать чат целиком
  можно только в настройках клиента.
  События ввода ловятся с приоритетом LOWEST и отменяются: rezusmenu (F открывает меню, `ignoreCancelled`) в
  диалоге не срабатывает.
- **native** — обычное окно диалога клиента 1.21.6+ (как `/menuses` в rezusmenu): имя — заголовок, текст — тело,
  ответы — кнопки, «Уйти» — выход (и Esc). Без печати по буквам и без пакета ресурсов.

### Соседство с core-effects (actionbar и заголовок)

- core-effects рисует накладки эффектов в **заголовке (title)** раз в 3 с — окно диалога в **actionbar**, они не
  мешают друг другу.
- Иконки эффектов core-effects по умолчанию тоже в **actionbar** (раз в секунду, пока есть эффект). Во время диалога
  core-npc переотправляет окно каждые `dialog.refresh-ticks` (2) тика, так что иконки мелькнут не дольше чем на
  0,1 с. Чтобы не мелькали совсем: в core-effects `hud.actionbar: false` (иконки — через MythicHUD) или научить
  core-effects молчать, пока у игрока в PDC есть метка `corenpc:dialog` (byte 1) — её ставит core-npc на время
  диалога (`dialog.player-flag`), снимает при закрытии, выходе и входе.
- MythicHUD меняет `rendertype_text`, но трогает только текст с огромным сдвигом по высоте и зелёный цвет опыта;
  глифы core-npc в пределах экрана и другого цвета (не используйте в диалогах цвет `#80FF20`).

## ModelEngine

- Мягкая зависимость, вызовы через рефлексию (загрузчик системы не видит классы плагинов); метод выбирается по
  типам аргументов (у ModelEngine есть перегрузки `createModeledEntity(Entity|BaseEntity)`,
  `createActiveModel(String|ModelBlueprint)`, `playAnimation` с разными параметрами): `ModelEngineAPI
  .createModeledEntity(entity)`, `createActiveModel(id)`, `ActiveModel#setScale`, `ModeledEntity#addModel(model,
  true)`, `setBaseEntityVisible(false)`, `getAnimationHandler().playAnimation(anim, 0.25, 0.25, 1, true)`; при
  удалении NPC — `ModeledEntity#destroy()`. Ошибки вызова — в консоль один раз, NPC остаётся без модели.
- Все вызовы ModelEngine — **в потоке региона сущности** (там же, где она ставится): не полагаемся на то,
  потокобезопасен ли ModelEngine (`folia-supported` у R4.2.0 не проверен — jar с продакшена скачать не удалось).
- Модель «живёт» на сущности NPC; NPC не сохраняется в мир, поэтому и модель ModelEngine не сохраняет — при
  загрузке чанка система ставит NPC и вешает модель заново.
- **Не проверено вживую**: ModelEngine нет на тестовом сервере. Нужна проверка на продакшене: `/npc model <id>
  <модель>` и клик (анимация `interact`).

## Потоки (Amazake)

- NPC ставятся, правятся и убираются в потоке региона их чанка (`getRegionScheduler().execute(world, cx, cz)`);
  «смотреть на игрока» — глобальный таймер раз в `npc.look-interval-ticks` раздаёт задачи регионам NPC. Планировщик
  сущностей не используется.
- Диалог — задача `runForPlayer` игрока (печать, окно, расстояние), его события (колёсико, F, ЛКМ, Shift, движение)
  и команды. Кнопки обычного окна и клики в чате приходят из других потоков и передаются в поток игрока.
- Консольные команды действий — в глобальном потоке; поиск скина и запись `npcs.yml` — вне потоков тика.
- Выключение (`disable`, глобальный поток): диалоги закрываются в потоках игроков, NPC убираются, `npcs.yml`
  сохраняется. NPC убираются сразу только в регионах, которыми владеет текущий поток — сегодня Amazake тикает мир
  в одном потоке, и это все NPC. Задачам регионов при выключении система не доверяется (ядро отменяет их после
  `disable()`): при многопоточном тике NPC, голограммы и модели в чужих регионах останутся до выгрузки чанка (они
  несохраняемые), а при следующем включении их уберёт сама система как хвосты с меткой `corenpc:npc` (в
  `spawnHere` и при загрузке чанка). Сколько осталось — пишется в лог.
- `/npc reload`: чтение файлов — вне потоков тика, применение — в глобальном потоке. Поздний ответ поиска скина
  после выключения системы игнорируется (не перезапишет `npcs.yml` новой копии).

## config.yml

См. комментарии в файле. Главное: `dialog.mode` (`hud`/`native`), `dialog.chat-answers`, `dialog.max-distance`,
`dialog.freeze`, `dialog.camera-lock`, `dialog.face-npc`, `dialog.prevent-skip`, `dialog.chars-per-tick`,
`dialog.refresh-ticks`, `dialog.typing-sound.*`, `dialog.input.*`, `dialog.format.*`, `dialog.native.*`,
`npc.look-interval-ticks`, `npc.look-radius`, `npc.cooldown-seconds`, `npc.hologram-offset`, `modelengine.enabled`,
`messages.*` (ключи — `Settings.java`, пустая строка — не отправлять).

## Тесты

`./gradlew test` — чистая логика: разбор диалога и проверка графа страниц (битые `goto`, недостижимые страницы,
ссылки между диалогами), печать с тегами MiniMessage и `<wait>`, ход диалога (пропуск, выбор по кругу, скрытые
ответы), условия, действия, подстановка `{переменных}` с экранированием, разбор аргументов команд, сдвиги и ширины
глифов (окно ровно по центру, строки примера влезают, незнакомые символы → `?`), пакет ресурсов по правилам
клиента (`ascent ≤ height`, клетка ≤ 256), безопасные аргументы консольных команд, выбор перегрузки ModelEngine по
типам аргументов, `npcs.yml` туда-обратно, `config.yml`.
