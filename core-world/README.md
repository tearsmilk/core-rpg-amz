# core-world — правила мира для Amazake

Система (`.azs`) для ядра [Amazake](https://github.com/tearsmilk/amazake) (Paper 1.21.11, Java 21).

core-world собирает правила мира из **модулей**. У каждого модуля свой раздел в `config.yml` и свой переключатель.
Сейчас модуль один.

- **hunger — голода нет.** Уровень еды не падает: если что-то пытается его понизить, это отменяется, а повышение
  разрешено. Истощение не копится, в том числе от эффекта «Голод». Шкала еды держится на 20, насыщение — на 20
  (`keep-saturation`), поэтому здоровье восстанавливается так же быстро, как у сытого игрока. Есть по-прежнему
  можно: ничего не блокируется, золотые яблоки и прочая еда с эффектами работают. Обычную еду при полной шкале, как и
  в ванилле, съесть нельзя.
  Еда и насыщение выставляются на 20 игрокам, которые уже онлайн, когда систему включают или перечитывают
  настройки. То же происходит при входе, после возрождения и при переходе в другой мир. Кроме того, раз в секунду
  отдельная задача каждого игрока подтягивает шкалу обратно, если её опустил другой плагин или команда.

## Установка

```bash
./gradlew azs
```

Файл `build/libs/core-world.azs` положите в папку `systems/` сервера (рядом с `plugins/`). Файл включённой системы
заменяйте переименованием: сначала скопируйте во временный файл, потом выполните `mv` поверх старого. Затем в
консоли:

```
amazake system enable core-world
```

Обновление уже включённой системы: `amazake system restart core-world`. Есть также скрипт `deploy.sh` (см.
комментарий в нём).

## Настройки

`systems/core-world/config.yml` создаётся при первом включении:

```yaml
hunger:
  disabled: true        # true — голода нет; false — обычный голод
  worlds: []            # пустой список — во всех мирах; иначе только в перечисленных, например [world, world_nether]
  keep-saturation: true # держать насыщение полным (быстрая регенерация); false — насыщение не трогается
```

- Имена миров сравниваются без учёта регистра. Если мир из списка не загружен, в консоли появится
  предупреждение.
- Если в `worlds` записано одно имя без скобок (`worlds: world`), оно засчитывается как `[world]`, а в консоль
  пишется предупреждение.
- Неверное значение (не `true`/`false`, не список) заменяется значением по умолчанию, в консоль пишется
  предупреждение.

После правки примените настройки без перезапуска:

```
amazake system reload core-world
```

или `/coreworld reload`. Если в YAML ошибка, остаются прежние настройки, а ошибка выводится в консоль.

## Команды

| Команда | Право | Что делает |
|---|---|---|
| `/coreworld status` (`/cworld`) | — | какие модули включены, в каких мирах, сколько игроков под задачей |
| `/coreworld reload` | `coreworld.admin` (по умолчанию у OP) | перечитать `config.yml` |

## Как добавить новый модуль мира

1. Создайте пакет `core.amazake.systems.coreworld.<модуль>`, например `weather`.
2. Сделайте настройки модуля неизменяемым `record` с методом `from(ConfigurationSection config, Consumer<String> warn)`.
   Он читает свой раздел (`weather.*`), включая переключатель (`weather.enabled` или по смыслу, как `hunger.disabled`).
   Неверные значения он заменяет значениями по умолчанию и сообщает о них через `warn`. Для списка миров есть готовый
   `module.WorldFilter` (пустой список — все миры). Напишите юнит-тест на разбор, как `HungerSettingsTest`.
3. Сделайте класс модуля, который реализует `module.WorldModule`:
   - `id()` — имя раздела в config.yml;
   - `enable(context)` — один раз: зарегистрируйте обработчики через `context.registerListener`;
   - `configure(config, warn)` — при включении и при каждом reload: подмените снимок настроек (`AtomicReference`),
     запустите или остановите задачи;
   - `disable()` — отмените свои задачи и верните игрокам то, о чём ядро не знает;
   - `active()` и `status()` — для `/coreworld status`.
   Выключенный в конфиге модуль держит обработчики зарегистрированными и просто ничего в них не делает.
4. Добавьте модуль в `CoreWorldSystem#createModules()` и его раздел с комментариями в `src/main/resources/config.yml`.
   У тех, кто уже ставил систему, `config.yml` на сервере не перезаписывается: новый раздел нужно дописать вручную,
   а пока его нет, действуют значения по умолчанию из `record`.

Правила потоков (подробно — `docs/systems.md` ядра, раздел 6):

- Игрока трогает только его поток: его события или `context.runForPlayer` / `context.runOnceForPlayer`. Из
  `enable`/`configure` (это глобальный поток) обойдите `Bukkit.getOnlinePlayers()` и поставьте каждому
  `runOnceForPlayer`.
- Для повторяющейся работы с игроком используйте `context.runForPlayer`, а не `player.getScheduler()`: задачи
  планировщика сущностей ядро не отменяет при выключении системы.
- Общие данные храните только в потокобезопасных структурах (`ConcurrentHashMap`, `Atomic*`, неизменяемые снимки).
- Глобальное (время, погода) меняйте в `context.runGlobalTimer` или в глобальном потоке.

## Сборка и тесты

```bash
./gradlew azs test
```

Юнит-тесты проверяют разбор `config.yml` (`HungerSettingsTest`) и выбор миров (`WorldFilterTest`).

## Взрывы (`explosions`)

ТНТ, вагонетки с ТНТ, криперы и дракон (и всё, что в `explosions.sources`) не ломают блоки: из взрыва убирается
только список блоков — урон по игрокам и мобам, отбрасывание и сам взрыв остаются. Дракон не ломает блоки и
пролетая сквозь них. Картины и рамки этими взрывами не срываются (`protect-hanging`). По желанию — взрывы кроватей
и якорей возрождения (`block-explosions`). Миры — `explosions.worlds` (пусто — все).
