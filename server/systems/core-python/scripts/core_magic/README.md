# core_magic (魔法) — Посох Лунного Странника

Python-система core-python. Механика посоха `azerus_moon_staff`: игрок **зажимает ПКМ** с посохом — перед ним
встаёт голубой магический круг (~3 блока), за 3 с он растёт, разгорается и вращается; **отпустил после 3 с** — из
круга бьёт белый луч на 29 блоков: каждая живая цель на пути получает 10 урона (один раз, луч пронзает). Отпустил
раньше — круг гаснет без выстрела.

Вид посоха, модели круга и луча, спрайты и шейдер — в `nexo-items/` (генератор `tools/moon_staff.py`, проверка
`tools/moonstaff_check.py`, описание — `nexo-items/README.md` и `docs/DEVELOPER_GUIDE.md` §6). Эта папка — только
логика сервера.

```
/cmagic give [ник] [кол-во]    выдать посох (1..64; из консоли — с ником)
/cmagic reload                 перечитать config.yml
/cmagic info                   заклинаний сейчас, эффектов в мире, ваша перезарядка, главные числа
```
Псевдонимы `/魔法`, `/coremagic`; право `coremagic.admin`. Колдовать может каждый (или только с правом
`staff.use-permission`, если оно задано).

## Как работает

**Удержание ПКМ.** У посоха компонент `consumable` (consume_seconds 3600, анимация BOW, звук
`minecraft:intentionally_empty`, без частиц и эффектов): клиент держит «натяжение» сколько угодно, посох не
тратится (звук и частицы поедания начались бы только после 21,875 % срока ≈ 13 мин, а заклинание гасится через
`max-hold-seconds`; `PlayerItemConsumeEvent` с посохом отменяется на всякий случай). Компонент задаёт Nexo
(`azerus_weapons.yml`). Система проверяет не только наличие, но и **значения**: consume_seconds ≥ `staff.consume-seconds`,
анимация BOW, без эффектов. Если Nexo принял секцию `consumable`, но не понял какой-то ключ, компонент был бы
ванильным (1,6 с, EAT) — удержание кончалось бы на 32-м тике и посох не стрелял бы никогда; такой компонент
заменяется. Ещё посоху ставится `use_cooldown` со своей группой `azerus:moon_staff` (см. «Перезарядка»). Чинит при
выдаче, входе на сервер (через 5 тиков), смене слота на посох (следующий тик; задача ставится только если в новом
слоте посох с неверными компонентами) и клике посохом (тогда работает со следующего клика).

**Перезарядка.** После выстрела/срыва — своя (в памяти, проверяется на ПКМ) и ванильная по группе
`azerus:moon_staff` (`player.setCooldown(группа, тики)`): на слоте посоха видна «шторка», клиент не начинает
натяжение. Группа своя, поэтому перезарядка не ложится на другие предметы на `DIAMOND_SWORD`. Клик на перезарядке —
`setUseItemInHand(DENY)`, строка «Посох восстанавливается: N с» и звук `denied` не чаще раза в 0,5 с (зажатый ПКМ
повторяет попытку каждые 4 тика).

**Начало** — `PlayerInteractEvent` (ПКМ в воздух/по блоку, `ignore_cancelled=False`: клик в воздух приходит
«отменённым»). Мир не в `disabled-worlds`, есть право (если задано). На перезарядке — `setUseItemInHand(DENY)` (нет
анимации), строка «Посох восстанавливается: N с» и звук `denied` (см. выше). Через тик проверяется, что игрок правда держит
посох поднятым (`isHandRaised` + `getActiveItem`) — так клики по сундукам и т.п. ничего не запускают.

**Заряд** — задача игрока раз в `watch-period-ticks` (2), только пока идёт заклинание:
- игрок вышел/умер/сменил мир → круг убирается сразу; рука опущена или в руке не посох → срыв;
- круг догоняет глаза `teleportAsync` (если глаза сдвинулись > `follow-min-move` или взгляд повернулся >
  `follow-min-angle`°; плавность `teleport-duration`), трансформацию при этом не трогаем — рост продолжается;
- каждые `update-ticks` — новый цвет предмета круга R = round(заряд·250) (шейдер по нему проявляет руны и яркость);
- гул (`hum`) каждые `hum-period-ticks`, высота +0.4·заряд; полоска заряда в строке над хотбаром;
- на `charge-ticks` — звук `ready` и «✦ Круг готов — отпустите ПКМ!»;
- дольше `max-hold-seconds` — `clearActiveItem`, срыв, «Круг не удержан и погас.».

**Отпускание** — `PlayerStopUsingItemEvent`: `getTicksHeldFor() ≥ charge-ticks` → выстрел, перезарядка
`cooldown.seconds`; меньше → срыв (круг сжимается за `fizzle-ticks`, звук `fizzle`, «держите ПКМ 3 с»),
перезарядка `after-fizzle-seconds`.

**Прерывания**: смена слота (если посох в основной руке — из второй руки ваниль удержание не прерывает), смена рук
(F), выброс посоха — срыв с угасанием; смерть, выход, смена мира, телепорт
дальше 4 блоков — круг убирается сразу.

### Круг (mahoujin.py)

Один `ItemDisplay` у глаз игрока (с его yaw/pitch, проверка `amazake.owns`): предмет — бумага с `item_model
azerus:moon_staff_circle` и цветом custom_model_data **(R, 233, 253)**; `ItemDisplayTransform.NONE`, билборд
`FIXED`, яркость (15, 15) — **обязательно**: UV2 = (240, 240) — часть метки шейдера; ширина/высота 0 (без отсечения),
без тени, не сохраняется (`setPersistent(false)`), PDC `py_core_magic:fx=circle`, `py_core_magic:owner=<UUID>`.
Билборд FIXED поворачивает локальную +Z дисплея туда, куда смотрит игрок; модель — плоскость XY, поэтому круг стоит
поперёк взгляда; перенос (0, −`down`, `forward`) — в осях дисплея.

Рост: на следующем тике — **один** пакет (интерполяция `charge-ticks − 1` тиков до размера `diameter`), дальше
клиент растит сам. Вращение, пульс, проявление рун — в шейдере по `GameTime` и R: сервер ничего не шлёт каждый тик.
Выстрел: вспышка (×`fire-flash-scale` за `fire-flash-ticks`), затем угасание за `fire-fade-ticks`.

### Луч (kousen.py) и правила потоков

Всё — в потоке заклинателя, в момент отпускания:

1. **Владение путём.** Отрезок [0, `range`] режется на куски `piece-length`; у каждого куска — AABB (кусок,
   расширенный на `hit-radius` + 1). Все столбцы чанков, которых он касается, должны быть загружены и принадлежать
   текущему региону (`world.isChunkLoaded` + `amazake.owns(Location(cx·16+8, y, cz·16+8))`). Первый непрошедший кусок
   обрывает луч, как стена. Почему это почти никогда не режет луч: регионы (как в Folia) сливают все соседние
   загруженные секции, а чанки в 29 блоках от игрока держит его же билет загрузки — весь путь лежит в регионе
   заклинателя; «чужой» столбец = незагруженная земля. Никаких задач в чужих регионах, ожиданий других потоков и
   обращений к сущностям из чужого потока.
2. **Блоки**: `world.rayTraceBlocks(глаза, взгляд, длина, FluidCollisionMode.NEVER, true)` → дальность D.
3. **Цели**: `world.getNearbyEntities(AABB куска)` по кускам [0, D], без повторов (UUID). Берутся `LivingEntity`
   (живые, видимые всем), кроме самого заклинателя, стоек для брони, «личных иллюзий» (`isVisibleByDefault() ==
   false`), NPC core-npc (PDC `corenpc:npc`), игроков в творческом/наблюдателе и игроков вообще, если
   `hit-players: false`. Точная проверка — отрезок × хитбокс, расширенный на `hit-radius` (метод плит, `keisan.当たり`).
4. **Урон** (каждой цели один раз): `setNoDamageTicks(0)` (если `ignore-invulnerability`), затем
   `damage(10, DamageSource(minecraft:magic, причина = прямой источник = заклинатель))` → `EntityDamageByEntityEvent`
   с атакующим-игроком: PvP, защита регионов и плагины решают как обычно. Заклинатель не получает урона никогда.
5. **Вид**: дисплей луча (`azerus:moon_staff_beam`, R = clamp(round(Lv·8), 1, 250), Lv = max(0.5, D − `forward`))
   ставится у глаз и **не двигается** (не пересекает границу регионов): модель тянется по +Z от 0 до 0.5 блока,
   масштаб Z = 2·Lv. Тик 0 — тонкий и широкий (×`start-width-factor`), тик 1 — растёт за `grow-ticks`, держится
   `hold-ticks`, сужается в 0 за `fade-ticks`, удаляется. Частицы: след (`trail`) каждые `every` блоков от круга до D,
   вспышка (`end`) в конце. Звуки `fire` у глаз.

### Метка шейдера (константы кода, не настройки)

Цвет custom_model_data: **G = 233, B = 253, R ≤ 250 = параметр**, плюс яркость дисплея (15, 15) → UV2 = (240, 240).
Не пересекается с rezusmenu (B = 254), порталами и небом (R = 255). Второй ключ — сигнатура в самом спрайте
(текстель (0,0) = (177,126,90,3)). Без шейдера (Iris, старый пак) круг просто голубой — это безопасно.
Параметр: круг R = round(заряд·250) (250 — готов), луч R = round(Lv·8).

### Загрузка, выгрузка, остатки

- Дисплеи не сохраняются в мир (`setPersistent(false)`).
- `@on_unload`: всё из идущих заклинаний и гаснущих эффектов убирается `amazake.remove_entity(e)` (сразу, если
  поток владеет сущностью, иначе — Java-задачей в потоке самой сущности; переживает закрытие Python). На старом
  core-python.azs без этого API (сейчас прод и тестовый сервер) — запасной путь: плагин отражением (как в
  core_effects) и Java-Runnable `Entity.remove` в **планировщик сущности** (`entity.getScheduler().execute`), а не
  региона — сущность могла уйти от последнего известного места.
- Ошибки Java приходят в Python как `polyglot.ForeignException` (это `BaseException`, не `Exception`), поэтому все
  запасные ветки вокруг вызовов Java ловят `BaseException`. Частицы из конфига проверяются при первом использовании:
  неизвестное имя или частица с данными (DUST, BLOCK…) → END_ROD, выстрел не ломается.
- `@on_load`: у каждого онлайн-игрока (в его потоке) убираются дисплеи с меткой `py_core_magic:fx` в 48 блоках.
- Нет `PlayerMoveEvent` и глобальных циклов; повторяется только надзор во время заклинания. Перезарядки — в памяти.

## Заливка (только после «заливай»)

Сначала ресурсы (`nexo-items`: include-файлы и спрайты azerus, потом общие файлы шейдера, `nexo reload all`,
`moonstaff_check.py --pack`, `armor3d_check.py --pack`), затем эта папка в `/systems/core-python/scripts/core_magic/`
(без `tests_core_magic.py` — можно и с ним, он не грузится) и `/python load core_magic`.
