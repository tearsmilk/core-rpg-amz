# core-mobs — мобы, лут и регионы спавна для Amazake

Система (`.azs`) для ядра [Amazake](https://github.com/tearsmilk/amazake) (Paper 1.21.11).

- **Регионы спавна любой формы.** Топориком ставятся точки полигона, от 3 до 256. Пока в руке топорик, контур виден
  частицами; командой его можно показать всем игрокам неподвижными линиями. У каждого региона свой список мобов с
  весами, лимит живых мобов, интервал спавна и радиус деспавна.
- **Миры без ванильных мобов:** `/mobs world disable <мир>` — остаются только мобы core-mobs.
- **Свои мобы из `mobs.yml`.** Здоровье, урон, скорость, броня, размер, снаряжение, постоянные эффекты, эффекты при
  ударе, урон стрел, опыт, защита от солнца, модель ModelEngine (по желанию).
- **Лут из инвентаря.** Кладёте предметы в инвентарь и сохраняете их командой. Предметы пишутся со всеми NBT
  (компонентами). Шанс и количество каждого предмета настраиваются в файле.
- **Команды:** призыв, список, выдача предмета из лута, яйцо призыва, перезагрузка.

## Сборка и установка

```bash
./gradlew azs
```

Файл `build/libs/core-mobs.azs` кладётся в `systems/` сервера, затем в консоли:

```
amazake system enable core-mobs
```

## Как сделать регион

1. `/mobs wand` — выдаёт топорик (золотой, с меткой; обычный золотой топор не сработает).
2. **ЛКМ по блоку** ставит точку, **ПКМ** убирает последнюю, **Shift + ПКМ** сбрасывает выделение. Точки ставятся по
   контуру, по порядку обхода. Блоки, через которые проходит граница, входят в регион.
3. `/mobs region create <имя>` — создаёт регион. Высота: от самой низкой точки до самой высокой плюс
   `regions.default-height` (5 блоков). Менять её — `/mobs region expand <имя> up|down <блоков>`.
4. `/mobs region addmob <имя> <моб> [вес]` — кто спавнится. Чем больше вес, тем чаще.
5. При желании настроить: `/mobs region set <имя> <параметр> <значение>`.

Пока в руке топорик, видно своё выделение и все регионы рядом (частицы, видит только сам игрок). Нижняя линия идёт
по высоте поставленных точек и не зависит от того, где стоит игрок; на вершинах — столбики до потолка региона.

`/mobs region show <имя>` показывает контур региона **всем игрокам** — тонкими зелёными линиями из блок-дисплеев.
Они стоят на месте и не мерцают. Повторная команда убирает их у всех. Состояние хранится в regions.yml (`show`),
переживает перезапуск; блок, толщина, свечение и дальность линий — в разделе `display` config.yml.

| Параметр `set` | Что | По умолчанию |
|---|---|---|
| `spawn on/off` | спавн включён | on |
| `interval <сек>` | как часто регион пробует заспавнить | 10 |
| `max-alive <n>` | сколько мобов региона живо одновременно | 10 |
| `amount <n или a-b>` | сколько за раз | 1 |
| `player-radius <блоков>` | регион работает, только если игрок не дальше этого от границы | 48 |
| `min-distance <блоков>` | моб не появляется ближе этого к игроку | 6 |
| `despawn-radius <блоков>` | моб, отошедший от границы дальше этого, пропадает; `-1` — выключено | 5 |

Мобы появляются на твёрдом блоке, где над ним два свободных блока, в пределах высоты региона. Чанки ради спавна не
грузятся. Мобы регионов не сохраняются в мир: выгрузился чанк или перезапустился сервер — регион заспавнит новых.
Мобов из команды и яйца это не касается: они остаются в мире, как обычные.

## Миры без ванильных мобов

`/mobs world disable <мир>` — в мире перестают появляться ванильные мобы: естественный спавн, спавнеры, яйца,
раздатчики, размножение, подкрепления. Уже живые ванильные мобы вокруг игроков убираются сразу, остальные — когда
загрузится их чанк. Прирученных, с именем от бирки и на поводке не трогаем.

Проходят всегда мобы core-mobs (регионы, команды, яйца core-mobs). По умолчанию проходят также мобы других плагинов
(MythicMobs и т. п.) и `/summon` — это список `worlds.allowed-spawn-reasons` в config.yml.

`/mobs world enable <мир>` — вернуть ванильных мобов, `/mobs world list` — список. Хранится в worlds.yml.

## Лут

1. Положите в инвентарь предметы, которые должны падать с моба (любые, с NBT, зачарованиями, предметами других
   плагинов). Топорик и яйца призыва в лут не попадают.
2. `/mobs drops save <моб>` — заменить лут моба, `/mobs drops add <моб>` — добавить к нему.
3. Откройте `systems/core-mobs/drops/<моб>.yml` и поставьте шансы и количество:

   ```yaml
   items:
     '1':
       preview: diamond_sword x1 «Меч»   # подпись для вас
       chance: 25.0                      # шанс в процентах, можно 0.5
       amount: '1'                       # число или диапазон 1-3
       item: rO0ABXNy...                 # сам предмет, не трогать
   ```
4. `/mobs reload`.

Каждый предмет проверяет свой шанс отдельно. Ванильный дроп моба по умолчанию выключен (`vanilla-drops: false`).
Опыт с моба (`exp`) ванильный, поэтому core-rpg переводит его в свои уровни.

## Команды

Всё под правом `core.mobs.admin` (по умолчанию у операторов). Алиасы: `/cmobs`, `/мобы`.

| Команда | Что |
|---|---|
| `/mobs list` | мобы из mobs.yml (клик — подставить команду призыва) |
| `/mobs spawn <моб> [кол-во] [мир x y z]` | призвать; без координат — туда, куда вы смотрите |
| `/mobs egg <моб> [кол-во] [ник]` | яйцо призыва (ПКМ по блоку) |
| `/mobs drops save\|add <моб>` | лут из инвентаря |
| `/mobs drops list <моб>` | лут с шансами (наведите — предмет, клик — получить) |
| `/mobs drops give <моб> <номер\|all> [ник]` | выдать предмет из лута |
| `/mobs drops remove <моб> <номер>` · `clear <моб>` | убрать предмет / весь лут |
| `/mobs wand` · `/mobs sel info\|undo\|clear` | топорик и выделение |
| `/mobs region create\|redefine <имя>` | регион из выделения / заменить его точки |
| `/mobs region list` · `info\|tp\|delete <имя>` | регионы |
| `/mobs region show <имя>` | показать контур всем / убрать у всех |
| `/mobs region addmob <имя> <моб> [вес]` · `removemob <имя> <моб>` | кто спавнится |
| `/mobs region set <имя> <параметр> <значение>` | настройки из таблицы выше |
| `/mobs region expand <имя> up\|down <блоков>` | высота |
| `/mobs world disable\|enable <мир>` · `/mobs world list` | ванильные мобы в мире |
| `/mobs reload` | перечитать config.yml, mobs.yml, regions.yml, worlds.yml и лут |

## Файлы

| Файл | Что |
|---|---|
| `config.yml` | топорик, частицы, линии контура (`display`), высота и радиус деспавна новых регионов, формат имени, миры без ванильных мобов (`worlds`) |
| `mobs.yml` | мобы (в примере: зомби, скелет-стрелок, ядовитый паук) |
| `regions.yml` | регионы; пишет система, можно править руками и делать `/mobs reload` |
| `drops/<моб>.yml` | лут моба |
| `worlds.yml` | миры, где выключены ванильные мобы |

## Варианты мобов (mobs.yml)

31 моб: слизни и магмовые кубы (`size`), фантомы (не горят на солнце), зомби, кадавры, утопленники, скелеты, зимогоры,
болотные скелеты, пауки и пещерные пауки, скелеты-иссушители, блейзы, зоглины, брутальные пиглины (не превращаются в
зомби в обычном мире), разбойники и поборники. Огненные шары мобов core-mobs не поджигают и не ломают блоки
(`no-fire`, по умолчанию true). Слизни core-mobs не делятся (превращения отменяются, как и раньше).

## Модели ModelEngine

Любому мобу из `mobs.yml` можно надеть модель ModelEngine (R4). ModelEngine — обычный плагин в `plugins/`, мягкая
зависимость: без него мобы работают как раньше, в консоли одно предупреждение.

```yaml
  cave_skeleton:
    type: SKELETON
    name: "<gray>Пещерный стрелок</gray>"
    model: skeleton_archer   # id модели (blueprint) ModelEngine
    model-scale: 1           # масштаб модели (1)
    model-hide-base: true    # прятать ванильного моба (true)
    model-attack: attack     # анимация при выстреле из лука и ударе (attack); none — не проигрывать
    model-hit: hit           # анимация при уроне (hit); none — не проигрывать
```

- **Анимации.** idle, walk и death ModelEngine проигрывает сам (обработчик состояний по умолчанию). core-mobs
  добавляет attack — при выстреле из лука и при ударе моба в ближнем бою, и hit — при несмертельном уроне (при
  смертельном играет death). Вызов — `ActiveModel#getAnimationHandler().playAnimation(имя, 0.1, 0.2, 1, true)`.
- **Снаряжение и поведение не меняются**: лук остаётся в руке, скелет стреляет по-ванильному. С
  `model-hide-base: true` ванильный моб (и лук) не виден — видна только модель.
- **Когда вешается.** При спавне (регион, `/mobs spawn`, яйцо) — сразу. Моб снова появился в мире (чанк загрузился,
  сервер перезапустился — это мобы из команды и яйца, мобы регионов в мир не сохраняются) — через 2 тика
  проверяется, восстановил ли ModelEngine модель сам; нет — вешается. Дважды модель не вешается: сначала ищется
  `ModelEngineAPI.getModeledEntity(моб)` с этой моделью. При включении core-mobs и `/mobs reload` модели
  проверяются у мобов рядом с игроками; включился ModelEngine позже системы — тоже.
- **Выключение и смерть.** Модель принадлежит ModelEngine: при выключении core-mobs она остаётся на мобе (анимации
  attack/hit до включения не играют), при смерти ModelEngine играет death и убирает модель сам, при удалении моба —
  тоже сам. core-mobs не хранит ничего по сущностям — утечек нет.
- **Потоки.** Все вызовы ModelEngine — в потоке региона моба (события моба, задача региона), как в core-npc. Методы
  вызываются через рефлексию с выбором перегрузки по типам аргументов. Ошибка вызова — в консоль один раз, моб
  остаётся без модели.
- **Имя над головой.** ModelEngine прячет ванильного моба от клиентов целиком, поэтому имя со здоровьем, скорее
  всего, не будет видно (в `skeleton_archer` кости-таблички `tag_…` нет). Если оно нужно — кость-табличка в модели
  или `model-hide-base: false`.
- **Не проверено вживую**: ModelEngine нет на тестовом сервере. Проверка на продакшене: `/mobs spawn cave_skeleton`
  — модель, idle/walk, attack при выстреле, hit при ударе, death при смерти; перезапуск сервера с мобом из команды —
  модель одна.
- В `mobs.yml` по умолчанию модель `skeleton_archer` надета на `cave_skeleton` («Пещерный стрелок»).
